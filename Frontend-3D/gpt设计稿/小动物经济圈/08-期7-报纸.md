## 一句话

送给爱说话的那位邻居一台报纸打印机，第二天早上桌上就有一份「XXX 晨报」——
头条、天气、邻居动态、市场行情，每天一版。报名是你自己取的。

**用户点名这是整套里的重点。** 对"专注陪伴工具"这个定位来说，一个每天
跟你说"昨天发生了什么"的角色，比任何数值系统都更对题。

## 分四步

### 7A · 字体：思源宋体子集

**报纸"像不像"有一大半在中文衬线上。** 而这个项目：

- `public/font/` 是**空的**
- `src/index.css` 里**一句 `font-family` 都没有**（只有一处 `GameBtn.css` 写了）

三条路里选了子集打包（用户勾的）：

| 方案 | 效果 | 代价 |
|---|---|---|
| **① 子集打包** ✅ | Electron 和网页版长得一模一样 | 加一个构建步骤 |
| ② 系统衬线栈 | 零成本 | Windows 宋体和 macOS 宋体观感差很远，打包后用户机器上有什么不可控 |
| ③ 不用衬线 | 零成本 | "像报纸"打七折 |

做法：

```
scripts/generate-font-subset.mjs   （新，挂进 prebuild / predev）
  1. 读 src/i18n/t.ts，扫出全部用到的**汉字集合**
  2. 加上常用标点、数字、拉丁字母
  3. 用 fonttools / subset-font 从思源宋体（OFL，可随游戏分发）切子集
  4. 输出 public/font/serif-subset.woff2
```

`index.css` 加：

```css
@font-face {
  font-family: "GameSerif";
  src: url("/font/serif-subset.woff2") format("woff2");
  font-display: swap;
}
```

> **注意两件事**：① 报纸里会出现**玩家自己输入的文字**（报名、行动名
> "写完 assignment2"），那些字不在 `t.ts` 里，子集切不到——所以
> `font-family` 要写成 `"GameSerif", "Songti SC", "SimSun", serif`，
> 切不到的字优雅退到系统衬线。② 生成脚本挂进 `prebuild`/`predev`
> （`generate-music-registry.mjs` 已经是这个位置的先例），文案改了自动重跑。

### 7B · 打印机 + 报名

#### 打印机是一件家具

走 `create-furniture` 的既有流程（Core 物品定义 + Frontend 低模配方 +
注册 + 文案 + 验收）。**先问参考图。**

```ts
// Data/items/index.ts
{
  id: "furniture_news_printer",
  category: ItemCategory.Furniture,
  rarity: Rarity.Rare,
  origin: ItemOrigin.Real,   // 现实世界的东西——正是它成为礼物的理由
  value: /* economy */,
  placement: { /* ... */ },
}
```

#### 送礼解锁

```ts
{
  id: "newspaper_unlocked",
  triggers: [{ signal: "gift_given", subject: "furniture_news_printer" }],
  effects: [
    { kind: "start_dialogue", dialogueId: "reporter_names_the_paper" },
  ],
},
{
  // 对话里玩家取完名字 → 那个节点的 emitEventId 接这条
  id: "newspaper_started",
  triggers: [{ signal: "dialogue_event", subject: "paper_named" }],
  effects: [{ kind: "unlock_feature", featureId: "newspaper" }],
},
```

**用送礼当解锁开关，这是第一次。** `gift_given` 信号早就在（"递出去了，
不分档位"），而把它用在最有性格的角色身上是对的——播报员想要一台
打印机，你把它送过去，这比"造好就自动解锁"有分量得多。

#### 报名

「XXX 晨报」，XXX 玩家取，进存档。

- **时机**：对话 `reporter_names_the_paper` 里他问"叫什么好呢？"
  → 弹一个命名输入 → 存下来 → 发 `paper_named`
- **存哪**：`WorldSave`（报纸是这个家的，做客时看到的是主人家的）
- **之后能改**：报纸面板角落一个小按钮
- **长度限制**：照 `dailyBoardDefinition.textLimit` 的路数，给一个数
  （报头一行放得下，8 个汉字左右）
- **空的兜底**：不填就用据点的名字，不要让报头开个洞

### 7C · 出刊

```ts
// Systems/newspaper.ts（新）
/**
 * 每个世界日出一期。**只出最新一期，不补发**（总纲：每日内容不补发，
 * 照动森——商店商品、狸端机任务都只有今天的）。
 *
 * 离线七天回来出的是"今天这一期"，但**头条可以写"这几天"**——
 * 对应动森村民那句"好久不见"。
 */
export function issueOf(worldDayId: string): NewspaperIssue | null;
```

版面从昨日事实编：

| 版块 | 内容 | 数据源 |
|---|---|---|
| **头条** | 昨天最大的一件事 | `headlines[]` 按优先级表取最大的一条 |
| 天气 | 昨天什么天 | `weatherId` |
| 邻居动态 | 谁搬来了 / 谁买了你的家具 | `headlines[]` |
| 市场行情 | 金币进出 + **水獭这回想要什么**（决策 30） | `goldIn/goldOut` + `wantedToday()` |
| 昨日行动 | 你做完了哪几件事 | `actions[]` |

**头条挑选是一张优先级表，不是 if 链**：

```ts
// Data/newspaper/index.ts（新）
/**
 * 哪种事更值得上头版。**数据表不是 if 链**——加一种大事
 * （比如以后的节日）是往这里加一行，不是回去改挑选逻辑。
 */
export const headlinePriority: Record<string, number> = {
  theft: 100,           // 被偷了，没有比这更大的
  resident_moved_in: 90,
  building_completed: 70,
  shop_sold: 40,
  action_completed: 10,
};
```

出刊结果存 `WorldSave.newspaper`（**本蓝图唯一的新存档切片**）：
一期定稿之后不再变，玩家当天反复打开看到的是同一份。

**存档四件套照总纲走**：版本 +1、迁移、`Backend` 的 `applyRefresh`
+ `WORLD_REFRESH_KEYS`、`Core/types/net.ts`。

> `net.ts` 里有一句**编译期断言**（`MissingFromKeys`）：往
> `WorldRefreshSlices` 加字段却忘了加进 `WORLD_REFRESH_KEYS`，**Core 当场
> 编译不过**。所以只要决定让报纸跟着联机走，漏不了。**但反过来：
> 如果决定不跟（报纸只给主人看），就两处都别加。**

### 7D · 版面（这一期真正的活）

**当一件版式作品做，不是普通面板。**

```
┌────────────────────────────────────────────┐
│  松果谷 晨报        第 12 期 · 2026年8月24日 │   ← 报头，双线压底
╞════════════════════════════════════════════╡
│  ┌──────────────┬─────────────────────────┐│
│  │              │ 昨天多云，傍晚下过一阵雨  ││
│  │  【木刻插图】 │ ────────────────────    ││   ← 分栏，栏间细竖线
│  │              │ 邻居动态                 ││
│  │              │ 小狐狸买走了你那把摇椅   ││
│  ├──────────────┴─────────────────────────┤│
│  │ 头条：小龙又来了？                       ││   ← 粗横线分版块
│  └────────────────────────────────────────┘│
│  市场行情 · 水獭这回想要：书架、坐垫、挂钟   │   ← 广告版（决策 30）
└────────────────────────────────────────────┘
```

要素清单：

- **报头**：报名 + 期号 + 世界日期，一条**双线**压底（`border-bottom: 3px double`）
- **衬线字**，标题大而粗、正文小而密，字号层级明显拉开
- **分栏**，栏间一道细竖线
- **粗横线 / 双线**分隔版块——**不是圆角卡片**
- **做旧**：纸色泛黄、轻噪点、边缘微微不齐、印色略有偏移
- **一张木刻风插图**（黑白粗线条的版画感，和低多边形的美术调性对得上）

**横屏 667×375 是硬约束**（[[landscape-only-iphone-se]]）。报纸是密排版式，
小屏排坏比普通面板更难看。做法：小屏**减栏不减字号**（两栏 → 一栏纵向滚），
字号缩到读不清就失去意义了。

## 最容易写错的四处

### 一 · 玩家输入的字不在字体子集里

报名、行动名（"写完 assignment2"）都是玩家打的，`t.ts` 里没有。
`font-family` 必须带系统衬线兜底，否则那几个字会掉回无衬线，
一行里两种字看着像 bug。

### 二 · 一期定稿之后不能变

同一天反复打开必须是同一份。存进 `WorldSave.newspaper`，
不要每次打开现算——现算的话"水獭想要什么"那一栏会在他走了之后变空。

### 三 · 不补发往期

离线七天回来出一期（今天的），不是七期。总纲的"每日内容不补发"。
一上线七份报纸等着读，那是欠账不是惊喜。**但头条要能写"这几天"**。

### 四 · 新切片的四件套别只做两件

`net.ts` 那句编译期断言只拦"加了类型忘了加白名单"。它拦不住
"忘了在 `applyRefresh` 里写那一行"——`Backend/tests/sessions.test.ts:341`
的 gramophones todo 就是这么漏的。**决定要不要联机同步，然后四处一起做齐或者一处都别加。**

## 刻意不做的

- **往期归档**（决策：每日内容不补发，往回翻明确不做）
- **玩家投稿 / 自定义版面**
- **报纸的实体道具**（桌上放一份可拾取的报纸——是好点子，但那是家具那条线）
- **联机时访客能看主人的报纸**（要不要同步是这一期的一个决定，
  倾向不同步：报纸是主人家的私事，做客的人看别人的家务事很奇怪）
- **插图随内容变**（一张通用木刻就够；按头条换图是内容量的事）
