# 06 · 居民之间

> 状态：**文档，待执行** · 2026-09-05 · 前置：02 作息与场所、03 对话
>
> 一句话：他们彼此有关系——碰面停下聊两句、约在井边一起待着、互相讲对方的八卦。
> 你不在的时候他们也在过日子，这是"活着"最便宜的证据。不做吵架。

## 玩家看到什么

- 上午阿茜跑过咕噜身边，两人停下，面对面，头顶轮流冒气泡（"哟咕噜！""……早。"），三四句后各走各的。你走近能看见气泡内容。
- 作息里都去井边的时段，薇尔和阿茜站在井边，隔一会儿一个人冒一句，像真的在聊。
- 按 F 和咕噜聊天，他说"阿茜昨天去小镇了，回来一直说街上的灯"——引用的是阿茜真实的记忆 / 事实。
- 阿茜的委托是把包送给薇尔（05），薇尔收下后下次见咕噜，咕噜说"听说阿茜把借的东西还了"。
- 怕生的咕噜看见薇尔走近会往旁边挪一步（`shy` 关系）。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 两村民碰面停下对话，带表情 | 取：`social` 技能 + 双人对话池 |
| 一起唱歌 / 做操 / 坐在一起 | 一起待着（同场所，面对面）；一起活动等 12 的活动注册表 |
| 讲别人八卦，转述别人对你的评价 | 取：八卦池引用对方记忆与事实 |
| 吵架、闹别扭、请你去调解 | **不做**（不制造焦虑）。关系只有正面和中性 |
| 村民互送礼物、串门 | 送礼中转靠 05 的 `deliver`；串门站门口（02），进屋等 08 |
| 性格相克（暴躁 vs 元气）决定谁和谁处不好 | 关系表显式写，不从性格推——推出来的关系没人能预测，写出来的能改 |

## 数据

### 关系表（Core/src/Data/residents/relations.ts）

```ts
export const relationDefinitions = [
  { a: "slime_neighbor", b: "fox_neighbor",    kind: "friends", chatPool: "chat.slime_fox" },
  { a: "fox_neighbor",   b: "spirit_neighbor", kind: "curious", chatPool: "chat.fox_spirit" },
  { a: "slime_neighbor", b: "spirit_neighbor", kind: "shy" },              // 没有 chatPool = 不聊
] satisfies RelationDefinition[];

export const relationKinds = {
  friends: { stopToChat: 0.8, hangoutTogether: true,  keepDistance: 1.2 },
  curious: { stopToChat: 0.4, hangoutTogether: false, keepDistance: 1.6 },
  shy:     { stopToChat: 0,   hangoutTogether: false, keepDistance: 2.6, stepAside: true },
} as const;
```

- 关系是**无向**的（a/b 顺序无意义），content 测试查每对最多一条、两端都是居民、`chatPool` 存在。
- 第四位居民来了 → 加两三行。没写的一对 = `neutral`（不停下、不聊、不避）。

### 双人对话池（Core/src/Data/residents/talk/pairs.ts）

```ts
export const pairChats: Record<string, PairChat[]> = {
  "chat.slime_fox": [
    { lines: [["fox", "pair.slime_fox.1.a"], ["slime", "pair.slime_fox.1.b"], ["fox", "pair.slime_fox.1.c"]] },
    { lines: [/* … */], when: [{ kind: "weather_is", weatherId: "rain" }] },
    { lines: [["fox", "pair.slime_fox.town.a"], ["slime", "pair.slime_fox.town.b"]],
      when: [{ kind: "neighbor_remembers", residentId: "fox_neighbor", memoryId: "went_to_town" }] },
  ],
};
```

- 一段 = 2~4 句交替，每句一个说话人 + 文案键，可带表情。`when` 仍是 `DialogueCondition`（03 新增 `neighbor_remembers`，读**另一位**的记忆）。
- 确定性抽：`hashSeed(pairKey + worldDayId + 第几次)`。

### 八卦（03 闲聊池的一种条件段）

不另做八卦系统。03 的闲聊段加条件 `neighbor_remembers` / `neighbor_fact_yesterday: { residentId, kind }`（读 `dayRecord` 昨天那位的事实：去过小镇、没出门、完成委托），段落文案里用 `{name:fox_neighbor}` 模板引用对方昵称。**八卦 = 引用别人记忆的闲聊**，这个定义让它零新代码。

## 技能与动词

### `social` 技能（优先级 45，在 routine 之上、needs 之下；可打断）

`decide`：

1. 扫场上其他居民；对每一位查关系。
2. `shy` 且距离 < `keepDistance` → Intent `[walk_to 反方向 1.5m]`（`stepAside`），并行 `gesture("look_away")`。冷却 30 秒。
3. `friends` / `curious` 且距离 < 2.5 m 且双方都在可打断的 Intent 里 且今天和这位聊过 < 3 次 且掷中 `stopToChat` → **发起**：给自己一个 Intent `[stand(facing: 对方)]`，并通过 `world.requestPair(me, other, poolKey)` 让对方也换上 `[stand(facing: me)]`（对方的 Intent 来源标 `social`，优先级同）。开始双人对话：一个运行时 `PairTalk` 对象按 2.5 秒一句轮流下 `speak`（并行槽），说完双方 Intent 结束、各回作息。写 `ResidentSave` 无字段——聊过几次是运行时计数，跨天归零。
4. `hangoutTogether` 且作息表当前段两人都是 `visit` 同一场所 → routine 已经把他们放一起；`social` 只补一件事：到达后 `stand(facing: 对方)`，以及每 40~90 秒抽一段双人对话（掷 `stopToChat`）。这一支不发起移动。

`requestPair` 是 `SkillContext.world` 上**唯一的写操作**——它不改世界，只给另一位下一个 Intent，本质是"技能对技能说话"。为了不破 01 的"技能只读世界"，把它定义成身体的动词：`invite(other, intent)`，走对方的 `perform`（优先级 `social`，对方正在做不可打断的事就失败，发起方自己也不停下）。

### 走近避让

两位 `friends` 走路时 `keepDistance` 1.2，`shy` 2.6——现有让路逻辑（`askBlockerToYield`）按 `radius` 判，这里加一个"社交半径"参与 `waitBlocked` 的判定即可，不改让路算法。

## 联机

- 双人对话完全在房主端决策：`invite` 是房主内部的事；房客只收到两条 `resident_intent`（两人各自 `stand(facing)`）和两串 `speak` 关键帧字段（01 关键帧加 `speaking?: localizationKey`，让房客也能看见气泡——**这里和 03 不同**：两人聊天不是对着某个玩家说的，房客看见文字是对的）。
- 八卦是闲聊的一部分，房客按 F 听到的八卦读的是同步过来的记忆与事实。
- 联机验收：房主用 `/npc pair slime fox` 强制发起 → 房客那边两只面对面、轮流冒同样的气泡文字、顺序一致；结束后两边各回作息位置差 < 0.5 m。

## 指令

| 指令 | 干什么 |
|---|---|
| `/npc pair <谁> <谁>` | 立即发起一段双人对话（无视距离，先把两人拉到一起） |
| `/npc relations` | 打印关系表 + 今天各对聊过几次 |
| `/npc <谁> gossip` | 打印他此刻能讲的八卦段（条件求值） |

## 存档

无新字段。聊天次数、冷却全是运行时。`dayRecord` 加事实 `residents_chatted`（"咕噜和阿茜在井边聊了一下午"），报纸邻居动态登。

## 刻意不做的

- 吵架、绝交、关系值变化（关系是静态设定，不是变量）；三人以上的群聊；居民之间送礼（用 05 的 deliver 委托表现"帮我转交"）；居民和商人 / 石傀儡的关系（他们不是居民；水獭以后想和居民聊是加一行关系，不是特判）。

## 最容易写错的四处

1. **`social` 直接改对方的状态。** 走 `invite` 动词 → 对方 `perform`，对方有权拒绝。
2. **两人同时互相发起** → 死锁。发起前查对方当前 Intent 的 `skillId !== "social"`；同帧竞争由 `residentId` 字典序小的让。
3. **双人对话被打断后另一位还在说。** `PairTalk` 订阅双方 Intent 结束事件，任一方结束就整段收尾。
4. **八卦引用的记忆两端不同步。** 记忆在 `ResidentSave` 里，走 `pets` 切片，是同步的；但**昨天的事实**（`dayRecord`）是房主存档字段，房客读不到 → 房客端 `neighbor_fact_yesterday` 一律 false，那些段落就不出现。这是可接受的降级，写进联机节。

## 验收

- Core：关系表完整性（每对最多一条、双端是居民、池存在）；双人段抽取确定性；`neighbor_remembers` 条件。
- Frontend `social.test`：`shy` 走近 → 让开；`friends` 近距 + 掷中 → 双方 `stand(facing)`，`speak` 交替，说完各回作息；一方在 `needs` 最后一步 → `invite` 失败发起方不停；同帧互发只成立一段；每天每对最多 3 次。
- 浏览器：`/npc pair slime fox` 看面对面轮流气泡；`/time day` 等薇尔和阿茜同在井边看自发聊天；咕噜见薇尔挪步。截图。
- 联机双端：见上。

| 抓到的 | 改法 |

| 关系从性格推 | 显式表，可预测可改 |
