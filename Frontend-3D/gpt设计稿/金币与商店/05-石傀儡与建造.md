# 石傀儡与建造流程

> 状态：**计划，等确认** · 2026-08-22 · 前置：期 0–2 + 女巫小屋三轮全部完成
>
> 标准同前四份：任何人不看聊天记录也能照着做完并验收。

## 一句话

领地上坐着一尊无头石傀儡。玩家在院子另一头捡到他的头，走过去按 F 装上，他苏醒；
和他说话打开建造面板；面板里买一张图纸；拿着图纸选址落下蓝图；石傀儡走过去把它建起来。
建好之后对着建筑按 F 能迁移 / 拆除 / 升级 / 看详情。

## 拍板过的（2026-08-22，用户定）

| # | 决策 | 依据 |
|---|---|---|
| G1 | 面板点击 → **扣材料、拿到一张图纸（物品）** → 玩家自己拿着图纸去选址 | 用户选。和「他一开始会给你图纸，你拿着图纸按 F 就会有蓝图」完全对上；图纸是真物品，以后能当任务奖励 / 商店商品 |
| G2 | 石傀儡在建 A 时下 B 的单 → **B 排队**：蓝图落地、围栏立起、进度条 0%，但傀儡不去 | 用户选。「B 不会动工」变成看得见的东西；以后多一尊傀儡就是多一个工位，规则不用改 |
| G3 | 建造面板**本期只吃金币，且 l1 储金罐要 0 枚** | 用户定（测试用）。也是 Core 早就写下的硬约束——`logic/goldJar.ts:31` 注释：第一只罐的建造代价必须为 0，否则玩家永远攒不出建罐的钱，死锁 |
| G4 | 材料是**数组**，不是单个数字 | 用户定。好消息：`upgradeCost` 本来就是 `Array<{itemId, quantity}>`，照抄它给"建造代价"就行 |

## 现状盘点：哪些是现成的，哪些是空的

### 现成能直接用（这条链最大的运气）

| 要的东西 | 现成的 |
|---|---|
| 两步确认选址 | `BuildingPlacementController`（311 行）：**真模型半透明虚影**（不是方块）+ 地面占地框 + 整格吸附（奇偶宽都对）+ R 转向 + 选定后虚影不消失可以走开绕圈看 + [确认][重选][取消]。今天唯一入口是 `/site` 指令 |
| 放置合法性 | `previewPlacement()` 同时喂预览和提交，绿色显示和提交结果不可能打架。四条理由齐全：领地外 / 压楼 / 压家具 / 超实例上限 |
| 储金罐模型 | 三级全有，液面按 `state.fill` 插值 |
| 生物寻路 | `PetAgent.seekNear(x, z, reach)`，A* 带 `clearanceRadius`，大家伙不钻缝 |
| 休眠 / 苏醒 | `PetAgent.state === "sleeping"`、`placeSleepingPet()`、`wakeUp()`、StoryEffect `pet_wake` |
| 带骨架的生物建模范本 | `recipes/shushu.ts`（476 行）：pivot 骨架 + `userData.animate(dt, {state, moving})` + `playGesture` + `outlineScale` |
| 对话 | 解释器、信号、效果、`DialoguePanel` 全套现成 |
| 面板栈 | Redux `uiSlice.panelStack` + `usePanel` / `useMirroredPanel` + `EscArbiter`（ESC 的唯一裁判） |
| 世界坐标 → 屏幕像素 | `RoomScene.getHintBubble()` + `InteractBubble` 的 rAF + transform 骨架，进度条照抄 |
| 花钱 | `spendGoldFrom(amount)`（金币存在罐的 `state.stored` 里，罐就是钱包） |

### 空的 / 缺的

| 缺口 | 现状 |
|---|---|
| **建造代价** | **字段不存在**。`BuildingLevel` 只有 `upgradeCost`，新建一栋楼永远免费 |
| **扣材料** | `checkUpgrade` 的 `missing_materials` 校验写好了，但 `upgradeBuilding` 调它时**不传 `materials`**（`buildings.ts:266`），这道门物理上无法触发；**扣材料的代码根本不存在** |
| **施工时间** | `construction { targetLevelId, finishUtc, workerId? }` 和 `buildDuration` 都是预留字段，**全仓库零引用**。Core 里没有任何推进/结算施工的函数。而且只有 `finishUtc`，**算不出进度百分比** |
| **工人** | 只有 `workerId?: string` 一个字符串。没有工位、没有认领/释放、没有排队 |
| **围栏 / 半成品** | `BuildingsView.applyState` 只认 `fill`（液面）和 `stage`（农田），没有在建表现 |
| **图纸** | 零。能建什么是硬编码数组 `buildableIds()` |
| **建造 UI** | **唯一入口是控制台指令**。玩家点地上的罐子毫无反应——`refreshInteractTarget` 只遍历家具 + 门 + 宠物，**从不看 `listBuildings()`** |
| **NPC** | 不存在这个概念，只有宠物。`storyRules` 和 `dialogueDefinitions` **都是空数组** |
| **进度条** | 没有任何可复用组件，也没有世界空间进度条 |

## 分五期

每期结束都可玩、可验收、单独一笔提交。

### 期 A · 石傀儡到场：无头休眠 → 装头 → 苏醒

**Core**
- `Core/src/types/pets.ts` 加 `role?: "pet" | "worker"`（缺省 `"pet"`，老档零迁移）
- `Core/src/Data/pets/index.ts` 加 `stone_golem`：`role: "worker"`、`collisionRadius: 1.1`、`moveSpeed: 0.55`（石头做的，比舒舒还慢）
- `Core/src/Data/items/index.ts` 加 `golem_head`：`placement.interactHint = { action: "pickup" }`

**Frontend**
- `Game3D/Visual/recipes/golem.ts`（新）：低多边形石傀儡，照 `shushu.ts` 的 pivot 骨架，但**走平面着色**（岩石本来就该有折面，和 `soft()` 的毛绒路线相反）。可动件：`headSocket`（空的脖颈插槽）/ `armLeft` / `armRight` / `legs[2]` / `body`。`userData.animate` 三态：`sleeping`（整体下沉、苔藓面朝上）、`idle`（呼吸似的起伏）、`work`（双臂交替砸下去）
- `PetAgent`：`role === "worker"` 时 `chooseNextActivity` 跳过吃/喝/亲近三支
- 开局把它 `placeSleepingPet` 在门前院子东侧；头摆在院子西北角（详见坐标表）
- **装头交互**：手上拿 `golem_head` 对着它按 F。照唱片机那条路写（`RoomScene.ts:1583` 的"拿着唱片 → 换碟"），不走送礼系统

**验收**
- 开新档：院子东侧一尊无头石傀儡坐着，西北角草里一颗头
- 走到头旁边，气泡「右键 拾取」，右键进背包
- 走到傀儡跟前，手上拿着头，气泡变成「F 装上头」；空手时气泡是「……」（他没头，说不了话）
- 按 F：头装上，傀儡站起来（`sleeping → idle` 过渡就是起身动画本身，同 shushu 的 `sleepBlend`）
- 存档往返：装过头的傀儡读档后还是醒着

### 期 B · 对话 → 建造面板 → 图纸

**Core**
- `BuildingLevel` 加 `buildCost?: Array<{ itemId, quantity }>`（**和 `upgradeCost` 同形，就是数组**）
- `logic/buildings.ts` 加 `checkBuild({ level, materials })`，复用 `checkUpgrade` 里那段 `missing_materials` 的写法
- 新物品 `blueprint_gold_jar`（图纸），`state: { buildingId: "gold_jar" }`
- `Data/dialogues` + `Data/story` 写石傀儡的第一段：初次见面 → `emitEventId: "golem.first_talk"` → storyRule → 效果 `open_panel: "build_shop"`（新增一种 StoryEffect）

**Frontend**
- 新面板 `Components/BuildShopPanel/`，`PanelId` 加 `"build_shop"`
- 面板内容：可建型号列表（名字 / 说明 / **材料数组逐条列出，够的绿不够的红** / 建造时长）；点击 → 扣材料 → 背包多一张图纸
- 扣材料的通用入口：`Game/Systems/materials.ts`（新），金币走 `spendGoldFrom`，其余走背包。**一处扣钱，建造和升级共用**

**验收**
- 对着醒着的傀儡按 F → 对话 → 建造面板弹出
- 面板里「储金罐 · 0 金币 · 20 秒」，点击 → 背包里多一张「储金罐图纸」
- `/give gold 0` 之后再点仍然成功（0 枚就是免费）；把造价临时改成 5 金币且身上没钱时，条目变红且点不动

### 期 C · 图纸 → 蓝图 → 工地

**Core**
- `construction` 补 `startUtc: string`（**这是进度条的分母**，现在只有 `finishUtc` 算不出百分比）
- `logic/buildings.ts` 加 `constructionProgress(placement, now): number`（0..1）和 `isConstructionDone(placement, now)`

**Frontend**
- 手上拿着图纸按 F → `beginBuildingSiting({ mode: "build", buildingId: 图纸上的 })`。**选址控制器一行不改**
- 确认落地时**不再立刻建成**：新实例带 `construction: { targetLevelId: "l1", startUtc, finishUtc, workerId: undefined }`，图纸从背包消耗
- `BuildingsView.applyState` 加在建分支：建筑模型整体降到 30% 不透明 + 一圈**施工围栏**（`buildSiteFence`，木桩 + 两道横杆，照占地矩形围一圈）
- 新组件 `Components/BuildProgress/`：世界空间进度条，照 `InteractBubble` 的 rAF + transform 骨架；`RoomScene` 加 `getBuildingProgressAnchors()`

**验收**
- 拿着图纸按 F → 出现半透明储金罐虚影，跟鼠标走，R 能转
- 点一下选定 → 底部确认条 → [确认] → 图纸消失，原地立起围栏 + 半透明罐 + 头顶 0% 进度条
- 领地外 / 压到房子时虚影变红且确认按钮不出现（现成行为，回归验证）

### 期 D · 石傀儡施工（单工位排队）

**Frontend**
- `PetAgent` 加活动 `"work"` 和差事 `{ kind: "build", instanceId }`
- `trySeekConstructionSite()`：照 `trySeekWater()` 同构写。挑**最早下单**的、`workerId` 为空的工地，认领（写 `workerId`）
- 走到工地边 → `seekNear(工地中心, 占地半径 + 1)` → 到了切 `work` 状态 → `animate` 播砸击
- 完工：`construction` 清空、`levelId` 落到 `targetLevelId`、`emit("world_changed", { reason: "buildings" })`、傀儡释放工位
- **排队**：一次只认领一个。别的工地 `workerId` 为空、进度**不推进**（进度按"认领之后才开始走"算，不是墙钟——不然排队的工地会自己走完）

> ⚠️ 这条最容易写错：`finishUtc` 是绝对时间，排队的工地要是也按墙钟算，玩家去睡一觉回来全都建好了，工位就白设了。
> **改法**：`startUtc` 在**傀儡认领的那一刻**才写；没认领的工地 `startUtc` 为空 = 进度 0，"等着"。

**验收**
- 下单后傀儡自己走过去（能看见他走），到了开始砸，进度条涨
- 20 秒后围栏消失、半透明变实心、罐子建成
- 连下两单：第二个工地围栏立起但进度**恒 0**，傀儡建完第一个才走过去
- 建造中把傀儡引开（跟着玩家走）→ 进度停住，回来接着走

### 期 E · 建成后的管理面板

**Frontend**
- `refreshInteractTarget` 加 `{ kind: "building" }` 一支（照门那一支抄），让建筑参与 F 竞争
- 新面板 `Components/BuildingPanel/`，四项：
  - **迁移** → `beginBuildingSiting({ mode: "move", instanceId })`（现成）
  - **拆除** → `removeBuilding`（现成，非空不给拆且说得出剩多少）
  - **升级** → 列出下一级的**材料数组**和时长 → 确认 → 扣材料 → 写 `construction { targetLevelId }` → **围栏立刻立起** → 排队等傀儡
  - **概览** → 当前等级 / 容量 / 存了多少 / 下一级是什么、要多少材料
- `upgradeBuilding` 补传 `materials` 和 `levelReaches`（现在两道门都是恒开的）

**验收**
- 对着建好的罐按 F → 面板四项都在
- 升级：材料够 → 确认 → 围栏立起、进度 0% → 傀儡走过来 → 完工后罐变 l2（3×3，容量 150）
- 罐里有钱时点拆除 → 被拒，提示还剩多少金币
- 升级时屋里有家具 → 被拒（现成规则，回归验证）

## 刻意不做的

- 多个傀儡 / 多工位（G2 的规则天然支持，但本期只有一尊）

- 傀儡在施工间隙的闲逛 AI（本期建完就站在原地）
