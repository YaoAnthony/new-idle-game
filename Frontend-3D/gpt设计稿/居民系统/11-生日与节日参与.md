# 11 · 生日与节日参与

> 状态：**11 已完成** · 2026-09-06 · 本提交 · 前置：04 好感、07 门口、10 信箱
>
> 一句话：每位居民有生日，那天他家门口挂彩带、另一位邻居在他家门口陪他、你送的礼物反应翻倍；
> 节日系统本身另开，这里只留一个口：**节日 = 一天的作息覆盖 + 对话池覆盖 + 门口装饰**。

## 玩家看到什么

- 报纸提前三天登"下周三是阿茜的生日"（邻居动态）。当天早上信箱有她的信："今天是我生日，来我家玩吧！"
- 走到她家门口：彩带、气球（门口展示位临时被占）；咕噜站在旁边（关系表里的 `friends`），两人偶尔冒气泡。
- 按 F：生日专用对话；送礼物 → 反应比平时大一档、好感 ×2、当天记忆 `birthday_<year>`。不送也没事，她只是很高兴你来了。
- 第二天恢复正常，门口装饰撤掉。
- 将来有节日时（比如"丰收日"），居民全体作息表换成节日版：都聚到院子中间、门口挂灯笼、对话全是节日段。这期只留数据形状和一条测试用的假节日。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 生日派对在村民家里，另一位村民在场，送礼物加分 | 门口版派对（有室内后进屋），一位朋友在场，礼物 ×2 |
| 生日蛋糕、拉炮 | 门口装饰 + 一个 `gesture("celebrate")`；不做小游戏 |
| 你的生日：村民给你办派对 | 玩家生日 = 注册时可选填；居民寄信 + 当天全体招呼换生日段。**不做派对** |
| 节日全体参与（钓鱼大会、万圣夜、新年倒数） | 节日系统另开；这里定"居民如何参加"的数据形状 |
| 季节限定活动 | 无季节 |

## 数据

### 生日（居民定义）

`ResidentDefinition.birthday: "MM-DD"`（**新字段**，三位各填）。`PlayerSave.profile.birthday?: "MM-DD"`（**新字段**，可空）。

### 生日流程（Core/src/Data/residents/birthday.ts + storyRules）

全部是规则，`day_started` 触发、条件 `is_birthday_of: residentId`（新条件，比日期）：

| 规则 | 效果 |
|---|---|
| 提前 3 天 | `record_fact("birthday_soon", residentId)` → 报纸邻居动态 |
| 当天早上 | `send_letter(birthday_invite_<id>)`；`porch_decorate(residentId, "birthday")`；`set_flag(birthday_today = residentId)` |
| 当天作息覆盖 | 寿星：整天 `hang_home`；关系表里第一位 `friends`：整天 `visit spot: neighbor_door(寿星)`（02 的场所） |
| 当天对话覆盖 | 03 的池加条件 `birthday_today: residentId`（寿星段 / 朋友段 / 其他人的"今天是 X 生日"段），权重 100 压过日常 |
| 当天送礼 | `gift_*` 信号的规则里 `adjust_affection` 读 `birthday_gift_multiplier`（04 已留）；`add_memory("birthday_<year>")` |
| 次日 | `porch_decorate(residentId, null)` |

- **玩家生日**：条件 `is_player_birthday` → 每位居民 `send_letter(player_birthday_<id>)`（附 `presents` 池一件）+ 招呼池换段。不改作息。

### 门口装饰

07 的 `porch` 表加 `decoration?: decorationId`；`Core/src/Data/residents/decorations.ts`：`{ id: "birthday", visualId: "porch_birthday" }`。渲染在展示位之外的固定点（`BuildingLevel.decorationAnchor`）。

### 节日的口（Core/src/Data/festivals/index.ts，只放形状 + 一条测试节日）

```ts
export type FestivalDefinition = {
  id: FestivalId;
  when: { month: number; day: number } | { weekday: number; nthOfMonth: number };
  /** 居民怎么参加：作息覆盖（全体或按性格）、对话池条件、门口装饰、场所 */
  residents: {
    routineOverride?: RoutineSegment[];          // 覆盖当天整张作息表
    gatherSpot?: SpotKind;                       // 都去哪儿（02 场所表里的一种，可新增 festival_ground）
    decoration?: decorationId;
    talkCondition: DialogueCondition;            // 03 的池用它挑节日段
  };
};
```

- 节日的**其他部分**（玩家的活动、奖励、特殊物品）不在居民系统里。这里只保证：节日定义出现时，居民系统**不需要改代码**就会参加。
- 一条 `test_festival`（`when` 指向一个永远不会到的日期，指令 `/festival start test_festival` 强制开始）用来验收这个口。

## 联机

- 生日 / 节日由房主时钟判定，效果在房主执行；房客看到的是切片（porch 装饰）+ Intent（作息覆盖）+ 信箱（切片）。
- 联机验收：房主 `/npc fox birthday` → 房客那边阿茜门口出现装饰、咕噜站过来；房客按 F 阿茜说的是生日段（条件读同步过来的 flag——`birthday_today` 存 `WorldSave.flags`，走 `unlockedFeatureIds` 旁边新加的 `flags` 切片）。

## 指令

| 指令 | 干什么 |
|---|---|
| `/npc <谁> birthday` | 把今天变成他的生日（临时覆盖，不进存档） |
| `/festival start <id>` / `end` | 强制开始 / 结束一个节日 |

## 存档与契约

`ResidentDefinition.birthday`（内容）；`PlayerSave.profile.birthday?`（人的）；`WorldSave.flags: Record<string, string>`（**新**，通用一次性旗子，`set_flag` 效果写）+ 切片。`porch.decoration`。**版本号 +1、空迁移、切片 + 白名单 + 协议 +1。**

## 刻意不做的

- 玩家生日派对；蛋糕道具；节日玩法本体；生日礼物专属物品（用 presents 池）；年龄。

## 最容易写错的三处

1. **生日判定用设备时间。** 用世界日 `worldDayId` 的月日。
2. **装饰占了展示位**，送的灯被挤掉。装饰有自己的锚点。
3. **节日作息覆盖写进 routine 代码。** 覆盖是 `resolvePersonality` 的一个入参（今天有没有节日），routine 只读结果。

## 验收

- 浏览器：`/npc fox birthday` 截图门口与对话；`/festival start test_festival` 看全体聚到院子。

## 收工记录（2026-09-06）

**做成的样子**：三位各有生日（定义上的 "MM-DD"，按世界日的月日比）。全是 `day_started` 上的规则，门槛是**触发器上的通用
条件**（`trigger.requires`，对话条件那张表直接拿来用，按"没有对话对象"求值）：提前三天 `record_fact` 登报"过几天是阿茜的生日"；
当天 `set_flag(birthday_today)` + `porch_decorate(彩带)` + `send_letter(邀请)`；次日撤（撤的规则排在立的前面）。作息覆盖读旗子
（`routineOverrideFor`）：寿星整天 hang_home、关系表里的 friends 整天 `visit neighbor_door` 且**点名寿星家**（RoutinePlan.visit 多了
`owner`，nearestFreeSpot 按主人过滤）；旗子一变把每位正在做的作息打断重下——同优先级不互抢，不打断的话正在坐的那一小时
谁也抢不掉。对话：招呼 / 闲聊池各加权重 100 的生日段（寿星自己、朋友、你的生日、节日）。送礼当天四档翻倍
（gainAffection 读旗子）+ `resident_gift_on_birthday` 信号 → 记忆 `birthday_gift`。你的生日：`/birthday set MM-DD`，当天每位寄一封
夹一件、招呼换段，不办派对。节日：`Data/festivals` 只放形状 + `test_festival`（2 月 30 日永远不到），`/festival start` 立旗子、
全体门口挂灯笼、作息按节日表（都去井边）、闲聊必抽节日段；`end` 恢复；按日期立 / 拔是两条规则。通用旗子 `WorldSave.flags`
进切片（协议 v13），`set_flag` 效果写、`flag_is` 条件读，以后剧情记"某件事发生过"也用它。

**和文档不一样的地方**

| 文档写的 | 实际 | 为什么 |
|---|---|---|
| 条件 `is_birthday_of` 写在规则上 | `StoryTrigger.requires`：通用条件当触发门槛（`is_birthday_of` `birthday_in_days` `flag_is` `festival_on` `is_player_birthday`） | 触发器原来只有几个专用字段（requiresAffection / requiresItem…），再加一个专用的就是第七个；接通对话条件表之后以后任何条件都能当门槛 |
| 记忆 `birthday_<year>` | `birthday_gift`（不带年） | 规则里的 memoryId 是字面量，带年份要靠代码拼——那就不是"全数据"了 |
| `PlayerSave.profile.birthday` | `PlayerSave.birthday`（没有 profile 这一层） | 存档里没有 profile；不为一个字段造一层 |
| 生日派对"有室内后进屋" | 门口版：朋友站门口，寿星在屋里的窝上 / 门口转 | 08 的室内只有 3×3，两位挤不下；朋友在门口和寿星隔着门就能开双人对话（06 的 meet 距离够） |
| 玩家生日在注册时填 | 只有指令 `/birthday set` | 角色创建面板没动；等 14 开场那期看要不要加 |

**踩的坑**：作息覆盖第一版只改了 `planRoutine` 的输入，浏览器里咕噜照样坐在窝上——他正在做的那条 routine Intent 有一小时，
同优先级的 routine 抢不掉自己（身体那层的规矩）。加了 `interruptIntentOf("routine")` + `flags_changed` 监听（进用例）。
装饰的几何函数误插进了 BuildingsView 的类体里（锚点是一个方法的注释），编译报了一屏；挪到模块级。

**没做**：玩家生日派对（用户定不做）；蛋糕；联机双端（旗子进切片、房客按 F 读得到"今天是谁的生日"，没实测）。
顺手记到 15：朋友站门口和屋里的寿星隔着墙开双人对话（06 的 meet 只看距离）。
