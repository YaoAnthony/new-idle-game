> 状态：**已完成** · 2026-08-24 · 见文末收工记录 · 前置：期 0（信号 / 效果 / 池）+ 期 1（价格）+ 期 2（开箱）

## 一句话

金库建成的第二天，一条小龙偷走几枚金币；一只背着大书包的水獭找上门说能帮你抓，
但他看上了你的家具——从此每三天来一趟收货，顺便卖你种不出来的食材。

**这一期是整套改造的枢纽**：两条循环第一次接上（家具 → 金币），金币第一次有了
经常性去处（食材），剧情引擎第一次真的跑起来（`storyRules` 从空数组变成一条链）。

#### 来去调度

**固定周期，玩家数得出来**（用户定）。判据用世界日的天数差，不用随机：

```ts
// Systems/trading.ts（新）
/**
 * 水獭今天在不在。
 *
 * **固定周期**（`tradingTuning.otterVisitEveryDays`，3 天）而不是随机：
 * 他是"收货的熟人"不是稀客，可预期正是他该有的气质——玩家能规划
 * "后天他来，我再攒两件"。稀客那一档留给旅行商人（期 6，7 天以上），
 * 两个角色一密一疏才不会糊成一个。
 *
 * 基准日是**他第一次登场那天**（进存档），不是世界的第 0 天——
 * 否则玩家在第 5 天解锁交易，他的周期看起来是从天上掉下来的。
 */
export function isOtterHereToday(): boolean;
```

在场 = `spawn_pet` 把他放到摊位；不在场 = 从运行时移除（不是隐藏——
隐藏的话碰撞体还在，玩家会撞到空气）。切换挂在 `day_started` 上。

> **摊位是布景，不是建筑**：河岸边一张小摊（`Visual/recipes/` 里一个
> 小模型，或者 `Maps/base/dressing.ts` 里加一处陈设）。做成建筑的话它会
> 进存档、能拆能移，而"商人的摊位"不该是玩家的财产。

### 3B · 偷窃链（剧情引擎的第一条链）

**这一步一行 gameplay 代码都不写**，全是 `Core/src/Data/` 里的数据。
期 0 补的口子就是为它准备的。

#### 事件

```ts
export const eventDefinitions: EventDefinition[] = [

    id: "gold_theft",
    localizationKey: "event.gold_theft",
```

#### 规则链


**追与不追的分岔靠对话选项的 `emitEventId`**：玩家点"不用管他"那一项
发 `theft_waived`，规则 ④' 抢先把事件推到 `settled`，于是 ④ 的
`requiresEventStage: chasing` 第二天就不成立了——**龙不会被抓，钱也不回来**。
**对话本身不写效果**（`dialogueDefinitions` 那段注释的既有约定），
只报告"我到了这里"。

> ⚠️ 用户 2026-08-24 明确过：**拒绝不影响他做生意**——"商人是随着事件
> 出现随机过来的，不影响"。所以 ⑤ 和 ④' **两条都要 `unlock_feature`**。
> **别让拒绝把销路一起拒掉**——那会把玩家锁在没有收入的世界里。

#### 五天的节奏

| 天 | 发生什么 | 阶段 |
|---|---|---|
| D1 | 金库落成 | `eyed` |
| D2 | 早上发现少了几枚，龙影掠过院子 | `robbed` |
| D2 稍后 | 水獭上门：「我见过那家伙，我去把它逮回来」 | `chasing` |
| **D3** | **水獭拎着小龙回来了**——你第一次看清那条龙 | `caught` |
| D4 | 钱全额奉还；他提出长期合作，从此收你的家具 | `settled` |

**五幕看起来长，但它是这游戏唯一一条这么长的链**，而且每一幕都有画面：
落成 / 失窃 / 上门 / 见贼 / 了结。真实时间四天，`/day` 一分钟能跑完。

> 用户原话是"多一个时间，把小龙抓回来了"。合并成"抓回来的同时还钱"
> 也讲得通、而且短一天——**但那样见贼这一幕会被追赃盖掉**，玩家读到的
> 只剩"钱回来了"，那条龙又变回一个数字。分开是为了保住那张脸。

#### 演出：在场时演，不是上线看一行字

用户定的是"在场时演"。做法：`show_toast` 之外，规则触发时 EventBus 发一个
场景事件，`RoomScene` 听到就放一段：**金库的箱盖敞着 + 一条小龙的影子从
院子那头掠过**。

**小龙需要两套表现**（因为它现在有两幕）：

| 幕 | 表现 | 要什么 |
|---|---|---|
| D2 失窃 | 一道**掠过的影子**，看不清 | 剪影就够，可以是同一个模型压暗、快速划过 |
| **D3 被抓** | **站在院子里被你看清**——垂头丧气、被水獭拎着 | **完整模型 + 一段待机动画 + 一段对话** |

所以它**进 `petDefinitions`**（`coin_dragon`），不是纯演出道具——
`spawn_pet` / `start_dialogue` / 按 F 交互那一整套都要它是个真生物。
但它**不常驻**：⑤ 那一步之后从运行时移除。

> 这是相对初稿的改动。初稿写的是"只出现在演出里、不进 petDefinitions"，
> 那是在"只有影子"的前提下成立的；用户 2026-08-24 加了「抓回来」这一幕，
> 前提变了。

对着在场的水獭按 F → 面板。照 `BuildShopPanel` 的"左分类右卡片"版式。

#### 「这回想要的」

```ts
// Systems/trading.ts
/**
 * 他这回特别想要哪几件。**确定性抽签**——同一趟里反复开关面板必须
 * 抽出同一批，否则玩家会一直重开面板直到抽到自己背包里最多的那几件，
 * 加价这个机制当场失效（和每日任务抽签同一条判据）。
 *
 * 种子用**这一趟的日期**而不是"第几趟"：日期是现成的、不用另存计数。
 */
export function wantedToday(): Set<ItemId> {
  const seed = hashSeed(`otter_wanted|${getClock().worldDayId}`);
  return new Set(drawDeterministic(sellableItemIds(), tradingTuning.wantedCount, seed));
}

export function sellPrice(itemId: ItemId): number {
  const base = findItemDefinition(itemId)?.value ?? 0;
  return wantedToday().has(itemId)
    ? Math.round(base * tradingTuning.wantedMultiplier)
    : base;
}
```

#### 卖出结算

走**一条路**：`Systems/trading.ts` 的 `sellItem(itemId, count)`
→ `removeItem` + `depositGoldTo`（满了照常溢出提示）。

> **溢出在这里第一次变得刺眼**：一趟清十几件家具，l1 金库只装 10。
> 这是想要的——它把玩家推向升级金库，而金库升级本来就是期 2 建好、
> 一直没有理由用的功能。**但要确认提示不刷屏**：一次卖一批只报一次
> 溢出总量，不是每件报一次。

## 最容易写错的四处

### 一 · 拒绝抓贼不能连销路一起拒掉

用户明确过"不影响"。两条分支都要解锁 `merchant_trading`——只在"追回"
那条上解锁的话，选了"不用管他"的玩家会永远没有销路，而卖货是主要收入
（决策：卖货为主）。这是本期唯一能把玩家锁死的路径。

### 二 · "第二天"靠 `day_started` + `requiresEventStage`，不是靠 `minWorldDayId`

`minWorldDayId` 是**绝对日期**（"2026-09-01 之后"），表达不了"建成之后
的第二天"。相对的第二天只能用"事件停在某阶段 + 新的一天开始了"这个组合。
期 0 补 `day_started` 就是为它。

### 三 · 离线多天回来，偷和还各只发生一次

`day_started` 离线只补发一次（期 0 定的），所以 ②→③→④ 这条链**一天推一步**，
玩家离线七天回来只走一步。这是对的：剧情不该在你不在的时候自己演完。
用例要钉住（判据：设 `lastObservedWorldDayId` 为七天前，启动后事件阶段只前进一格）。

### 四 · 商人不在场时按 F 什么都不该有

从运行时移除而不是隐藏。隐藏的话碰撞体还在（`collisionRadius: 0.5`），
玩家会撞到一团空气，而且 `refreshInteractTarget` 会把他算进交互竞争。

### 用例抓出来的引擎级缺陷（本期最大的收获）

**一次派发里后面的规则看得到前面规则刚改的阶段。** `StoryContext.eventStage`
是惰性求值的函数——`theft_strike` 把阶段推到 robbed，同一次 `day_started`
里下一条规则的 `requiresEventStage: robbed` 立刻成立，五幕在一天里连锁跑完，
"一天一步"整个塌掉。**离线测试第一个红**（期 0 的"只补发一次"变得毫无意义）。

修法：**一次派发看到同一份世界快照**——`currentContext()` 里对
eventStage / isFeatureUnlocked 做派发内 memo。要连锁请显式用两条信号。
这条若晚发现半年，会以"剧情偶尔跳幕"的形态出现且极难复现。

### 已知限制

1. **偷不足额时净赚**：库里只有 5、偷走 5，奉还固定 8 → 玩家净 +3。
   方向永远对玩家有利（不违反"不制造焦虑"），修的话要把"实际偷走多少"
   存进事件状态——`EventProgressSave` 今天没有这种口袋，不为一个上限 8 的
   口子加存档字段。记录，不修。
2. **龙影掠过的演出没做**（D2 只有 toast + 金币变少 + 箱盖状态）。
   影子飞过是纯表现层的一段动画，不挡任何机制，补的时候零数据改动。
