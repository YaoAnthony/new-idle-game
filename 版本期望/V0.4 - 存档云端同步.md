# 云存档功能

在 V0.4 版本中，我们主要实现存档云保存功能

当用户登录之后，所有的生命周期应当如下：

1. 打开游戏时，会先检查 token。
2. token 没问题，就问云端：现在是不是在联机，有没有云端存档。
3. 如果不是联机状态，就按云端存档优先进入游戏。
4. 如果云端没有存档，但本地有，就把本地存档传上去。
5. 如果云端服务挂了，用户仍然可以用本地存档玩。
6. 游戏过程中，每 30 分钟同步一次云端。
7. 退出游戏前，先保存本地，再尽量同步云端。
8. 如果正在联机，就不走普通云存档同步，而是等 server session 结束后由服务端写回。

## 联机模式前瞻

在下一个版本的联机版本正式上线之前，我们需要做出一下的接口

### 同步存档
websocket启动下，停止同步存档到云端，而是直接启用server 的存档 ref，直到联机结束

## Runtime Mode

客户端需要明确区分三种状态：

- local_only
  没登录，或者 token 无效，或者云服务不可用。
  只用本地存档。

- cloud_sync
  已登录，并且没有在联机。
  本地正常玩，本地正常存，同时按规则同步云端。

- multiplayer_session
  已登录，并且正在联机。
  停止普通云存档同步，状态听 server session 的。


### 意外断线

统一以下面的方式处理：

首先client走正常步骤
1. 打开游戏时，会先检查 access token。
2. token 没问题,获得了用户信息，就问云端：现在是不是在联机，有没有云端存档。

在这里server返回正在联机，
3. 用 sessionId、playerId、Token、请求恢复。
4. 恢复成功：
  - server 返回最新的存档，client接受最新的联机数据
  - client 以 server 状态为准继续。
4. 恢复失败：
   - client 不上传本地 session cache。
   - 回到最后稳定的本地/云端存档。


如果玩家持续掉线，超过 server 的 heartbeat timeout，导致websocket退出，server自动会保存最新的存档，此时

在这里server返回没有联机，但是依旧同步云端存档，
3. 获得最新存档

### 房主意外断线

如果 3 个玩家进入了 A 玩家存档，那么 A 就是这个 session 的 owner。

如果 A 掉线：

1. server 等待 A 重连，等待时间暂定 30 秒。
2. 30 秒内 A 重连成功：
   - session 继续。
   - server 返回最新联机状态给 A。
3. 30 秒内 A 没有重连：
   - server 立刻保存当前最新 session state 到 A 的云端存档。
   - server 结束 session。
   - server 把其他玩家全部踢出联机。
   - 其他玩家回到自己的本地/云端存档状态。
4. A 下次登录时，直接读取自己最新的云端存档。


### 访客意外断线

如果掉线的是访客：

1. server 等待该访客重连，等待时间暂定 30 秒。
2. 30 秒内重连成功：
   - 访客回到当前 session。
3. 30 秒内没有重连：
   - server 把该访客移出 session。
   - session 继续，不影响房主和其他玩家。
