# 10 · 信箱

> 状态：**10 已完成（信箱造型与两张插图待参考图）** · 2026-09-06 · 本提交 · 前置：04 好感、09 出门
>
> 一句话：门口一只信箱，居民会写信给你、附一样东西；出门的居民寄明信片；你也能给他写信。
> 离线期间寄到的信回来一次看完。信是唠叨的另一条渠道，也是剧情送"物"的一条渠道。

## 玩家看到什么

- 早上出门，主屋门边的信箱旗子立着（有新信）。按 F 打开信箱面板：一叠信封，点开一封是薇尔的信纸，字迹、称呼（`{you}`）、落款，底下夹着一样东西的图标，点"收下"进背包。
- 咕噜回老家的第二天收到明信片，画着"老家"的插图，一行字。
- 面板里有"写信"：选收信人（在场居民）、从几句固定模板里挑一句（不能自由输入）、可以夹一样东西 → 次日他见你时提起这封信，夹的东西按送礼规则算。
- 离线七天回来，信箱里三封，不多不少（每人每几天最多一封，上限由数据定）。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 村民寄信，好感高的附礼物 | 取 |
| 你寄信（自由输入，村民按关键词回） | 改成**模板句**——不做自由输入解析，也避开 UGC 审查 |
| 搬走告别信 | 出门明信片 |
| 信在信箱里堆积，满了新信丢失 | 信箱上限 20，**满了不再寄**（不丢） |
| 母亲的信、狸克的通知 | 剧情信：`send_letter` 剧情效果，主线用得上（魔女来信） |

## 数据

### 信件模板（Core/src/Data/residents/letters.ts）

```ts
export const letterDefinitions = [
  { id: "slime_hello",   residentId: "slime_neighbor", bodyKey: "letter.slime.hello",
    requires: [{ kind: "affection_at_least", stage: "familiar_resident" }], weight: 2,
    attach: { pool: "presents" } },                                    // 04 的 presents 池
  { id: "slime_thanks_lamp", residentId: "slime_neighbor", bodyKey: "letter.slime.thanks_lamp",
    requires: [{ kind: "remembers", memoryId: "favor_slime_lamp" }], once: true },
  { id: "postcard_hometown", kind: "postcard", bodyKey: "postcard.hometown", illustrationId: "postcard_hometown" },
  { id: "witch_first", kind: "story", bodyKey: "letter.witch.first", illustrationId: "letter_witch" },   // 主线用，由效果发
] satisfies LetterDefinition[];

export const mailTuning = {
  boxCapacity: 20,
  /** 每位居民每 N 天最多一封自发信；保底池 */
  perResident: { everyDays: 4, base: 0.25, step: 0.15, max: 0.9 },
  requires: [{ kind: "affection_at_least", stage: "familiar_resident" }],
  playerTemplates: ["letter.you.hi", "letter.you.thanks", "letter.you.miss", "letter.you.come_over"],
} as const;
```

- 三类：`resident`（居民自发，条件 + 权重抽）、`postcard`（09 出门时系统发）、`story`（剧情效果 `send_letter: { letterId, attach? }` 发，**主线的"魔女来信"就走这个**——没有对应的实体角色也能寄）。
- 信的**后果**（附件入包、好感 +、记忆）由收信 / 拆信发信号 `letter_opened`（subject = letterId）→ 规则接。信箱系统本身只管收、存、开。

### 存档

- `WorldSave.mailbox: { letters: Array<{ id: string; letterId: string; fromResidentId?: string; receivedDayId: string; opened: boolean; attach?: { itemId; quantity }; playerText?: { templateKey; toResidentId } }> }`（**新字段**）。
- 信**属于世界还是人**？收信人是"这个家"（房主），寄件人是居民（世界的）。放 `WorldSave`：联机时房客能看信箱面板但**不能收附件**（附件是房主的）。

### 你写的信

- 面板"写信" → 收信人 + 模板句 + 可选附件（从背包挑一件）→ 写进 `mailbox.outbox`（同一字段下）。
- 次日 `day_started`：房主端处理 outbox：附件走 `offerGift` 的委托 / 口味判定（复用 05、现有送礼），产生 `gift_*` 信号；居民下次见面对话池多一段 `replied_letter`（条件 `letter_replied_pending`），说完清掉。**不做自动回信**——他当面回应，比一封模板回信像活人。

## UI

- 信箱：主屋门边一件**固定布景**（不是家具，不可搬），旗子 = 有未读。按 F 走 `interact_target` 加一种 `mailbox`。
- 面板 `MailboxPanel`：左边信封列表（未读加粗），右边信纸。信纸用报纸那套做旧风格的**信纸变体**（同一族字体、纹理），明信片是横版带插图。手机横屏 667×375 单列切换，不做双栏。
- 附件"收下"按钮复用 RewardPanel 的领取语义（走 `presentItems`，一封一次）。

## 联机

- 信箱是世界的，走 `mailbox` 切片（**`WORLD_REFRESH_KEYS` 加一项**）。房客能打开面板读信（好感、称呼按房客渲染 `{you}` → generic），**"收下"按钮不显示**，写信入口不显示（做客中）。
- 联机验收：房主收到一封带附件的信 → 房客打开信箱看到同一封、无"收下"；房主收下 → 房客那边附件图标消失。

## 刻意不做的

- 自由输入；自动回信；信箱满了丢信；给非居民（商人）写信；信件语音；离线补寄超过上限。

## 最容易写错的四处

1. **附件在收信时就入包。** 拆信 → "收下" 才入包，走领取语义，房客看不见按钮。
2. **outbox 附件直接 `removeItem`。** 走 `offerGift`，让口味 / 委托判定发生，居民才"知道"你送了。
3. **明信片在出门当天就到。** 第二天。
4. **信箱容量满了继续寄。** 不寄，池 miss 不累加（不然回来一开箱 20 封同一天的）。

## 收工记录（2026-09-06）

**做成的样子**：主屋门前两步半一只红信箱（占位造型，旗子 = 有没拆的信），站到跟前"F 有新信 / 看信箱"打开面板：
左边信封列表（未读加粗、📎 有附件），右边信纸（借报纸那套做旧纹理），明信片是带插图框的横版；附件"收下"经领取面板
入包（一封一次），做客中没有"收下"和"写信"。三条进信的路：居民自发（`resident_mail` 池，同一天最多一位，伙伴档起；
写哪封在效果里按条件 + 权重抽，每位每 4 天最多一封，`once` 不重寄，附件从他的 presents 里按种子挑）、
出门明信片（09 的 `resident_away` 排定**第二天**到，去小镇当天往返的不寄）、剧情信（`send_letter` 效果，没有实体角色也能寄——
魔女那封已经在表里等 14 用）。拆信发 `letter_opened`，后果由信件表的 `onOpened` 生成规则（好感 +2、谢委托那封记忆）。
"写信"= 收信人 + 四句模板之一 + 可选夹上手里那件（写信那一拍就离开背包）→ outbox → 次日早上房主端处理：夹的东西走
`giftByMail`（委托 / 口味四档 / 进食结算 / 四个信号一样不少，不占当天送礼名额），记一笔"等他当面提"，下次见面闲聊池
必抽 `<who>_chat_replied_letter`，说完清掉。**不做自动回信**。信箱满 20 封不寄（不丢），池 miss 归零不累。

**和文档不一样的地方**

| 文档写的 | 实际 | 为什么 |
|---|---|---|
| 信箱贴在主屋门边 | 门前两步半、往右 0.9 米，**在门框的视锥里** | 镜头固定朝北，主屋的门朝北开：贴墙放门边从哪个角度都看不见它；门开着从屋里往外看正好看见 |
| `mailbox.outbox` 处理"附件走 offerGift" | `giftByMail(residentId, itemId, quality)`：offerGift 的尾巴拆出来的一条没有格子的路 | 东西写信时就离开背包了，次日没有 SlotRef 可递；判定和信号一个不少 |
| 每人每几天一封 + 保底池写在 mailTuning.perResident | 节流在效果里（everyDays），保底是全体共享的一个池 | 剧情池按 poolId 同一天只抽一位，每人一个池要三个池、三份 miss；共享一个池 = 同一天最多一封信，本来就是要的 |
| 离线七天回来三封 | 没做离线补寄 | day_started 一次只掷一次；补寄要另算"错过的天数"，等 15 看有没有必要 |
| 插图两张、信箱建模走出图流程 | 明信片留了插图框（文案"插图待画"），信箱是几何占位 | 先问参考图 |

**踩的坑**：信抬头的 `{you}` 在还没叫法的档位渲染成空——对话里省略称呼没问题，信里就是一个光秃秃的冒号；
信的抬头改成"叫法 || 玩家名"。`deliverLetter` 返回的是信箱里那个对象本身，用例里收完附件再读同一个引用会读到 undefined
——按 id 再查一次。验证时 `rig.orbit(180)` 想把镜头转过来，把镜头状态弄坏了（整屏灰），刷新才恢复：**镜头固定朝北，别转它**。

**没做**：离线补寄；插图与信箱造型（参考图）；联机双端翻信（房客只读靠 `isRemoteWorld` 挡，切片 v12 已进，没实测）。
