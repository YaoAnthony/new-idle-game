# 天气系统

在这个版本中，我们开始设计天气系统。

天气系统不是单纯换一个背景图，而是世界状态的一部分。之后 NPC 作息、小动物出门、环境音、事件触发、家具声音，都会读天气。

目前先做基础天气，后期再慢慢加更复杂的天气，比如下雪、雾天、流星雨、魔法雨之类的。

## 天气类型

初期应该有以下天气：

1. 晴天
2. 阴天
3. 雨天
4. 刮风天
5. 暴雨

晴天和阴天是最基础的天气，不需要特殊交互。

雨天会影响环境音，小动物出门可能会带回一些潮湿、植物、蘑菇之类的东西。

刮风天会影响风铃、窗帘、树叶、一些轻飘飘的家具表现。

暴雨是特殊天气，暴雨可以作为事件条件，比如后续 `救助大河` 事件就需要暴雨。

## 天气注册

天气也应该走注册表，不应该直接写死在 gameplay script 里。

```ts
type WeatherId = string;

type WeatherDefinition = {
    id: WeatherId;
    localizationKey: string;

    // 基础类型，用来给系统判断，不一定等于显示名
    kind: "sunny" | "cloudy" | "rain" | "wind" | "storm";

    // 强度，主要给表现层和声音层读取
    intensity: "light" | "normal" | "heavy";

    // 天气会给哪些系统提供标签
    tags: string[];

    // 视觉和声音资源都只存 id，具体资源由表现层注册
    visualProfileId: string;
    audioProfileId: string;
};
```

比如：

```ts
const weatherDefinitions = [
    {
        id: "sunny",
        localizationKey: "weather.sunny",
        kind: "sunny",
        intensity: "normal",
        tags: ["dry", "bright"],
        visualProfileId: "weather_visual_sunny",
        audioProfileId: "weather_audio_sunny",
    },
    {
        id: "heavy_rain",
        localizationKey: "weather.heavy_rain",
        kind: "storm",
        intensity: "heavy",
        tags: ["wet", "dark", "event_candidate"],
        visualProfileId: "weather_visual_heavy_rain",
        audioProfileId: "weather_audio_heavy_rain",
    },
];
```

## 世界天气

天气应该属于世界，而不是属于玩家。

如果玩家进入自己的世界，就读取自己的 `ownWorld.weather`。

如果玩家进入朋友的世界，就读取房主世界的天气。

```ts
type WeatherSave = {
    // 用来根据 WorldDayId 稳定生成自然天气
    seed: number;

    // 最近一次已经确认过的世界日期，主要用于每日天气生成和诊断
    lastResolvedWorldDayId: WorldDayId;

    // 当前自然天气日程，不保存“现在天气”，而是保存这一天的天气安排
    schedule: WeatherScheduleEntry[];

    // 事件、道具、家具造成的临时天气覆盖
    overrides: WeatherOverrideSave[];
};

type WeatherScheduleEntry = {
    weatherId: WeatherId;
    startsAtLocalTime: string;
    endsAtLocalTime: string;
};

type WeatherOverrideSave = {
    overrideId: string;
    weatherId: WeatherId;

    source:
        | "event"
        | "item"
        | "furniture"
        | "debug";

    priority: number;

    startsAtUtc: UtcTimestamp;
    endsAtUtc?: UtcTimestamp;

    // 如果只影响某个地图或房间，可以填 scope
    scope?: {
        mapId?: string;
        roomId?: string;
    };
};
```

这里最重要的是：天气不应该一直保存“现在是什么天气”。

当前天气应该由以下内容推导：

1. 统一 Clock Interface 拿到当前有效 UTC。
2. 转换到世界保存的 `timeZoneId`。
3. 根据 `WorldDayId` 和天气 seed 得到当天自然天气表。
4. 如果有事件、天气瓶、家具等 override，就按优先级覆盖。

这样就不会因为玩家切设备、改时区、进朋友世界，而让天气突然变得不可靠。

## 每日天气生成

自然天气按世界日期生成。

同一个 `worldId + seed + WorldDayId` 应该生成同一份天气日程。这样玩家当天反复进出游戏，天气不会乱跳。

初期可以非常简单，比如每天只生成一个主天气：

```ts
type DailyWeatherRoll = {
    worldDayId: WorldDayId;
    weatherId: WeatherId;
};
```

后期再升级为一天多个阶段：

```ts
[
    { weatherId: "cloudy", startsAtLocalTime: "06:00", endsAtLocalTime: "12:00" },
    { weatherId: "rain", startsAtLocalTime: "12:00", endsAtLocalTime: "18:00" },
    { weatherId: "clear_night", startsAtLocalTime: "18:00", endsAtLocalTime: "24:00" },
]
```

如果跨过了很多天，游戏不需要补算所有错过日期的天气，只需要算当前 `WorldDayId`。

## 天气和事件

天气可以作为事件条件，但是天气自己不推进剧情。(此处是展望，不参与此版本设计)

比如 `救助大河` 应该是：

1. 已经完成前置事件。
2. 当前世界日期已经达到要求。
3. 当前天气是暴雨。
4. 玩家走到门口并选择交互。

只有玩家真正触发并完成事件之后，才写入 `progression.events`。

如果某一天暴雨但是玩家没有开门，那么事件不应该自动完成。之后再遇到符合条件的暴雨，依旧可以触发。

## 天气和 NPC

天气系统放在 NPC 系统之前，是因为 NPC 会读天气。

小动物可以根据天气决定：

1. 要不要出门。
2. 出门带什么东西回来。
3. 会不会躲在屋里睡觉。
4. 对玩家做的食物或家具有没有额外反应。

例如：

- 雨天更容易带回蘑菇、湿木头、花瓣。
- 刮风天更容易带回羽毛、风铃碎片、纸片。
- 晴天更容易带回普通素材。
- 暴雨天一般不适合普通小动物出门，但可以触发特殊事件。

NPC 作息可以读取天气，但不能直接修改天气。想修改天气必须通过事件、道具或家具能力。

## 天气和声音

天气要接入声音系统。

下雨时，靠近窗户和门应该能听到更清晰的雨声。

刮风时，风铃会响，窗帘会动，屋外可能会有风声。

暴雨时，环境音应该更明显，也可以让室内音乐更安静一点。

声音层只读取当前天气结果，不负责判断天气规则。

## 天气瓶

后期工作台可以做天气瓶。

天气瓶不是永久改变世界天气，而是在一定时间内添加一个天气 override。

比如：

```ts
type WeatherBottleEffect = {
    weatherId: WeatherId;
    durationSeconds: number;
    scope: "room" | "map" | "world";
};
```

初期可以先做房间范围，比如雨瓶只让房间进入下雨白噪音状态，不一定真的改变整个世界。

如果天气瓶影响整个世界，那就要写入 `WeatherOverrideSave`，并且联机时必须由 Server 验证。

## 联机天气

联机时，只使用房主世界的天气。

房客看到的天气、听到的环境音、遇到的事件天气条件，都应该来自房主世界。

联机中的天气时间来源使用 Server UTC，然后转换到房主世界的 `timeZoneId`。

房客不能用自己的设备时间或自己世界的时区改变房主天气。

如果房客使用天气瓶，这属于耐久操作，必须发送给 Server：

```ts
type UseWeatherItemCommand = {
    itemStackId: string;
    weatherId: WeatherId;
    scope: {
        mapId?: string;
        roomId?: string;
    };
};
```

Server 验证成功后，更新房主世界的 `WeatherSave.overrides`，增加 revision，再广播给所有玩家。

## 命令行调试

因为 V0.3 已经有命令行系统，所以天气应该提供调试命令。

比如：

```txt
/weather sunny
/weather rain
/weather storm 30m
/weather clear_override
```

这些命令只用于调试。

正式玩法里，玩家想改变天气，应该通过天气瓶、家具、事件或未来魔法系统。

## 初期目标

这个版本只需要做到：

1. 可以注册天气类型。
2. 可以根据世界时间算出当前天气。
3. 可以把当前天气交给视觉、声音、NPC 和事件系统读取。
4. 可以保存天气 seed、当天日程和临时 override。
5. 联机时读取房主世界天气，并用 Server UTC 判断。

天气系统不需要在这个版本做得特别复杂，但接口要留好。因为后面很多东西都会慢慢靠天气变得更像一个活着的世界。
