## 两条硬前置

### 前置 A · 可走范围和房子尺寸解耦

`yardBoundsOf(map, room.floorGrid)` 拿**房子宽深 + 四向边距**算可走范围，三处消费（`doorsRuntime`、`navigation`、镜头）。房子从 24×20 缩到 9×12，可走范围跟着缩：

| | 24×20 | 9×12 | 后果 |
|---|---|---|---|
| 东界 | 12 + 33 = **45** | 4.5 + 33 = 37.5 | 东桥（到 45）走不到头 |
| 西界 | −12 − 24 = **−36** | −4.5 − 24 = −28.5 | A 列领地（−40..−25）出界 |

**改法**：`MapDefinition` 加可选 `walkableRect?: DeckRect`，给了就直接用，不再从房子推。base 写今天的实际值 `{ minX: -36, maxX: 45, minZ: -24, maxZ: 47 }`——**零行为变化**，只是把"据点多大"从房子身上摘下来变成地图自己的数。小镇、店铺不动。

```ts
// Core/src/logic/roomGeometry.ts · yardBoundsOf —— 改后
export function yardBoundsOf(
  map: Pick<MapDefinition, "yardMargin" | "yardMargins" | "walkableRect">,
  floorGrid: { width: number; height: number },
): DeckRect {
  // 地图自己声明了可走范围就用它——"据点多大"是地理，不该跟房子尺寸走。
  // 老的按房子推的算法留给没声明的图（小镇、店铺），它们的房间就是整张图
  if (map.walkableRect) return map.walkableRect;
  …原逻辑不动…
}
```

验收：`Core` 加一条用例——给 `walkableRect` 时返回它、不给时按原算法；Frontend 现有 `yardBoundsOf` 的三处调用方不改。

## 外观（新做的四样，都挂在**风格**上）

`RoomStyleDefinition.visual` 加一项 `shell: "wafu" | "witch_cottage"`。`HouseBuilder.buildHouse` 按它选屋顶 / 外皮 / 大门 / 门廊的建造器——**一条管线两套皮**，地板、天花、内墙、门洞、拾取面、窗玻璃照旧共用。新风格 `witch_cottage`（`Core/Data/roomStyles`），`forest_cottage` 等老风格默认 `wafu`，行为不变。

| 新文件 | 做什么 |
|---|---|
| `House/WitchRoof.ts` | 女巫帽：屋脊沿 z（南北向）在 x≈1.5，峰高 8。西坡陡直到西檐；**东坡是一道弧**（二次曲线采样 6–8 段）扫到东檐，檐口向外挑 0.6。南北两面山墙填石。木瓦：按行错缝的四边形 + 抖色，合批成一个 `createQuadMesh` |
| `House/StoneWalls.ts` | 乱石外皮：逐格四边形，每格在灰米色基色附近抖、随机分成 1–3 块"石头"（用 `hash01` 定）。只建朝外的面，和 `ExteriorWalls` 同样的"外皮往外挪 0.12 + 分组即淡出单位" |

## 期 2 建筑实例那栋 `house` 怎么办

`/build house` 盖出来的是期 2 的粗盒子模型，而现在默认的家是地图自带的。两栋并存会出现"领地上有两个家"。**本期**：把 `house` 从 `buildableIds()` 里摘掉（型号定义留着，`maxInstances: 1` 不动），`/build house` 报"家已经有了"。合并成一条路（默认家 = 建筑实例 l1、升级到 l3 = 2LDK）是下一期的事——那一步要让建筑实例的内景也走 `HouseBuilder` 渲染，期 2 文档「刻意没做」里记了。
