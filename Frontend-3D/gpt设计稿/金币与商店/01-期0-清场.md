### 为什么要做

用户定了：**院子里将来要盖小房子**（仓库、工坊，和主屋同图、不换图）。

0a 的 `houseRectWorld()` 只算**主房间一栋**的矩形。这和"房子中心 = 世界原点"是同一类隐含公理——
代码里没写"只有一栋"，但结构上只容得下一栋。第二栋盖起来的那天，人走进去镜头不切屋内盒，
从屋顶上方俯视穿进去看。到时候再改，就是把 0a 刚收口的三处判据再拆一遍。

### 改法（两个文件）

**`Frontend-3D/src/Game/State/world/maps.ts`** —— 加两个只读访问器

```ts
/** 当前图上的某个房间（含它自己的 RoomAnchor） */
export function getRoom(roomId: string): RoomSave | undefined {
  return worldState.rooms[roomId];
}
/** 当前图上的全部房间 */
export function getRooms(): Readonly<Record<string, RoomSave>> {
  return worldState.rooms;
}
```

理由：家具、门、掉落物都带 `roomId`，转世界坐标必须用**自己那个房间**的锚点；
今天到处用 `getWorld().room`（主房间）去转，是同一公理的另一份拷贝。

**`Frontend-3D/src/Game3D/World/RoomScene.ts`** —— 五处

| # | 位置 | 改前 | 改后 |
|---|---|---|---|
| 1 | 字段 | `private readonly built: BuiltHouse` 单数 | 保留 `built`（门、窗、陈设仍用它），**新增** `private readonly houses: Array<{ room: RoomSave; built: BuiltHouse }>`；构造函数 `buildHouse` 之后 `push` 一条。今天长度为 1 |

## 0b · 存档不再写入小镇/店铺几何

### 背景：什么该存、什么不该存

游戏里两种地方：

- **家**（`base`）：玩家能挪家具、收放房子，改动必须进存档
- **小镇 + 六家店**（`town`、`shop-*`）：布局固定，玩家动不了。`MapDefinition.volatileRooms: true` 标记它们
  「每次进图当场重新生成，存档里那份直接忽略」

这个标记**读档时是生效的**（`restoreWorld` / `switchMapState` 都看它），但**写档时没人看它**——
`snapshotWorld()` 把所有图的完整几何都写进去。结果是写进去了从没被读过。

实测（用下面「验收·字节」那段脚本量的）：

| | 字节 |
|---|---|
| 家 | 2 726 B |
| 小镇 + 六家店（写进去又丢弃） | 7 305 B |
| 废字节占比 | **72.8%** |
| 每多一座同规模小镇 | +7 305 B，随内容线性增长 |

### 为什么不是「改一行」——读档侧的两个暗礁

原计划写「serialize.ts 改一行跳过 volatile 图、连键都不留」。写细后发现**读档侧有两处逻辑依赖那些键存在**：

1. `loadWorldEntities`（`entities.ts`）：`activeKey = bundle.maps[当前图] ? 当前图 : 第一张图`。
   玩家**在店里存档**，存档里没有店的键 → `activeKey` 退回 `base` → 家里的家具被判成「当前图的」→
   **灌进店铺场景**。
2. `restoreWorld`（`maps.ts`）：`current = saved.maps[当前图] ?? 第一张` → 同样退回 `base` →
   `base` 被当成当前图不上架 → 回家时 `shelvedMaps.base` 不存在 → **家的几何按定义重新生成，锚点和收放状态丢失**。
3. `roomToMapIndex`（`entities.ts`）：实体归属靠「存档几何里的 roomId → mapId」索引；volatile 图没几何就没索引。
   定义兜底只补了 `outdoorRoomId` 和 `extraRoomIds`，**漏了 `primaryRoomId`**（店的主房间、广场）。

所以做法改成**键留着、几何清空**：volatile 图写成 `{ mapId, rooms: {} }`。
两处兜底照常命中键；`rooms: {}` 被读档侧本来就忽略；每图约 30 字节。再补上第 3 条的一行。

> 被否：**连键一起去掉 + 改写两处兜底**。触及 3 个文件 4 处逻辑，而且那两处兜底还服务于
> 「老存档的键不一定叫 base」的兼容路径，改它们要回归更多老档用例。留键是零风险的那条路。

### 改动 1 / 2：`Frontend-3D/src/Game/State/world/maps.ts` · `snapshotWorld()`

**改前**

**改后**

```ts

     * volatileRooms 的图（小镇、店铺）只留键不留几何：读档侧本来就按定义
     * 重新生成、从不读存档里那份（restoreWorld / switchMapState 各有一句），
     * 原来照样全写进去，实测 73% 的几何字节是写了没人读的。
     *
     * **键必须留**：loadWorldEntities 和 restoreWorld 都靠"存档里有没有当前
     * 图的键"决定哪张图是活跃图，人在店里存档时键没了会把家里的家具灌进
     * 店铺场景（写细了才发现的坑，见 gpt设计稿/金币与商店/01-期0-清场）。

    maps: Object.fromEntries(
```
