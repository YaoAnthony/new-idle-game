# 存档槽位（本地 A/B/C ＋ 云端 ×1）

2026-09-07 做完。用户当天拍的四条：云槽是**独立的第四个档**（不是某个本地槽的镜像）、
老档按登录态分去向、后端加真的 DELETE、云槽兼登录入口。

## 规格

四个槽地位相同：**都能进、都能下载成文件、都能删（二次确认）、空了都能新建或导入**。
唯一的区别是 `cloud` 跟账号绑定——只有玩云槽时才走云同步；A/B/C 永远纯本地，
不会哪天被自动推上去顶掉云端那份。

卡片上四项：`第 N 天 · 金币` / `上次保存` · `存档大小`。三个槽长一样等于没做多槽。

| 槽 | 键 |
|---|---|
| `a` / `b` / `c` | `world.a` / `world.a.backup` / `world.a.conflict`（b、c 同理） |
| `cloud` | `world` / `world.backup` / `world.conflict`（**沿用老键**） |

云槽不换名字的理由：云同步的三方基准（`lastSyncedRevision`、`pendingWriteId`）记的是
"本机这份主档和云端的关系"，键一改等于告诉引擎本地换了一份档，已登录玩家下次启动
当场吃一个假冲突框。代价是 `world` 这名字看不出它是云槽——用 `keysForSlot` 一个函数
换取，**别处不许再拼键**。

| 文件 | 职责 |

## 五个坑（改这块之前先读）

1. **抢跑读存档 = 读到空。** 搬家正把 `world` 挪去 `world.a` 的半路上，两个键都可能
   是空的。App 的启动检查、继续游戏、云对账全部先 `await whenSlotsReady()`。
2. **云对账必须锁死云槽**（`getSaveRepository("cloud")`）。多槽之后"全局仓库"就是
   "当前活动槽"：玩着 B 槽登录，对账会把云档写进 B，当场顶掉眼前的世界。
3. **存档页列卡之前先 `await whenCloudReady()`。** 换台设备登录时镜像还在下载路上，
   抢先列出来的云槽是"空档位"，玩家点一下新建就在云端那份还好好的情况下开了新档。
4. **删云槽先云后本地。** 云端失败就整件事不做——本地清了云端还在，玩家看到云槽空了、
   下次登录它又回来，比删不掉更难解释。删成功后同步基准必须归零，否则下一次节流推送
   把刚删掉的档原样推回去。
5. **导入云槽要补一次仓库写 + `pushCloudSoon()`。** `transfer` 直接写 IndexedDB，
   不认识仓库，不补这一下就是"导入成功但永远不上云"。

手动（浏览器，每次动这块都要重跑）：

1. 四卡状态：有档 / 空 / 未登录云槽各一张，数字对得上。
2. 删除：点删除 → 翻面问句带槽名 → 确定 → 只有那一个槽的键消失。
3. 空槽新建：点空卡 → 捏脸 → 进屋 → ESC 回标题 → 该槽出现「第 1 天」，别的槽不动。
4. 下载：点下载 → 文件名形如 `异世界小家-A-第12天-20260907.json`。
5. 上传：空槽点上传 → 选一份导出的文件 → 卡片当场刷成那份档。
6. 667×375 横屏：四卡 2×2 不裁切、按钮点得到。

## 已知的取舍与待办

- **游客登录不再自动上传本地档。** 以前登录那一刻本地那份会被当成"本地有档、云端没有"
  推上去；现在它在 A 槽而云槽是空的，不会自动上云——这是"四个槽互相独立"换来的代价。
  手动通道是下载 A → 传进云槽。要不要做一个"复制到云槽"的按钮，等你说。
- **登录态下的云槽卡片没在浏览器里真跑过**（需要在本机后端注册账号）。那一排按钮和
  本地槽是同一段代码，云端那半边由用例覆盖。
- 卡片上没有角色头像小样：那要把捏脸预览离屏渲一张图存进档里，值得单独一期。
- 摘要里的"第几天"用 `createdAtUtc` 的日期和世界日相减，跨时区玩家在日界线附近可能
  差一天。补一个"建档那天的 worldDayId"要 bump 存档版本 + 写迁移，为卡片上一个数字不值得。
