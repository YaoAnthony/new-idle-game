# 13 · 个人剧情线

> 状态：**文档，待执行** · 2026-09-05 · 前置：05 委托、09 新邻居、10 信箱；魔女主线尚未定稿（薇尔那条要等）
>
> 一句话：每位居民一条三幕的线，节拍由好感档和委托驱动，内容零代码；
> 三条线各接一个主线节点——小镇、餐厅、魔女——让主线是"因为邻居"而不是"系统解锁"。

## 玩家看到什么

- **咕噜（史莱姆）·「怕黑」**
  第一幕：搬来第三天，他请你带他去井边（`visit_me` 变体：跟着你走）。第二幕：委托"想要一盏灯"，完成当晚他家窗亮成暖色、门口摆着灯，信箱收到一封歪歪扭扭的信。第三幕（家人档）：他送你"史莱姆做的软凳"（专属家具），并且说出他为什么怕黑——一段长对话，之后闲聊池多一类"关于老家"的段。**接主线**：软凳是第一件"邻居做的家具"，餐厅（期 8）开张时他第一个来吃（决策 23 的客源）。
- **阿茜（狐狸）·「河对岸」**
  第一幕：她总念叨小镇，想开一条近路。第二幕：委托"把这个送到小镇的杂货铺"——**你第一次因此过桥**，到小镇后触发解锁（**接主线决策 22：小镇解锁由这条委托触发**，不再是系统自动开）。第三幕：她从小镇带回一封不是她写的信（`story` 类信件，寄件人空白）——这是魔女线的第一个钩子。
- **薇尔（精灵）·「会发光的土地」**
  第一幕：她说被照料的土地会发光，请你在她家旁边种点什么（农田系统的委托变体 `plant`）。第二幕：`visit_me` 进屋，她教你风铃的事，解锁她的专属家具配方。第三幕：等魔女主线定稿——她是"像人"的第一个角色，文明设定在这里立。**这一幕留空，不写占位内容。**

## 动森原型与取舍

动森没有个人剧情线，只有友好度台阶上的固定事件（送照片、改口头禅）。个人线是我们加的，取的是**动森的节拍感**：不靠任务面板推，靠"今天他主动说了一句不一样的话"。所以三条线的每个节拍都是**居民主动发起**（`favor` 那套走过来），不是任务板上的一行。

## 数据

全部是现有引擎的数据：`storyRules` + `favorDefinitions` + `letterDefinitions` + `dialogues` + `events`。

### 事件（Core/src/Data/events/index.ts）

每位一个 `EventDefinition`，阶段就是幕：

```ts
{ id: "arc_slime", stages: ["settled", "afraid_of_dark", "lamp_lit", "opened_up", "done"] },
{ id: "arc_fox",   stages: ["settled", "wants_shortcut", "delivered_to_town", "brought_letter", "done"] },
{ id: "arc_spirit",stages: ["settled", "asked_to_plant", "taught_chimes", /* 第三幕待定 */] },
```

### 规则（每位 6~10 条，形状统一）

| 触发 | 条件 | 效果 |
|---|---|---|
| `resident_moved_in` subject=slime | — | `set_event_stage(arc_slime, settled)` |
| `day_started` | `event_stage(arc_slime, settled)` + `days_since_moved_in ≥ 3` | `offer_favor(slime_walk_to_well)`（**新效果**：直接提出一件委托，绕过日抽签） |
| `favor_completed` subject=slime_walk_to_well | — | `set_event_stage(afraid_of_dark)` + `add_memory` |
| `affection_reached` subject=slime:familiar | `event_stage(afraid_of_dark)` | `offer_favor(slime_wants_lamp)` |
| `favor_completed` subject=slime_wants_lamp | — | `set_event_stage(lamp_lit)` + `send_letter(slime_thanks_lamp)` + `porch_place(cloud_lamp)` |
| `affection_reached` subject=slime:family | `event_stage(lamp_lit)` | `start_dialogue(slime_opens_up)` + `present_items(signature)` + `set_event_stage(opened_up)` |
| `dialogue_event` subject=slime_arc_done | — | `set_event_stage(done, complete)` |

阿茜第二幕的关键规则：`favor_completed` subject=fox_deliver_town → `unlock_feature("town_travel")`。**现有的小镇解锁规则改成由它触发**（今天是怎么解锁的要查一下再改，标为执行时确认项）。

### 新效果 / 条件

- 效果 `offer_favor: { favorId }`（05 的委托系统提供入口）。
- 委托 kind `escort`（"跟着我走到某处"）：`walk_to` 目标是"玩家身边 1.5 m"的持续跟随 Intent，到达场所结束。给咕噜第一幕用；也给以后"带访客参观"用。
- 委托 kind `plant`：`wants` 换成 `plantedNear: { buildingId, radius, cropId? }`，读农田系统"该建筑附近有没有作物"。

### 闲聊池的"幕后段"

每幕完成后解锁一类闲聊（条件 `event_stage`），每幕 3 段 × 3 幕 × 3 人 = 27 段，让"经历过的事"在日常里留下痕迹。这是 03 的内容量之外的。

## 联机

个人线全部是房主的剧情，做客时剧情系统闭嘴（既有）。房客看到的副作用（门口的灯、门牌、居民位置）走各自切片。**无新同步需求。** 联机验收只补一条：房主推进咕噜第二幕 → 房客那边门口出现灯、窗亮暖色。

## 刻意不做的

- 任务面板 / 追踪标记；失败分支；限时；薇尔第三幕占位内容；居民之间的联动剧情（06 的八卦已经在做"软联动"）。

## 最容易写错的三处

1. **在代码里判"第几幕"。** 全在规则条件里。
2. **小镇解锁改挂委托后，老档已经解锁的玩家**：规则条件加 `feature_unlocked(town_travel) == false`，避免重复触发；已解锁的老档阿茜第二幕直接跳到 `delivered_to_town`（迁移里按 `unlockedFeatureIds` 补阶段）。
3. **`escort` 跟随把玩家挡住。** 跟随目标点在玩家**身后** 1.5 m，让路逻辑照常。
