> **偏离文档的三处**：① 睡觉不是 `interruptible: false` 一条就够——时钟会跳（`/time day`、`/advance`），

> 否则一 `sleep` 人就露在门口；`ResidentAgent.asleep` 把两种睡都算上。③ `resident_stayed_in` 这条事实没记（要"前一天下过雨且他没出门"的跨日判断，放到 15）。
>
> **验收抓到的四个旧 bug**（都是这一期之前就存在的，顺手修了、各有回归测试）：
> `ResidentView` 从来没接过 `hidden`（01 定了动词，模型照画，人"进屋"了身子还杵在门口）；
> 三栋居民房的窗埋在 0.13 厚的墙里，从来没露出来过，且都开在侧墙——固定朝北的镜头看不见，正面门旁加了一扇；
> 关键帧只发**变过的**，夜里满屋子睡着不动，后进来的房客永远等不到"藏着"那一帧（房主看进了屋、房客看站门口）——有人进房就清一次过滤；
> Backend 的 `liftHeight` 只收 0..10，房主站在洼地（地面 -0.45）上开房被拒——改成 ±10。
>
> **验收留到 15 的**：房客 `/npc list` 看不到"出门了"（`residentTrips` 不进切片，房客只看到人没了）；`/spawn` 把两只叠在一格会互相挡死（加了 `/npc <谁> place` 调试口）；
> 读档后"在屋里睡"靠 `sleeping` 标记还原成随机长度的 nap，不是按作息（下次 decide 会纠正，最多几十秒）。
>
> 一句话：性格模板决定起居，读时钟与天气；场所从家具能力和建筑推出来——坐你做的椅子、
> 站在你店门口看货、井边打水、去小镇；傍晚回家，夜里窗户亮灯。
> 全部落成一个技能 `routine` + 一张性格表 + 一张场所表。`ResidentAgent` 一个字不动。

## 玩家看到什么

- 早上他从屋里出来（窗灯灭），伸个懒腰，去门口转转。
- 中午你做的椅子上坐着咕噜；你的店门口站着阿茜看橱窗，货架上有货她站得更久。
- 下雨了，咕噜回屋不出来；薇尔反而出来站在雨里；暴风全员回家。
- 傍晚各自回家，窗户一盏盏亮起来；夜里院子安静，只有窗光。
- 阿茜隔几天去一趟小镇，桥头消失，傍晚从桥头回来。
- 第二天报纸的邻居动态："阿茜昨天去了小镇""昨儿下雨，咕噜一天没出门"。

字段说明：

| 字段 | 含义 |
|---|---|
| `wakeAt` / `sleepAt` | 本地钟点（世界时区）。睡觉 = 回家 + `hide` + `sleep`；醒 = `show` + `gesture("stretch")` |
| `routine[].do` | 五种：`hang_home`（门口转圈，今天的行为）/ `visit`（去场所）/ `roam`（大半径乱走）/ `nap_out`（就地打盹）/ `town`（作息表里不写，由 `townTrip` 生成） |
| `routine[].weather` | 只在这些天气执行；不满足退到 `hang_home` |
| `onRain` | `stay_home` / `go_out_slow`（照常出门，速度 ×0.7）/ `go_out_watch`（站在自家屋檐下 `stand`，不去场所） |
| `onStorm` | 第一版全是 `stay_home`，字段留着 |
| `townTripEveryDays` | 0 = 不去；N = 按 `epochDayOf % N`（沿用水獭班表的做法，确定性） |

时段用**钟点**不用四段：四段太粗，"傍晚回家"和"天黑睡觉"是两个时刻。四段留给 03 的对话条件。

`ResidentDefinition` 加 `personalityId`；`skills` 里加 `routine`。没有 `personalityId` 的居民（以后的访客）`routine` 技能直接返回 null，退回 `wander`。

## 场所表（Core 数据 + 前端解析）

`Core/src/Data/residents/spots.ts` 只声明**哪种东西算哪种场所**，不写任何实例 id：

| 场所 `spot` | 来源 | 到了做什么（动词序列） | 一位居民占多久 |
|---|---|---|---|
| `seat` | 带 `Sitting` 能力、摆在**室外**的家具（`isIndoors` 为假） | `walk_to` 座旁 → `sit` | 到作息段结束，或被打断 |
| `water` | 井（建筑 `well`）、带 `WaterSource` 能力的室外家具 | `walk_to` → `stand(6s, flavor: "drawing")` → 原地 `stand(随机 20~60s)` 再来一次 | 段内循环 |
| `shop` | 建筑 `furniture_shop` 的门口一步 | `walk_to` → `stand(flavor: "browsing", facing: 店)`；**货架有货 → 时长 ×2** | 段内 |
| `consign` | 带 `Consign` 能力的家具 | `walk_to` → `stand(flavor: "browsing")` | 段内 |
| `neighbor_door` | 别的居民房门口（`residence` 查表） | `walk_to` → `stand` | 段内。真正的串门留给 06 |
| `home` | 自己的房子门口（`BuildingLevel.doorstep`，见自查） | `walk_to` 门口 → `hide`（进屋） | — |
| `town` | 本图的访客入口（`MapDefinition.visitorEntry`，没填退到出入口落点） | `walk_to` 桥头 → 系统层 `removeResident`；`backAt` 到点 `spawnResidentAt` 桥头 → `walk_to` 家 | — |

前端 `Systems/residents/spots.ts` 负责把表翻成当前世界里的坐标列表：扫家具（按能力 + 室外）、扫建筑（按型号）。**每次 `decide` 现算**，不缓存——家具会被搬走。

**一个场所同时只容一位**：`spots.ts` 维护运行时占用表（`Map<spotKey, residentId>`），不进存档。两位都想坐同一把椅子，后到的重新挑。挑不到目标场所 → 退回 `hang_home`。

> **12 之后的修正**：上表"到了做什么"那一列在 12 落地后**从场所表移走**——场所表只管"怎么认出这种场所"，
> 到达后做什么由活动表按场所 + 爱好 + 天气抽。02 单独实现时可以先按上表写死序列，12 来了再抽出去；
> 两期合并实现就直接按 12 的形状。

## `routine` 技能

`Frontend-3D/src/Game/State/skills/routine.ts`，优先级 40（在 `needs` 之下、`approach` 之上）。

`decide(ctx)`：

1. 没有 `personalityId` → null。
2. 当前钟点在 `sleepAt`~`wakeAt` → Intent `[walk_to 家门口, hide, sleep(到 wakeAt)]`，`interruptible: false`（睡着了不该被 approach 叫起来；`needs` 优先级更高但夜里代谢放缓，一般不会触发）。
3. 天气：`storm` 或（`rain` 且 `onRain === stay_home`）→ 同上但 `sleep` 换 `stand`（在屋里待着，醒着）。`rain` 且 `go_out_watch` → `[walk_to 屋檐, stand(facing: 院子)]`。`go_out_slow` → 继续往下走，Intent 带 `speedScale: personality.rainSpeedScale`（`walk_to` 参数，初值 0.7）。
4. 小镇日且钟点在 `leaveAt`~`backAt` → 若在场：`[walk_to 桥头]` + `onArrive: leaveForTown`（系统函数，移除并记 `awayUntil`）。不在场的由系统层在 `backAt` 放回（见下）。
5. 查作息表当前段：
   - `hang_home` → null（让 `wander` 接手，它的圆心就是家门口）
   - `visit` → 挑最近的空场所 → 场所表对应的动词序列；挑不到 → null
   - `roam` → `[walk_to 随机点(半径 personality.roamRadius)]`（初值 12，比 `wander` 的 3~4 米大得多）
   - `nap_out` → `[stand(2s), sleep(personality.napSeconds)]`，天气不满足 → null
6. 连续两次算出同一目标 → 返回同一个 Intent 引用，身体据此不重启。

`decide` 不改任何状态；占座是 `onArrive` 里调 `spots.claim`，`onInterrupted` 调 `spots.release`。
`onArrive` 同时发剧情信号 `resident_used_spot`（subject = 场所种类）——04 的"他坐了你做的椅子 +1 好感"和报纸的"咕噜今天在你店门口站了半天"都接它。

## 去小镇（系统层，不是技能）

"整只从运行时移除再放回"和水獭来去是同一件事，所以放系统层 `Systems/residents/townTrips.ts`，`routine` 只负责把他走到桥头。

- `leaveForTown(residentId, backAt)`：`removeResident`，记到 `WorldSave.residentTrips[residentId] = { backAtLocalTime, dayId }`（**唯一进存档的新字段**：不记的话关掉游戏他就永远消失了）。
- `startTownTrips()`：订阅时钟，每分钟检查；到 `backAt` 或过了那一天 → `spawnResidentAt(桥头, home=门口)`，清字段，`dayRecord` 记 `resident_town_trip`。
- 读档时过了 `backAt` 的直接放回家门口。
- 玩家自己在小镇时**看不到他**（小镇地图不放居民，第一版）。

## 回家与窗灯（纯表现，用户定）

> **08 之后的修正**：有室内（房子 l2）的居民，"回家"不再是 `hide`，而是**真的走进室内房间**
> （`roomId` 切到室内，院子图里不渲染——`entities.ts` 的分图装卸本来就按 `roomId` 归属）。
> `hide` 只在 l1 没室内时用。"在家"的判定统一成一个纯函数 `isAtHome(resident)`：l1 看 hidden + 门口半径，l2 看 roomId。
> 窗灯、门锁（08）、来访条件（07）都读它，不各写各的。

- 在家 = `hidden` 且位置在自家门口半径 2 米内。`ResidentView` 在 `resident_changed` 上算一次 `residentsAtHome: Set<buildingInstanceId>`，`BuildingsView` 读它给窗户网格换发光材质（`emissive` + 一枚点光，夜间才开——白天亮着看不见也费）。
- **不进存档、不进 `BuildingPlacement.state`、不发 `building_state_changed`**。读档后第一帧算出来就对了。
- 居民房的窗户网格要能被找到：三个 `Buildings/*House.ts` 给窗户 mesh 打 `userData.window = true`。这是本期唯一碰建模文件的地方，不改几何。

## 读档与离线

- **不补过程只补结果**：读档时 `routine` 第一次 `decide` 就会按当前钟点给出该在的地方，身体照常走过去。要"瞬间在位"的话在 `restoreResidents` 后调一次 `snapToRoutine()`：直接 `debugPlace` 到目标场所。**第一版不做瞬移**，走过去更像活人，代价是读档后 10 秒内他可能在路上。
- `dayRecord` 每天推事实：`resident_town_trip`（谁去了小镇）、`resident_stayed_in`（谁因为下雨一天没出门——在 `day_started` 时由前一天的 `onRain` 决定）。报纸的 `neighborKinds` 加这两个 kind。

## 联机

作息、场所、去小镇的决策**全在房主**（01 的规则 1）。房客看到的一切来自三条通道：

| 房主发生了什么 | 房客怎么知道 |
|---|---|
| 居民换作息段、去坐椅子、回家 | `resident_intent` op，木偶用同一套动词走过去 |
| 走路途中的偏差 | `sync:residents` 关键帧纠偏 |
| 去小镇（移除）、从小镇回来（登场）、居民到来 | `pets` 刷新切片对账；`residentTrips` 是房主存档字段，房客不需要 |
| 夜里窗亮 | **两端各自算**：木偶也有 `hidden` 和位置，"在家"的判定是同一个纯函数，结果一致。不发任何网络消息 |
| 占座 | 房主的运行时表；房客不判占座，木偶被告知坐哪就坐哪 |

联机验收（接在 01 那六条之后）：

7. 房主 `/time dusk` → 两边史莱姆都走回家、两边窗户都亮（截图对照）。房客不会因为本地时钟不同而"自己决定回家"——房客的时钟本来就是房主刷过来的（`clock` 切片）。
8. 房主 `/npc fox town` → 房客那边阿茜走到桥头消失；房主推进到 `backAt` → 房客那边桥头出现并走回家。
9. 房主 `/weather rain` → 房客那边咕噜回屋（Intent 复制），薇尔站到屋檐下。
10. 房客在做客期间 `/npc spots` → 列出的是房主世界解析出的场所（家具是房主的），但**不显示占用**（占用表只在房主）。

## 存档与契约影响

- `WorldSave.residentTrips?: Record<ResidentId, { backAtLocalTime: string; dayId: string }>`——可选字段，老档读出来 undefined = 没人出门。**版本号 +1、迁移是空迁移。** 它是房主端的自治状态，**不进刷新切片**（房客靠 `pets` 切片看到人消失 / 出现即可），所以 `net.ts` 和 Backend 白名单这次不动。
- `BuildingLevel.doorstep` 与 `MapDefinition.visitorEntry` 是内容字段，不进存档。
- 其余全部是运行时状态（占座表、在家集合）。

## 最容易写错的五处

1. **场所缓存**。家具会被搬走、店会升级。每次 `decide` 现算，宁可慢。
2. **占座不释放**。被打断、被指令抢走、去小镇被移除，三条路都要 `release`。`onInterrupted` 和 `removeResident` 都得调。
3. **睡觉 Intent 不可打断，但指令要能打断。** 01 定的：`command` 无视 `interruptible`。
4. **钟点比较跨午夜。** `sleepAt 22:00`~`wakeAt 06:00` 跨天，写成"分钟数"比较时要处理 wrap。抄水獭班表用的 `epochDayOf` 思路。
5. **窗灯白天也亮**。点光只在 `day_phase` 为 Dusk / Night 时开，否则一栋房子白天顶着一盏灯。
