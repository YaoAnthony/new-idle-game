# 10 · 信箱

> 状态：**文档，待执行** · 2026-09-05 · 前置：04 好感、09 出门
>
> 一句话：门口一只信箱，居民会写信给你、附一样东西；出门的居民寄明信片；你也能给他写信。
> 离线期间寄到的信回来一次看完。信是唠叨的另一条渠道，也是剧情送"物"的一条渠道。

## 玩家看到什么

- 早上出门，主屋门边的信箱旗子立着（有新信）。按 F 打开信箱面板：一叠信封，点开一封是薇尔的信纸，字迹、称呼（`{you}`）、落款，底下夹着一样东西的图标，点"收下"进背包。
- 咕噜回老家的第二天收到明信片，画着"老家"的插图，一行字。
- 面板里有"写信"：选收信人（在场居民）、从几句固定模板里挑一句（不能自由输入）、可以夹一样东西 → 次日他见你时提起这封信，夹的东西按送礼规则算。
- 离线七天回来，信箱里三封，不多不少（每人每几天最多一封，上限由数据定）。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 村民寄信，好感高的附礼物 | 取 |
| 你寄信（自由输入，村民按关键词回） | 改成**模板句**——不做自由输入解析，也避开 UGC 审查 |
| 搬走告别信 | 出门明信片 |
| 信在信箱里堆积，满了新信丢失 | 信箱上限 20，**满了不再寄**（不丢） |
| 母亲的信、狸克的通知 | 剧情信：`send_letter` 剧情效果，主线用得上（魔女来信） |

```ts
  boxCapacity: 20,
  /** 每位居民每 N 天最多一封自发信；保底池 */

  requires: [{ kind: "affection_at_least", stage: "familiar_resident" }],

```

- 三类：`resident`（居民自发，条件 + 权重抽）、`postcard`（09 出门时系统发）、`story`（剧情效果 `send_letter: { letterId, attach? }` 发，**主线的"魔女来信"就走这个**——没有对应的实体角色也能寄）。
- 信的**后果**（附件入包、好感 +、记忆）由收信 / 拆信发信号 `letter_opened`（subject = letterId）→ 规则接。信箱系统本身只管收、存、开。

### 存档

- `WorldSave.mailbox: { letters: Array<{ id: string; letterId: string; fromResidentId?: string; receivedDayId: string; opened: boolean; attach?: { itemId; quantity }; playerText?: { templateKey; toResidentId } }> }`（**新字段**）。
- 信**属于世界还是人**？收信人是"这个家"（房主），寄件人是居民（世界的）。放 `WorldSave`：联机时房客能看信箱面板但**不能收附件**（附件是房主的）。

### 你写的信

- 面板"写信" → 收信人 + 模板句 + 可选附件（从背包挑一件）→ 写进 `mailbox.outbox`（同一字段下）。
- 次日 `day_started`：房主端处理 outbox：附件走 `offerGift` 的委托 / 口味判定（复用 05、现有送礼），产生 `gift_*` 信号；居民下次见面对话池多一段 `replied_letter`（条件 `letter_replied_pending`），说完清掉。**不做自动回信**——他当面回应，比一封模板回信像活人。

## UI

- 信箱：主屋门边一件**固定布景**（不是家具，不可搬），旗子 = 有未读。按 F 走 `interact_target` 加一种 `mailbox`。
- 面板 `MailboxPanel`：左边信封列表（未读加粗），右边信纸。信纸用报纸那套做旧风格的**信纸变体**（同一族字体、纹理），明信片是横版带插图。手机横屏 667×375 单列切换，不做双栏。
- 附件"收下"按钮复用 RewardPanel 的领取语义（走 `presentItems`，一封一次）。

## 联机

- 信箱是世界的，走 `mailbox` 切片（**`WORLD_REFRESH_KEYS` 加一项**）。房客能打开面板读信（好感、称呼按房客渲染 `{you}` → generic），**"收下"按钮不显示**，写信入口不显示（做客中）。
- 联机验收：房主收到一封带附件的信 → 房客打开信箱看到同一封、无"收下"；房主收下 → 房客那边附件图标消失。

| 指令 | 干什么 |

## 存档与契约

`WorldSave.mailbox`（新）。**版本号 +1、空迁移、切片 + 白名单 + 协议 +1。** 信箱布景要建模（**先问参考图**），插图两张（明信片、魔女信）走 `prompt/` 的出图流程。

## 刻意不做的

- 自由输入；自动回信；信箱满了丢信；给非居民（商人）写信；信件语音；离线补寄超过上限。

## 最容易写错的四处

1. **附件在收信时就入包。** 拆信 → "收下" 才入包，走领取语义，房客看不见按钮。
2. **outbox 附件直接 `removeItem`。** 走 `offerGift`，让口味 / 委托判定发生，居民才"知道"你送了。
3. **明信片在出门当天就到。** 第二天。
4. **信箱容量满了继续寄。** 不寄，池 miss 不累加（不然回来一开箱 20 封同一天的）。

## 验收

- Core：信件抽签确定性、`once`、容量；模板句表。
- Frontend `mailbox.test`：自发信按池到达；出门明信片次日到；剧情 `send_letter`；拆信发信号 → 规则给好感；outbox 次日走送礼判定并触发 `replied_letter` 段；满箱不寄；离线 7 天最多 N 封。
- 浏览器：面板截图（信、明信片、写信）；旗子状态。
- 联机双端：见上。
