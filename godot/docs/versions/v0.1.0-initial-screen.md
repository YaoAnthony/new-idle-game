## Goal

让 Godot Project 启动后稳定显示一个可交互的最小 Main Menu Shell，为未来 New Game Flow、Continue Flow、Settings、UI Asset 和 Scene Transition 提供可替换的 Presentation Shell。

## Player-visible Outcome

Player 启动游戏后看到一个非空的 Initial Screen。Screen 使用 `godot/assets/background/home/home.png` 作为 Home Background，显示艺术字风格 Game Title：`一起做任务吧！`，并提供四个基础 Menu Button：`新建游戏`、`继续游戏`、`设置`、`退出游戏`。

本 Version 的 `Initial Screen` 是最小 `Main Menu Shell`，但不是完整 Gameplay Entry。

## Why This Version

此 Version 只验证最基础的 Delivery Path 和 Menu Interaction：

- Godot Project 可以启动。
- Main Scene 配置正确。
- UI Root 能覆盖 Viewport 并响应 Resize。
- Home Background Asset 可以被加载和铺满 Viewport。
- Placeholder UI 可在未来替换为正式 Asset，而不要求重写 App Structure。
- Button Flow、Modal Back Flow 和 Quit Flow 可被验证。
- Agent 能运行 Project、读取 Error，并提供可验证 Evidence。

它不验证 Core Loop 或 top-down Gameplay。

## User Flow

1. Player 启动 Godot Build 或运行 Project。
2. App 加载 Main Scene。
3. Initial Screen 先执行一次短暂 `fade_in`，随后显示 Home Background、Game Title 和四个 Button。
4. Player 点击 `设置` 后，打开一个空 Settings Panel；Panel 中只有返回入口，可以退回 Main Menu。
5. Player 点击 `继续游戏` 后，打开一个空 Continue Panel；Panel 中只有返回入口，可以退回 Main Menu。此 Version 不读取 Save。
6. Player 点击 `新建游戏` 后，打开一个空 New Game Placeholder Panel；Panel 中只有返回入口，可以退回 Main Menu。此 Version 不进入 Gameplay。
7. Player 点击 `退出游戏` 后，请求关闭 Project；在 Editor/Debug 环境下允许表现为正常退出请求。
8. Player 仍可以通过 OS Window Close 正常退出。

## In Scope

- 一个作为 Project Entry 的 Main Scene。
- 一个铺满可用 Viewport 的 Initial Screen。
- 使用 `godot/assets/background/home/home.png` 的 Home Background。
- 一个艺术字风格 Game Title：`一起做任务吧！`。
- Title 和 Menu UI 的短暂 `fade_in` 入场动画。
- 四个 Menu Button：`新建游戏`、`继续游戏`、`设置`、`退出游戏`。
- 一个集中 Theme Token 文件：`godot/ui/style/style.gd`，由它提供 Color、Title、Button、Spacing 和 Modal token。
- Button 需要至少实现 normal、hover、pressed 和 focus-visible 状态；状态变化不得造成 Layout shift。
- `设置` 打开空 Settings Panel，并可返回 Main Menu。
- `继续游戏` 打开空 Continue Panel，并可返回 Main Menu；不读取 Save。
- `新建游戏` 打开空 New Game Placeholder Panel，并可返回 Main Menu；不进入 Gameplay。
- `退出游戏` 触发 Godot quit request。
- 使用 Godot Built-in Control Node、Theme/Label Settings 和 AnimationPlayer/Tween 创建可替换 Placeholder Layout。
- Layout 构图为居中的纵向主菜单：Title 在上，Button Group 在下，整体在 Viewport 中央略偏上；不能把按钮散落在屏幕四角。
- 四个 Button 必须 group 到同一个父级 `VBoxContainer`，作为 Menu Button Group。
- Menu Button Group 和其外层 Layout 必须使用 Container/Anchor 加 `size_flags_horizontal/vertical` 的 Fill/Expand 组合完成自适应。
- Menu Button Group 的竖向间距通过 `GameStyle.BUTTON_SEPARATION` 写入 `VBoxContainer.theme_override_constants/separation`，不在每个 Button 上单独堆 margin。
- Layout 使用 Container/Anchor，而不是依赖单一 Resolution 的 Absolute Position。
- Initial Screen 在 `1280x720` 和 `960x540` Test Viewport 下保持非空、Title、Button 和 Panel 可见且无重叠。
- Project 启动、Scene Load 和 Window Close 时无 Error。

## UI 和 Asset Contract

本 Version 使用 Placeholder UI，只需要表达以下 Slot：

```text
InitialScreen
├── Background Slot
├── Title Slot
├── Menu Button Group：VBoxContainer
│   ├── New Game Button
│   ├── Continue Button
│   ├── Settings Button
│   └── Quit Button
└── Modal Slot
    ├── New Game Placeholder Panel
    ├── Continue Placeholder Panel
    └── Settings Panel
```

具体 Node Name 由 Implementation 决定，不作为 Durable Contract。Structure 必须让 Future Asset Version 能替换 Background、Logo/Title Font 和 Theme，而不改变 App Entry 或创建第二套 Initial Screen。

要求：

- Initial Screen Scene path 必须是 `res://ui/menus/initial_screen.tscn`，供 Automated Layout Test 加载。
- 测试需要识别的 UI Control 必须设置 metadata key `ui_test_role`，role 值包括：`initial_screen_root`、`home_background`、`game_title`、`menu_button_group`、`new_game_button`、`continue_button`、`settings_button`、`quit_button` 和 `modal_layer`。
- `ui_test_role` 是 Test Contract，不是 Player-facing ID；不得用它驱动 gameplay rule 或 persistence。
- Background 使用已有 Asset：`godot/assets/background/home/home.png`。
- Title 显示为 `一起做任务吧！`，使用 Godot 内置 Label/Theme 能力做“手写木牌/和纸标题”方向的艺术字风格；不得依赖未提供的 Custom Font。
- Title 必须使用 `GameStyle.TITLE_FONT_SIZE`、`GameStyle.TITLE_OUTLINE_SIZE` 和 `GameStyle.TITLE_SHADOW_OFFSET`，并通过 outline/shadow/颜色层次形成标题感；不得照抄任何现有游戏 Logo、字体造型或标题排版。
- Theme 走日系柔和自然方向，v0.1 使用 `GameStyle.PRIMARY` 作为主按钮色，`GameStyle.SECONDARY` 作为 hover/focus 强调色，`GameStyle.SURFACE` 作为面板/文字承托色，`GameStyle.TEXT` 作为主要文字色。
- 具体 Color value 只能存在于 `godot/ui/style/style.gd`。Theme Resource、Scene、Script 和 Button Style 只能引用或派生 `GameStyle` token，不得直接写 Color literal。
- Button 风格为“柔和纸质菜单牌”：小圆角、稳定边框、清晰文字、轻微 hover 强调；不能使用拟物木纹、外部图片九宫格或来自其他游戏的 UI Asset。
- Button min size、corner radius、border width 和 content margin 必须来自 `GameStyle.BUTTON_MIN_SIZE`、`GameStyle.BUTTON_CORNER_RADIUS`、`GameStyle.BUTTON_BORDER_WIDTH`、`GameStyle.BUTTON_CONTENT_MARGIN_X` 和 `GameStyle.BUTTON_CONTENT_MARGIN_Y`。
- Menu Button Group 必须是 `VBoxContainer`，四个 Button 作为它的直接或语义直接子节点，顺序为：`新建游戏`、`继续游戏`、`设置`、`退出游戏`。
- `VBoxContainer` 的 `theme_override_constants/separation` 必须来自 `GameStyle.BUTTON_SEPARATION`，作为本 Version 的单一按钮间距来源。
- Menu Button Group 必须随 Viewport 自适应，并受 `GameStyle.MENU_MAX_WIDTH` 约束；Title 和 Button Group 的间距来自 `GameStyle.MENU_TITLE_GAP`。不得通过固定 x/y position 摆放整组 Button。
- Button 文案使用中文 Display Text，但实现时必须集中在可替换位置，例如 scene-local exported text、Localization source 或 Theme/Scene resource，不得散落到 gameplay script 条件里。
- Button normal 状态使用 `GameStyle.PRIMARY`；hover 状态必须有可见变化，优先使用 `GameStyle.SECONDARY` 的边框、底色或轻微明度变化；pressed 状态必须比 hover 更深或更收敛；focus-visible 状态必须有清晰 outline，不能只依赖颜色细微变化。
- Button hover、pressed 和 focus 状态不得改变 Button 的最小尺寸、VBox 间距或整体位置。
- Disabled 样式可准备在 Theme 中，但本 Version 不要求出现 disabled button。
- Modal Panel 视觉走 `GameStyle.SURFACE` 承托、`GameStyle.TEXT` 文字、`GameStyle.SECONDARY` 强调边框，并使用 `GameStyle.MODAL_MIN_SIZE` 控制最小尺寸。
- `fade_in` 使用可配置 Duration；不得把动画时长写死在多个位置。
- 不新增 External Asset。
- Button 只实现本 Version 声明的 Placeholder Panel 和 Quit 行为。

## Implementation Boundary

- 将 `godot/app/main.tscn` 实现为 Project Main Scene 或稳定的 Composition Root。
- 在 `godot/ui/menus/` 中创建唯一的 Initial Screen/Main Menu Presentation Scene，并组合进 Main Scene。
- 在 `godot/ui/style/style.gd` 中维护本 Version 需要的 Theme Token；新增颜色或 spacing 前必须先扩展此文件，而不是在 UI 里直接写值。
- 在 `godot/project.godot` 中设置 Main Scene。
- Button Layout 必须优先用 `VBoxContainer`、size flags 和 theme override 完成；只有 Background、fullscreen overlay 或 Modal 居中这类 Viewport 级布局可以使用 Anchor preset。
- Button Theme 必须优先通过 Theme/StyleBox/Theme Override 管理 normal、hover、pressed 和 focus-visible 状态，并引用 `GameStyle` token；不在 `_process` 或 Button signal handler 中临时改颜色。
- Title、Button、Modal 和 Spacing 的 visual constants 必须来自 `GameStyle`；Scene 可以引用 token，但不能重新定义一套本地 magic numbers。
- 允许为 Button Flow、Panel Back、Quit 和 fade-in 添加最小 Presentation Script；Script 不得拥有 gameplay rules、save rules 或 external service calls。
- UI Text、动画时长和 Asset Reference 必须集中在 Scene/Resource 层，避免在多个 Script 中 hardcode。
- 不修改 Backend、Frontend、Contracts、Infrastructure 或无关 Feature。
- 不为 Future Feature 创建 Manager、Router、State Machine 或 Stub API。

## Risks 和 Rollback

- 提前扩展为 Gameplay Entry：通过 Out of Scope 和 Eval Assertion 防止。
- Absolute Position 导致 Resize Failure：通过 Container/Anchor 和双 Viewport Eval 防止。
- Background Asset 缺失导致空屏：通过 Asset Existence Check 和 Manual Visual Evidence 防止。
- Placeholder Panel 被误认为真实 Save/Settings：通过 Panel 文案和 Out of Scope 防止。
- Hover 或 focus 改变尺寸导致 Layout shift：通过 Theme 状态尺寸一致性和 Resize Eval 防止。
- 主题色散落或后续难以调整：通过 `godot/ui/style/style.gd` 作为唯一 Color Token Owner 防止。
- 艺术字或 Button 风格过度借鉴商业游戏：通过抽象“手写木牌/和纸标题”和“纸质菜单牌”方向、防止复制具体 Logo/UI Asset。
- Rollback：恢复 Main Scene 设置并移除此 Version 新增的 Initial Screen Scene，不影响其他 Feature。
