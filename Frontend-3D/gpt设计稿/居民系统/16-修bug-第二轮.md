## 多出来的四件事

### 1. 30 分钟 soak（照 `/soak-test` 的协议）

一个标签页开着不动 30 分钟，三位居民 + 石傀儡 + 水獭在场，时钟用 `/time` 每 5 分钟拨一段，天气每 10 分钟换一种。

| 观察 | 通过标准 |
|---|---|
| 内存 | `performance.memory` 30 分钟增长 < 20 MB；`ResidentView.views` 数量恒等于在场活物数（不泄漏视图） |
| 占座表 | 结束时 `/npc spots` 的占用数 == 正在 `sit` 的人数（不泄漏占座） |
| 关键帧 | 房主端出站字节稳定，不随时间涨（不累积） |
| 卡死 | 没有一只 30 分钟内位置和动词都不变（`/npc <谁> where` 抽查），除了在家睡觉的 |
| 控制台 | 零 error，warn 逐条解释 |

### 2. 性能实测（对 15 的基线）

在 iPhone SE 尺寸的浏览器窗口 + CPU 4× 降速（DevTools）下量：

| 项 | 15 基线 | 通过 |
|---|---|---|
| tick + 决策 | 记录值 | ≤ 基线 × 1.3（08~14 加了室内、活动、来访） |
| 首帧到可操作 | 记录值 | 不劣于 00 之前 |
| 进居民室内换图 | — | < 800 ms（对齐进店铺） |

超了先查场所解析（02 现算）和活动抽取（12），这两处是最可能的热点；缓存方案要写 ADR 再动。

### 3. 内容审计（不只是"键存在"）

| 审计 | 工具 | 通过 |
|---|---|---|
| 每位居民闲聊池条件覆盖：四个时段 × 六种天气 × 三档心情，**每个格子至少一段能抽到** | 脚本枚举条件组合调 `pickChat` | 空格子 = P1 |
| 委托、来信、访客的 `requires` 全部可达（不存在永远满足不了的条件） | `storyAudit` 扩展 | 不可达 = P1 |
| `{you}` / `{cp}` / `{name:x}` 模板全部渲染，无裸模板 | i18n 正则 | 裸模板 = P1 |
| 每幕剧情（13）从新档能在 N 天内到达 | 用 `/day` 推进的脚本 | 到不了 = P0 |
| 台词重复率：同一位居民连续 7 天按 F 各 3 次，重复段 < 30% | 脚本 | 超 = P2 |

### 4. 联机全链压测

五人房（上限）。房主 + 4 房客同时在场 10 分钟，房主跑一遍作息、委托、来访、出门、寄信。

| 观察 | 通过 |
|---|---|
| 位置一致 | 任一时刻四个房客与房主的每只活物位置差 < 0.5 m（脚本每秒采样 `/npc where`） |
| 生灭一致 | 出门 / 回来 / 访客 在四端 5 秒内一致 |
| 切片体积 | 单次 `world:refresh` < `NET_LIMITS.maxWorldBytes` 的 30%（六片新切片加起来） |
| 房客越权 | 四端各试一遍 `/npc do` / 送礼 / 邀请 / 收信 → 全部被拒，房主端零变化 |
| 晚加入 | 第 8 分钟第 5 人进场 → 30 秒内位置差 < 0.5 m |
