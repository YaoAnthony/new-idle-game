# 08 · 家：居民房的室内

> 状态：**08 已完成（室内 + 进出 + 槽位；建模待参考图）** · 2026-09-06 · 本提交 · 前置：07 门口展示、05 `visit_me` 委托、02 回家
>
> 一句话：推开他的门是一间真的屋子，风格是他的，你送的每一件东西都摆在里面。
> 他在家时你能进去找他；`visit_me` 委托在屋里完成。**这是整个系列建模量最大的一期，先问参考图。**

## 玩家看到什么

- 晚上咕噜回家后，走到他门口按 F，门开了：一间 5×5 的小屋，地上铺着软垫，角落有他睡觉的凹坑，你送的云朵灯挂在墙上亮着，小凳子在窗边。咕噜在凹坑里，看见你进来坐起来："哦……你来啦。"按 F 是屋内专用的闲聊段。
- 阿茜的屋子里满是她从小镇带回来的杂物；薇尔的屋子挂着风铃，窗开着。
- 送第三件家具时屋里没有空槽位，他会说"放不下了，我把旧的那个收进箱子里"——最早的那件进他屋里的储物箱（能打开看，不能拿走）。
- 他不在家时门锁着，按 F："咕噜不在家。"
- 房子升到 l2 才有室内；l1 是现在的小屋壳子，门不能开。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 每位村民独特的室内（壁纸、地板、家具套） | 取：每位一份室内定义（房间几何 + 固定陈设 + 槽位） |
| 你送的家具会摆进去，替换他原来的 | 取：槽位队列，满了最早的进箱 |
| 你送的衣服他会穿 | 无服装 |
| 白天随时能进（他在不在都行） | 改：**他在家才能进**——不在家进空屋子，我们的室内没那么多可看的；而且"敲门没人"是活着的证据 |
| 他在屋里坐、睡、做事 | 取：室内是他的一块场所，02 的场所解析加 `scope: "indoor_of:<instanceId>"` |
| 你去他家他会"招待"（送东西、聊天） | `visit_me` 委托在屋里完成（05），平时进屋是屋内闲聊 |

## 数据

### 室内定义（Frontend-3D/src/Buildings/interiors/<house>.ts，一栋一文件）

复用主屋的房间系统：室内是一个 `RoomSave`（几何、地板、墙）+ 一扇门 + 一个 `MapDefinition`（像六家店铺那样是"店铺内部"那一族：**几何是内容不是状态，每次进图重新生成**，存档里只存槽位）。

```ts
export const slimeHouseInterior: ResidentInteriorDefinition = {
  buildingId: "slime_house",
  minLevelId: "l2",
  room: { width: 5, height: 5, styleId: "slime_soft" },        // roomStyles 里加一种
  fixed: [                                                      // 固定陈设：他自己的东西，不能动
    { furnitureId: "slime_nest", cell: { x: 0, y: 3 }, facing: "east" },
    { furnitureId: "slime_storage_box", cell: { x: 4, y: 4 }, facing: "north" },
  ],
  giftSlots: [                                                  // 你送的东西摆哪
    { cell: { x: 2, y: 0 }, facing: "south", accepts: ["wall", "floor"] },
    { cell: { x: 4, y: 1 }, facing: "west", accepts: ["floor"] },
    { cell: { x: 1, y: 4 }, facing: "north", accepts: ["floor", "light"] },
  ],
  door: { wall: "south", offset: 2 },
  spawn: { x: 2, y: 4, heading: 0 },                             // 你进门站哪
  homeSpot: { cell: { x: 0, y: 3 } },                            // 他在家时待哪（睡觉凹坑）
};
```

- 三栋各一份 + 三种 `roomStyle` + 三件固定陈设家具（凹坑 / 杂物堆 / 风铃）要建模，**先问参考图**。
- `giftSlots.accepts` 按家具的 `placement` 类别过滤，送一盏灯优先进 `light` 槽。

### 存档

- `WorldSave.interiors: Record<buildingInstanceId, { gifts: Array<{ itemId } | null>; boxed: ItemId[] }>`（**新字段**）。写它的只有剧情效果 `interior_place: { residentId, itemId }`——和 07 的 `porch_place` 是同一条规则链：**有室内就进屋，没有就摆门口**，效果执行时判 `minLevelId`。
- 门口展示位在 l2 之后仍保留（门口 2 件 + 屋内 3 件 = 5 件可见）。

### 进出

- 居民房的门是新的 `DoorDefinition`（`doors` 注册表加一条 `resident_door`，锁定态文案"X 不在家"）。开门条件：`residentAtHome(instanceId)`（02 的"在家"判定）。
- 进门 = `travelTo(interiorMapId, landing)`，和进店铺同一条链；出门回院子落在门外一步。
- **他也在图里**：进入室内地图时，把那位居民从院子"搬"进室内（运行时 `roomId` 切到室内房间，位置 `homeSpot`），出来时搬回门口。这是 `entities.ts` 分图装卸已经在做的事（按 `roomId` 归属），只需要 02 的"回家 = hide"改成"回家 = 移到室内房间 + 在院子图里不渲染"。**这一条反过来简化了 02**：`hide` 不再是假装消失，而是他真的在另一间屋子里。

### 屋内行为

- 室内是他的场所（`scope: indoor_of`），作息表的 `hang_home` 在有室内时 = 在屋里 `sit`（凹坑）/ 小范围 `wander`。
- 屋内闲聊池：03 的 talk 文件加 `homeChats`（条件 `player_in_my_home`），5 段 / 人。
- 你进屋他转身面向你（03 的规矩）；你出去他回 `homeSpot`。

## 联机

- 室内地图和店铺内部一样是内容，房客进去时几何本地生成；槽位走 `interiors` 刷新切片（**`WORLD_REFRESH_KEYS` 加 `interiors`**）。
- 房客能进居民房（门的锁定态读同步过来的居民位置），屋里的居民是木偶；房主不在这张图时房客照样能看（居民位置来自切片）。
- 联机验收：房主送灯进屋 → 房客进屋看到灯在同一槽位；房主 `/npc slime do walk_to` 让他离家 → 房客那边门锁上"不在家"。

## 指令

| 指令 | 干什么 |
|---|---|
| `/npc <谁> interior place <itemId>` / `clear` | 摆 / 清槽位 |
| `/npc <谁> home` | （02 已有）让他回家 |
| `/interior <buildingId>` | 直接进那间室内（调布置用，不要求他在家） |

## 存档与契约

`WorldSave.interiors`（新）；三张 `MapDefinition`（内容）；一条 `DoorDefinition`。**版本号 +1、空迁移、切片 + 白名单 + 协议 +1。** 图纸 `blueprint_*_house_l2` 三件（05 的委托奖励之一就是它）。

## 刻意不做的

- 他不在家也能进；你能挪他屋里的东西；室内升级到 l3；两位居民互相进屋（06 的串门仍在门口）；室内的天气 / 昼夜光照差异（复用店铺内部的处理）。

## 最容易写错的五处

1. **室内几何存进存档**（主屋那条"存结果不存配方"是给玩家能改的地方定的，居民室内玩家改不了）。照店铺：内容，每次生成。
2. **他在室内和院子里同时存在一份**。`roomId` 归属唯一，装卸靠 `entities.ts`。
3. **门的锁定态用 `hidden` 判**。用"在家"判定（位置 + roomId），因为 `hide` 这期退役了。
4. **送礼进屋没判 `accepts`**，灯摆在地上、地毯挂墙上。
5. **l1 的房子也开门**。`minLevelId` 挡住，文案"门还没装好"。

## 验收

- Core：三份室内定义槽位不重叠、不压固定陈设、门在墙上、`spawn` 可走；`accepts` 过滤。
- Frontend `interior.test`：送礼 → 有室内进屋 / 无室内进门口；满了最早进箱；进门要求在家；进出时居民 `roomId` 切换且院子图里不渲染；l1 不开门。
- 浏览器：`/npc slime home` → 门口按 F 进屋截图三栋；送灯进屋看槽位；他不在家门锁。
- 联机双端：见上。

## 收工记录（2026-09-06）

**做成的样子**：三栋房子从 07 之前就有同图 3×3 的内景房间（用户 2026-08-24 "能进去参观就行"）。这一期把它变成他的家：
傍晚 / 下雨 / 睡觉他**真的走进去**（`homeSteps` 走到窝上，不再 `hide`），白天在家段坐在窝上、起来让 wander 转一圈；
门是一扇会开合的板子（`resident_door`），**他不在家门锁着**（按 F 说"咕噜不在家。"），他在家或就在门口就不锁，
他走到门前门自动开，你按 F 开；你送对了爱吃的家具、find 委托做完 → `interior_place` 进屋的槽（地面 / 墙面各归各），
同一面满了最早的挪到门口，门口也满了进箱，他说一句；你在他屋里按 F 是屋内专用的三段闲聊；`visit_me` 要在他屋里完成；
夜里他在屋里窗户亮。指令：`/npc <谁> home`（进屋坐窝）、`/npc <谁> interior [list|<itemId>|clear]`、`/npc <谁> route <x> <z>`、`/doors`。

**和文档不一样的地方**

| 文档写的 | 实际 | 为什么 |
|---|---|---|
| 室内是像店铺那样的**另一张图**，进门 `travelTo` | **同图**：内景房间就在院子里（07 之前已经如此） | 联机 `travelTo` 在会话里一律不许切图，另一张图会让"房客能进居民房"直接不成立；同图的话居民在屋里是真的在另一间房里，位置、门、镜头盒全是现成的。02 文档里"08 之后回家 = 走进室内"正是这个意思 |
| 房子升到 l2 才有室内，l1 门不能开 | **l1 就有**（3×3），没有 l2 | 三栋 l1 早就能走进去；5×5 的 l2 要新壳子 + 图纸 + 升级成本，等参考图 |
| 三件专属陈设（凹坑 / 杂物堆 / 风铃）+ 三种房间风格 | 借现成家具占位（软垫 / 储物箱 / 挂画），风格 = 每家一种地板色 | 建模不凭描述开工（建模前先问参考图）。换真模型只改 `residentInteriorDefinitions` 的 `itemId` |
| 满了最早的**进箱** | 最早的先**挪到门口**，门口也满了才进箱 | 文档另一句"门口 2 件 + 屋里 3 件 = 5 件可见"；箱子是最后一站 |
| 进出时把居民"搬"进室内地图、`entities.ts` 装卸 | 不需要：位置在房子占地里就是"在家"（`insideHomeOf` 按矩形判） | 同图没有装卸；矩形而不是查地面归属，是因为无头用例里房子摆在主屋里、地面表会答主屋 |
| 箱子按 F 能打开看 | 只在 `/npc <谁> interior list` 里看得到 | 只读储物面板是一块新 UI，留到有需要时 |
| 他不在家门锁 = 读 `hidden` | 门的锁**每帧按主人位置算**（`ownerLock`）：在屋里 / 门口两米半 → 不锁；你已经在屋里 → 不锁（别把你关在里面） | 锁不进存档（存了下一帧也被覆盖） |
| 门代理加 `visitorOutside` 之类字段 | `Door.owner` + `Door.homeRect` | 两个字段够了，逻辑在 doorsRuntime 一处 |

**踩的坑（都进了用例或指令）**

1. **门洞 1.1 米居民排不出回屋的路**：导航网格 0.5 米采样、体型进到 0.5 档，没有一列采样点能带着圆穿过去。门洞改 1.6（`HUT_DOOR_WIDTH`，门板读同一个数）。
2. 评论 / 走位在浏览器里看不动，一半是**测试自己的问题**：领地区块锁着（每次刷新要 `/territory free on`）、玩家站在他路上、对话开着他被冻住（`tickResidents` 冻结对话对象；对话面板点 (400,245) 才关）。为此加了 `/npc <谁> route` 和 `/doors` 两条只读指令——动态 import 模块拿到的是死实例，问不到活的世界。
3. 门板往外开（铰链在左框，绕 y 负转把板子甩向 +z）。改成正转，往屋里开。
4. `place` 到院子角落 (0,0) 的居民哪儿都去不了：那一格本来就不可走。调试指令的锅，不是路的锅。

**没做（记到 15 / 参考图）**：l2 5×5 + 图纸 + 升级；三件专属陈设与三种风格的建模；箱子的只读面板；薇尔的树洞（附录，房子改成大树后 `residentInteriorDefinitions` 的 `spirit_house` 那份换成树洞的坐标）；联机双端看进屋 / 门锁（房客那边木偶位置同步过来，`ownerLock` 两端同算，但没实测）；镜头在 3×3 小屋里贴着后脑勺（店铺挑高那套经验，l2 变大才有解）。
