## 一句话

做任务赚金币 → 建金库 → 金库招来一条偷金币的小龙 → 水獭商人上门帮你抓贼，
顺便看上你的家具 → 从此行动产出的家具能换钱 → 邻居陆续搬来 → 满三位开家具小店 →
播报员出报纸 → 去过小镇之后开餐厅。

## 这套设计解决的是什么

改之前，游戏里有**两条互不相干的循环**：

```
循环 A  行动（现实里做完一件事）→ 固定物品 → 工作台/灶台 → 饱食
循环 B  每日任务 → 金币 → 图纸 / 开地 → 更多金库装更多用不掉的金币
```

A 的产出换不到钱，B 的金币除了买地没有别的去处，而买地是为了摆更多金库。
**家具是把两条接起来的那一根轴**：行动只产出家具，家具卖给水獭换金币。

## 离线补算的哲学（照动森，但拒绝它一类）

动森把离线期间的事分四类各管各的，我们照抄三类、明确拒绝一类：

| 类别 | 动森 | 我们 |
|---|---|---|
| **产出** | 补，但**封顶**（跳一天化石 4→6，跳十天还是 6） | 小店/餐厅按实结算多天，**货架存量就是天然上限**——货卖完就停，不用另写封顶规则 |
| **每日内容** | **不补**（商店商品、狸端机任务只有今天的） | 报纸只出最新一期（头条可以写"这几天"）；水獭行情只算今天 |
| **惩罚** | **累积**（杂草每天 3 棵，一个月 90 棵） | **不做。** 这正是本作定位要避开的，也是动森玩家抱怨最多的一块 |
| **重大变化** | **必须先问过你**（《新地平线》特意改的，老作村民不告而别） | 偷窃的追回是玩家的选择（决策 10）——同一个道理 |

## 贯穿九期的纪律

| | |
|---|---|
| **钱数只住一处** | 所有金额（偷多少、加价倍率、居民预算、食材标价）住 `Core/src/Data/economy/`；gameplay 代码里出现数字字面量就是违规 |
| **剧情零代码** | 期 0 补完口之后，偷窃、居民、解锁全部是 `storyRules` 数据。任何一期发现要在代码里写剧情 if，先回头检查是不是引擎还缺口 |
| **慢不是倒退** | 必需开销 1~2 个勾覆盖；离线结算只补不罚；损失要么净零要么玩家自己选的。每期验收都带一条"离线七天回来"的用例 |
| **存档四件套** | 动 `WorldSave` 形状 = 版本 +1、迁移、Backend `applyRefresh` 白名单、`net.ts`，四处一次做齐 |
| **一物一文件** | 新小动物 = `Visual/recipes/` 一文件 + `petDefinitions` 一行；新楼 = `Buildings/` 一文件 + 登记一行；新面板 = `PanelId` 一行 + 组件 |
| **建模前先问参考图** | 动任何几何代码之前**先停下来问用户有没有图**（用户 2026-08-24 定）。低模的辨识度几乎全在剪影和比例上，凭文字描述建出来的东西返工成本很高——石傀儡第一版读成一根石柱，整套比例重排过。有图就按图采样配色（不拿最接近的现成色号顶上）；没图就先说清打算怎么理解那个形象，让用户纠一遍再动手。**本蓝图里期 3（水獭）、期 4（三位居民 + 居民房）、期 6（旅行商人）、期 7（打印机）、期 8（餐厅）都卡这一条。** |
| **确定性抽签** | 行情、居民抽签、商人排期全用 `hashSeed(种子 + worldDayId)`——同一天重开必须一致，否则"重开刷一刷"立刻成为最优策略。真随机只留给开箱 |

## 刻意不做的

- 四维修为（决策 5）
- 惩罚性的离线累积（杂草那一路）
- 玩家定价 / 讨价还价（Recettear 那一路，会把重心从陪伴挪到经营）
- 餐厅的实时操作玩法（等厨房重做那一版，用户想做成 Overcooked 那样）
- 居民的门槛条件（决策 14：现在纯随机，架构留口）
