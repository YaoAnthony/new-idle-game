> 一句话：走近他先开口，按 F 再细聊；说什么看时段、天气、心情、你今天做了什么、他记得什么。
> 每人有口头禅、有表情、有记忆。**一句台词都不写在代码里**，全部是对话池 + 条件。

## 玩家看到什么

- 早上第一次走近咕噜，他头顶冒一句"哈——早啊，咕噜刚醒。"（气泡，不开面板）。下午再走近，换一句短的；一个时段只主动说一次。
- 按 F，面板打开，是闲聊：晴天说晴天的，下雨说雨的，夜里问你怎么还不睡。同一天反复按 F，先后说三段不同的话，第四次开始重复"今天说得够多啦"这类收尾。
- 你今天在游戏里做完了一次"运动"类行动，阿茜会说"我看见你早上在跑步，跑得比我还快嘛"。
- 你手里拿着煎蛋走近，薇尔："那是……煎蛋？闻起来很暖。"
- 送过咕噜一盏云朵灯（爱吃档 / 委托要的），之后闲聊会冒出"上次你给的灯，咕噜每晚都开着"。
- 三天没和阿茜说话，再见面："哟，好几天没见了，还以为你搬走了呢！"
- 每人说话带口头禅：咕噜句尾"嘿嘿"，阿茜"喏"，薇尔说话不带口头禅（性格）。
- 对话里他会做表情（头顶冒一个小图标：开心 / 疑惑 / 害羞 / 困），和台词同步。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 走近主动说话，一天第一次热情 | 取。`greet` 技能 + `speak` 动词，时段节流 |
| 按 A 闲聊按情境挑 | 取。条件池 + 确定性抽段 |
| 一天聊多了会"说够了" | 取。`talks_today` 条件 |
| 评论衣着 / 工具 | 改成评论**手持物** |
| 反应（Reactions）在对话里做表情，也教你 | 表情注册表；"教你"→ 送一个 `gesture` 给玩家（玩家表情系统另议，这里只留信号） |
| 口头禅可改 | 04 |
| 讲别人八卦 | 06 |
| 提你最近的事（钓到大鱼） | 改成提你**现实里做的行动**——本作独有 |

## 两层对话

| 层 | 触发 | 载体 | 内容量 / 人 | 好感 |
|---|---|---|---|---|
| **招呼**（气泡） | 玩家进入 `greetDistance`（性格表，2.5~3.5 m）且本时段未招呼 | `speak` 动词 → 头顶 `Bubble`，3 秒 | 20 句 | +1 / 日（04） |
| **闲聊**（面板） | 按 F | 现有 DialoguePanel | 15 段 + 10 段条件特殊段 | +1 / 日（04） |
| **事件对话** | 剧情 / 委托拉起 | 现有 | 按剧情 | — |

招呼不打断他在做的事：`speak` 是**并行动词**——不进 Intent 队列，身体上有一个独立的"嘴"槽，走路、坐着都能说。这是 01 动词表里 `speak` 的补充定义：`speak` 和 `gesture` 是并行槽，其余是串行槽。

## 数据

### 对话池（Core/src/Data/residents/talk/<residentId>.ts，一人一文件）

```ts
export const slimeTalk: TalkPool = {
  residentId: "slime_neighbor",
  catchphrase: "talk.slime.catchphrase",          // "嘿嘿"，模板里的 {cp} 替换成它
  greetings: [
    { key: "talk.slime.greet.morning_1", when: [{ kind: "day_phase_is", phase: "dawn" }] },
    { key: "talk.slime.greet.rain_1",    when: [{ kind: "weather_is", weatherId: "rain" }], weight: 3 },
    { key: "talk.slime.greet.low_mood",  when: [{ kind: "mood_below", value: 40 }], weight: 5 },
    { key: "talk.slime.greet.any_1" },            // 无条件兜底
    // …
  ],
  chats: [
    { dialogueId: "slime_chat_sun_1", when: [{ kind: "weather_is", weatherId: "sunny" }] },
    { dialogueId: "slime_chat_saw_you_exercise", when: [{ kind: "recent_action_category", category: "exercise" }], weight: 4, oncePerDay: true },
    { dialogueId: "slime_chat_lamp_memory", when: [{ kind: "remembers", memoryId: "gift_cloud_lamp" }], weight: 2 },
    { dialogueId: "slime_chat_long_time", when: [{ kind: "days_since_last_talk", atLeast: 3 }], weight: 10, oncePerDay: true },
    { dialogueId: "slime_chat_enough", when: [{ kind: "talks_today", atLeast: 3 }], weight: 100 },   // 说够了
    // …
  ],
};
```

- `when` 是**对话引擎已有的 `DialogueCondition`**，本期补的新种类见下。招呼和闲聊共用同一套条件，不发明第二套。
- `weight` 默认 1；抽取 = 过滤满足条件的 → 按权重确定性抽（`hashSeed(residentId + worldDayId + talksToday)`）。同一天同一次数重开必须同一段。
- 闲聊段本身是普通 `DialogueDefinition`（可以有选项、可以送礼、可以 `emitEventId`），池只负责挑入口。
- **口头禅**：文案里写 `{cp}`，渲染时替换；玩家改过的存 `ResidentSave.catchphrase`（04）。

### 新增的对话条件（Core/types/dialogue.ts）

| 条件 | 读什么 | 备注 |
|---|---|---|
| `day_phase_is: phase` | `getClock().dayPhase` | 四段 |
| `mood_below / mood_at_least: value` | `ResidentSave.mood` | 心情现在终于有人读 |
| `days_since_moved_in: atLeast / atMost` | `ResidentSave.movedInDayId`（**新字段**，搬入那天写） | 刚搬来三天内的段 |
| `days_since_last_talk: atLeast` | `ResidentSave.lastTalkDayId`（**新字段**） | 久别 |
| `talks_today: atLeast` | `ResidentSave.talksToday`（**新字段**，跨天归零） | 说够了 |
| `recent_action_category: category` | `getActionEntriesByCategory` 里今天的 | 本作独有 |
| `holding_item: itemId? / itemTag?` | 玩家手持（`heldPreview`） | 评论手持物 |
| `remembers: memoryId` | `ResidentSave.memories` | 记忆 |
| `neighbor_present: residentId` | 场上有没有那位 | 06 用，这期先加条件 |
| `season_is` | — | **不加**：没有季节系统。表里留位置的做法是等季节系统来了加条件，不预埋 |

条件求值集中在 `Systems/dialogue.ts` 的 `conditionMet`，一处 switch 加九个 case——这是引擎里唯一允许长的 switch，因为条件种类本来就是引擎的词汇表。

## 技能与动词

- **`greet` 技能**（优先级 30，可打断——但它用并行槽，实际不抢串行动作）：`decide` 检查玩家距离 < `greetDistance` 且 `lastGreetPhase !== 当前时段` → 返回并行 Intent `[gesture(expression), speak(key, 3s)]`，写 `lastGreetPhase`（运行时，不进存档）。木偶模式不跑（房客不会被房主的邻居打招呼——**第一版**；见联机）。
- **`reactions` 技能**：无 `decide`，只有事件订阅；01 的 `Skill` 接口加可选 `onEvent(ctx, event)`。
- **F 交互**：01 定的 `interact()` → 居民子类返回 `{ kind: "dialogue", dialogueId: pickChat(...) }`；`pickChat` 是 Core 纯函数（池 + 条件求值结果 + 种子 → dialogueId），前端只负责把条件算出来喂进去。
- 对话打开时他**转身面向玩家**（`stand(facing: player)` 串行动词，`command` 优先级，结束后恢复原 Intent）。这一条是动森最让人觉得"他在和我说话"的细节，成本一行。

## 存档

`ResidentSave` 加四个可选字段：`memories: string[]`、`movedInDayId`、`lastTalkDayId`、`talksToday: number`。老档读出来 undefined → 空 / 0。**版本号 +1、空迁移。** 这些是 `WorldSave.pets` 下的字段，联机走 `pets` 切片自然带过去。

## 联机

- 房主的邻居**不主动**和房客打招呼（`greet` 不在木偶上跑）；房客按 F 能闲聊，条件在房客本地算：时段天气来自房主同步过来的时钟天气，`recent_action_category` 读的是**房客自己**的行动（这是合理的——他评论的是眼前这个人），`talks_today` 等居民侧字段读房主同步过来的值但**不写回**（房客说再多，房主那边的 `talksToday` 不动）。
- `add_memory` 效果在房客端不执行（剧情系统做客时闭嘴，本来就不会跑）。
- 反应技能在木偶上**只跑表现**：房主发关键帧时把 `expression` 带上（01 的关键帧字段加 `expression?`），房客照着冒图标。
- 联机验收：房主走近史莱姆 → 房主看到招呼气泡，房客那边史莱姆头顶同步冒同一个表情图标但**不冒台词**（第一版只同步表情不同步台词——台词是对着房主说的）；房客按 F → 面板打开、对话正常、结束后房主 `/npc slime where` 的 `talksToday` 不变。

## 指令

| 指令 | 干什么 |
|---|---|
| `/npc <谁> say <文案键>` | 立即冒一句气泡（走 `speak` 动词） |
| `/npc <谁> expr <表情id>` | 立即做一个表情 |
| `/npc <谁> talk` | 打印当前条件求值结果 + 闲聊池里此刻满足条件的段落和权重 + 会抽到哪一段。写文案时用它看"为什么这段不出现" |
| `/npc <谁> memory add\|rm <memoryId>` | 调记忆 |
| `/npc <谁> reset-talk` | `talksToday = 0`、`lastGreetPhase` 清空 |

## 内容量与写法

三位 × （20 招呼 + 15 闲聊 + 10 特殊）= 135 条。文案键规则 `talk.<resident>.<greet|chat>.<slug>`。写作要求：

- 每人一个说话方式，不靠口头禅撑：咕噜第三人称叫自己"咕噜"、短句、多省略号；阿茜感叹号多、爱用"喏""哟"；薇尔句子完整、用"请"、偶尔说一句像诗的话。
- 天气段不解释天气（"今天下雨了"没有信息量），说**他对天气的感受**（"雨落在咕噜身上会陷进去一点，痒痒的"）。
- 特殊段每段至少一处引用上下文（记忆 / 行动 / 手持物）才算特殊段。

## 刻意不做的

- 八卦（06）、改口头禅与昵称（04）、季节条件（无季节系统）、教玩家表情（玩家表情系统不存在）、台词语音。

## 最容易写错的四处

1. **在技能里写台词**。`greet` 只知道"该打招呼了"，说哪句是池子的事。
2. **条件求值用 `Math.random`**。同一天同一次数必须同一段，用 `hashSeed`。
3. **`speak` 进了串行队列**，他一说话就停下不走了。并行槽。
4. **记忆在对话系统里直接 push**。只有剧情效果能写。
