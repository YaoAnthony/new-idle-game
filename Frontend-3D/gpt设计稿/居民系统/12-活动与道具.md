# 12 · 活动与道具

> 状态：**12 已完成（五件道具占位，待参考图）** · 2026-09-06 · 本提交 · 前置：02 场所、06 一起待着
>
> 一句话：他不只是"站在场所"，他在那儿**做事**——看书、喝东西、打伞、打水、在工作台敲敲打打、
> 对着水面发呆。每种活动 = 场所条件 + 动词序列 + 手持道具 + 时长，全是注册表；性格的爱好决定挑哪些。

## 玩家看到什么

- 咕噜坐在椅子上，手里捧一杯东西，隔一会儿抬一下（喝）。阿茜跑到井边，拎起一只桶，弯腰、起身、放下。薇尔站在河边，什么都不拿，看水。
- 下雨，阿茜出门时手里举着一把伞（她的性格 `go_out_slow`）；咕噜不出门；薇尔站在屋檐下看雨，没伞。
- 你的工作台空着时，阿茜会跑过去站在台前敲两下（不产出任何东西，纯演出），走开时说"我也想做点什么"。
- 两位 `friends` 坐在一起时各拿一本书（06 一起待着 + 活动叠加）。
- 石傀儡建完房子，会在工地旁边坐下歇一会（活动对非居民也开放：它是 Resident 基类的能力）。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 村民活动：钓鱼、抓虫、浇花、跑步、做瑜伽、看书、喝咖啡、吃零食、DIY、唱歌、哼歌、睡午觉、玩手机、坐地上、靴子踢石头 | 取能对上我们世界的：看书、喝东西、打水、DIY 台演出、看水、打盹、哼歌、伸展；**不取**钓鱼抓虫浇花（没有这些系统；有了是加一行） |
| 6 种爱好决定活动倾向 | 取：性格表 `hobbies: HobbyId[]`，活动表 `hobby` 字段，权重相乘 |
| 手里拿东西（书、杯子、伞、渔具） | 取：**手持道具**——基类新增一个"手"槽，挂一个 `VisualId` |
| 雨衣、季节服装 | 无服装；伞是道具 |
| 反应动画（Reactions）配活动 | 03 的表情复用 |

## 数据

### 活动表（Core/src/Data/residents/activities.ts）

```ts
export const activityDefinitions = [
  { id: "read",      spot: "seat",  hobby: "education", prop: "book",    steps: ["sit", { stand: { flavor: "reading", seconds: [40, 90] } }], weight: 2 },
  { id: "sip",       spot: "seat",  hobby: "relax",     prop: "cup",     steps: ["sit", { stand: { flavor: "sipping", seconds: [30, 60] } }], weight: 2 },
  { id: "draw_water",spot: "water", hobby: "nature",    prop: "bucket",  steps: [{ stand: { flavor: "drawing", seconds: [6, 8] } }] },
  { id: "watch_water", spot: "shore", hobby: "nature",  prop: null,      steps: [{ stand: { flavor: "gazing", seconds: [30, 80], facing: "spot" } }] },
  { id: "tinker",    spot: "workbench", hobby: "craft", prop: "hammer",  steps: [{ stand: { flavor: "tinkering", seconds: [20, 40], facing: "spot" } }], requires: { spotIdle: true } },
  { id: "hum",       spot: "any",   hobby: "music",     prop: null,      steps: [{ stand: { flavor: "humming", seconds: [10, 20] } }], parallel: { speak: "hum.notes" } },
  { id: "stretch",   spot: "any",   hobby: "fitness",   prop: null,      steps: [{ gesture: "stretch" }], weight: 0.5 },
  { id: "nap",       spot: "seat|any", hobby: "relax",  prop: null,      steps: [{ sleep: { seconds: [90, 150] } }], weather: ["sunny", "cloudy"] },
] satisfies ActivityDefinition[];

export const hobbyDefinitions = ["nature", "fitness", "education", "craft", "music", "relax"] as const;

export const weatherProps = {
  rain:  { prop: "umbrella", forPersonalities: { onRain: ["go_out_slow"] } },   // 打伞的只有照常出门的
  storm: null,
} as const;
```

- **场所表（02）加两种**：`shore`（河岸：`GroundMap` 里水边一格的陆地，从地形推）、`workbench`（带 Crafting 能力的室外 / 你家里的工作台，`requires.spotIdle` = 玩家没在用）。
- `steps` 就是 01 的动词序列，多了 `flavor`（表现层选动画 / 姿态）和 `prop`（手持道具）。**活动不引入新动词。**
- 性格表加 `hobbies: ["relax", "nature"]`（咕噜）/ `["fitness", "craft", "music"]`（阿茜）/ `["nature", "education", "music"]`（薇尔）。权重 = 活动 `weight` × （爱好匹配 ? 3 : 1）。

### 手持道具

- 基类 `Resident` 加 `heldProp: VisualId | null`（运行时 + **进关键帧**，不进存档——读档时活动重新决策）。
- `ResidentView` 在手部挂点（各造型配方声明 `userData.handAnchor`，没声明的挂在体心偏前）挂道具模型。道具配方 `Visual/recipes/props.ts`：书、杯、桶、锤、伞（**先问参考图**，五件小件）。
- 伞：`walk_to` 期间也举着（道具跟随不受动词限制）；进屋 / 停雨自动收。

### 与 02 的接法

02 的 `routine` 决定"去哪种场所"；到达后原本是场所表里写死的动词序列。这期改为：**到达后从活动表里按 `spot` + 爱好 + 天气过滤，确定性抽一个活动执行**，场所表只剩"怎么认出这种场所"。这是 02 自查里预告过的方向（"等有了是场所表加行"），现在场所和活动彻底分开。

## 技能与动词

- 无新技能、无新动词。`routine` 的 `visit` 到达回调换成 `pickActivity(spot, ctx)`（Core 纯函数）。
- `hum` 的 `parallel.speak` 用并行槽冒音符气泡（"♪"），配 `Soundscape` 一段短哼唱采样（音频那边加一条 `sfx_hum_<resident>`，按 `residentId` 查；没有就静音）。
- 石傀儡等非居民子类也能挂 `activities`（基类能力）：石傀儡子类声明 `activities: ["nap"]`，完工后歇一会——这是"居民系统"的一个副产品，顺手。

## 联机

- 活动决策在房主；房客收到 Intent（含 `flavor`）+ 关键帧（含 `heldProp`）。**关键帧字段加 `heldProp`、`flavor`**（01 的关键帧定义补两项，协议 +1）。
- 联机验收：房主端咕噜坐下喝东西 → 房客那边咕噜手里有杯、同一姿态；下雨阿茜举伞 → 房客那边也举伞、停雨同时收。

## 指令

| 指令 | 干什么 |
|---|---|
| `/npc <谁> activity <activityId>` | 立即做一个活动（会先走到对应场所） |
| `/npc <谁> prop <visualId\|none>` | 手上挂 / 摘道具 |
| `/npc activities` | 打印活动表 + 每位此刻可选的活动和权重 |

## 存档

无新存档字段（`heldProp` 运行时）。性格表、活动表、场所表是内容。协议 +1（关键帧字段）。

## 刻意不做的

- 钓鱼、抓虫、浇花（没有这些系统）；服装；活动产出东西（阿茜在工作台敲不出家具）；玩家能打断活动之外的互动（按 F 照常打断，那是 03 的转身）。

## 最容易写错的四处

1. **活动里写新动词。** 只能组合已有九个。
2. **道具进存档。** 读档重新决策就有了；存进去反而会出现"没在喝却拿着杯子"。
3. **伞在室内 / 停雨后不收。** 天气变化事件 + 进屋回调都要摘。
4. **`workbench` 场所和玩家抢。** `spotIdle` 判玩家是否在用（`station_open` 状态），玩家走过去他要让开（`onInterrupted` 站起）。

## 收工记录（2026-09-06）

**做成的样子**：`Core/Data/residents/activities.ts` 九条活动（read / sip / draw_water / watch_water / tinker / browse / hum /
stretch / nap），每条 = 场所 + 爱好 + 道具 + **已有动词的模板序列**（秒数是区间，按种子落定）+ 权重 + 天气 + 要不要场所空着。
`pickActivity(spot, ctx)` 纯函数：过滤（场所 / 天气 / 空着）→ 权重 ×（爱好匹配 ? 3 : 1）→ 按种子抽；`activitySteps` 把模板翻成
动词（`faceSpot` 换成场所坐标）。性格表加 `hobbies`（咕噜 relax/nature、阿茜 fitness/craft/music、薇尔 nature/education/music）。
`routine` 的 `visitIntent` 从此不再是一串 if——到了场所查表；种子里带**每位递增的轮次**，同一把椅子一天坐三次可以做三件不一样的事。
场所表加 `shore`（源 `terrain_shore`：高度场里"脚下是岸顶、三米外是水"的点每 4 米取一个、朝水，一张图算一次缓存，站不站得住每次
用 `isWalkable` 现判；`MapDefinition.waterLevelY` 从 terrain 的 `WATER_LEVEL_Y` 来）和 `workbench`（院子里带 Crafting 能力的家具，
`spotIdle` = 行动系统的 `furnitureInstanceId` 没指着它）。手持道具：`Intent.prop`（VisualId，进网线、不进存档）+ `agent.weatherProp`
（伞，跨 Intent，`weatherProps` 系统按天气 / 性格发），`heldProp` 取值：木偶照抄关键帧；藏着 = 空；活动道具优先；伞只在室外举。
`ResidentView.syncProp` 按身体包围盒挂在右手边半身高、随身高缩放（0.6~1.6）。五件道具配方 `recipes/props.ts`（占位几何）。
石傀儡收工没活了就地伸展 + 打盹（build 的 `onDone`，用 nap 的优先级，来了新工地照样被叫醒）。指令三条。

**和文档不一样的地方**

| 文档写的 | 实际 | 为什么 |
|---|---|---|
| 造型配方声明 `userData.handAnchor` | 视图按包围盒算挂点（右手边、半身高、略靠前），配方不声明 | 三种骨架各不相同，让每个配方多一个约定 = 换模型就得回来改；等正式造型来了再看要不要手的节点 |
| `read` / `sip` 是 sit + stand(flavor) | 就是 `sit`，道具说明一切 | 坐着"抬一下杯子"要动画，表现层今天没有；坐着捧本书已经看得出在看书 |
| `workbench` 含"你家里的" | 只认**室外**（outdoor: true） | 没被请进门的居民不进你家（07 的规矩）；室内的工作台在门后面，排路会撞门 |
| `hum` 配 `Soundscape` 一段哼唱采样 | 只有气泡 "♪～♪"（`talk.common.hum`），没有音 | 音频资源没有；表里挂了 `speak`，声音那边接上是加一行 |
| 协议 +1（关键帧加 `heldProp` `flavor`） | **不加**：01 那次已经把 `heldProp` 定进关键帧了 | 字段早就在，只是没人写；改的是房主端"变没变"那把键多比一个字段 |
| 石傀儡子类声明 `activities: ["nap"]` | 写在 build 技能的 `onDone` 里 | "完工歇一会"和工地队列绑在一起（队里还有就不歇），放基类要多一个"完工"事件；傀儡只此一条，等第二种非居民要活动再抽 |
| 走开时说"我也想做点什么" | 没做 | 是一句台词，等 13 的个人线一起写 |
| 两位 friends 坐一起各拿一本书 | 没做 | 06 的 meet 是站着说话，没有"一起坐"的动作 |
| 验收：八个活动各一张 | 三张（雨天举伞、井边打水、河边看水） | 看书 / 喝东西要室外椅子（档里没有）、工作台要院子里的（没有），走的是同一条路 |

**踩的坑**：`/npc slime activity draw_water` 之后我把玩家传送到了它的路上，走到一半被挡 → Intent 作废，作息接管——
不是代码的锅（备忘 9 已写过）。河岸候选里有几个落在桥面上（桥面是院子高度、三米外就是水）：薇尔"看水"站在桥上看，
不算错，但要是嫌，加一条"桥面不算岸"的过滤就行。

**没做**：五件道具的正式造型（参考图）；哼唱采样；联机双端（`prop` 进 WireIntent、`heldProp` 进关键帧和变更键，
用例里木偶照抄验过，没开双标签页）；faceSpot 之外的朝向（哼歌 / 伸展就地朝原来的方向）。顺手记到 15：桥面不算岸。
