# 04 · 好感与称呼

> 状态：**04 已完成** · 2026-09-06 · 本提交 · 前置：03 对话与记忆
>
> 收工记录：分 → 档、老档补值、称呼渲染、昵称确定性、心情速度都是 Core 纯函数（`logic/affection.ts`），
> 数字在经济表（`affectionTuning` / `moodTuning`），称呼表 `Data/residents/address.ts`。
> 加分**只有** `Systems/residents/affection.ts` 的 `gainAffection`，而它只被剧情效果 `adjust_affection` 调；
> 规则由 map 生成（三位 × 招呼 / 聊天 / 收礼四档 / 随机赠礼 / 专属家具 / 两个输入框 = 30 条）。
> 随机赠礼走 `resident_present` 效果 → `Systems/residents/presents.ts`：走过来 → 对话 → 对话结束弹领取面板；
> 专属家具是同一条路带 `itemId`。改称呼是 `prompt_text` 效果 → `Components/Residents/TextPrompt.tsx`。
>
> **偏离文档的几处**：① `{you}` 不是代词是**呼语**（"{you}，早啊"）——把 270 句里的"你"全换成称呼会出现"小软好呀"这种句子；
> 陌生档呼语为空时连标点一起收掉。所以没有"没写 {you} 却出现你"的正则审计，改成每人若干句带呼语。
> ② 好感规则要知道**谁**收了礼：加信号 `resident_gift_received`（subject `人:档`）。③ 触发条件加 `requiresAffection`
> （看档位不看分数，StoryContext 加 `affectionStage`）——随机赠礼"伙伴档起"靠它进池。④ 三件专属家具先用现成的
> 云朵灯 / 路灯 / 幸运竹顶着：建模前要问参考图（用户定的规矩），这期没法问。⑤ `sat_on_your_seat` / `bought_from_shop`
> 的来源在表里、规则没接：`resident_used_spot` 的 subject 是场所种类不是人，等 05 小店一起接。
> ⑥ 一天一次的节流是运行时账本不进存档：读档后同一天最多多拿一次，换存档少一张表。
>
> **验收结果**：Core `affection.test` 7 条 + content 2 条（三位都有专属家具 / 赠礼表 / 昵称候选；四档递增无负数），451 过。
> Frontend `tests/affection.test.ts` 8 条：规则各 +1 且一天一次；跨档发信号并起昵称；`{you}` 三档渲染 + 改昵称 / 口头禅落存档；
> 老档迁移补分（v39）；随机赠礼保底四天内必中 → 走过来 → 对话 → 领取面板；专属家具一次性 + 记忆；心情日结不进好感；做客不涨不弹。全套 726 过。
> 浏览器：`/npc slime affection` 1 → `=30`（familiar）→ `=90`（life_companion，叫你「软软」）；`/npc slime present` → 他走过来"软软……这个，给你。"
> → 领取面板"邻居送来的 · 鸡蛋"；`ask_nickname_slime` → 输入框（预填「软软」）→ 改成「小软」→ `/npc slime say talk.slime.greet.any_1` → "小软，你好呀……嘿嘿"。
> 联机：房客侧的守卫（不涨、不弹、呼语用房客自己的名字）由用例覆盖，双标签页没单独验，记到 15。
>
> 一句话：好感是隐藏的分，看得见的是物——他怎么叫你、送你什么、请不请你进屋。
> 没有减分，没有心形条。心情值终于被读。

## 玩家看到什么

- 刚搬来时咕噜叫你"你"，熟了以后叫你的名字，再熟叫他自己起的昵称（"小软"）。你可以在对话里说"别这么叫我"，他会换一个或者问你想被叫什么。
- 有一天早上阿茜跑过来："喏，这个给你！"——一份食材或她"从老家带来的"小物。这是好感到"生活伙伴"档那天的一次性事件，之后偶尔（每几天一次）还会送。
- 好感到"家人"档，薇尔送你一件**她做的家具**（每位一件专属，动森"照片"的替身），门上挂一块写你名字的牌（07）。
- 你可以问他"要不要换口头禅"（伙伴档起），他会试着说一遍新的。
- 心情低时他话少、走得慢、招呼变成"……嗯"。连续几天没人理他心情就往下走，但**好感不掉**。
- 生日当天送礼，反应比平时大一档（11）。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 友好度 0~255 隐藏，六档 | 隐藏分 + **四档**（现有 `AffectionStage` 不加档，四档已经够分四种称呼） |
| 每天聊天 +、送礼 +（包装 +、生日 ×2）、完成请求 + | 取，数字进 Core 表；不做包装 |
| 打人 / 推人 / 网兜 − | **不做减分**（定案） |
| 档位解锁：送东西 → 教反应 → 改口头禅 → 改昵称 → 照片 | 送东西 → 改口头禅 / 昵称 → 专属家具 + 门牌 + 请你进屋（08） |
| 照片 = 最高档凭证 | 专属家具（每位一件，有他的气质）代替照片 |
| 村民随机送你东西 | 取，伙伴档起每 N 天抽一次 |

## 数据

### 好感分（Core/src/Data/economy/index.ts，和其他钱数一样住经济表）

```ts
export const affectionTuning = {
  /** 各档的下限分。四档对应 AffectionStage 的四个值 */
  stageThresholds: { stranger: 0, familiar_resident: 30, life_companion: 90, family: 200 },
  gains: {
    greet: 1, chat: 1,                  // 每日各一次
    gift: { loved: 6, liked: 3, disliked: 1, inedible: 1 },   // 每日一次（现有节流）。送错也有 1：递东西本身是心意
    favor: 10,                          // 05
    sat_on_your_seat: 1, bought_from_shop: 1,   // 02 场所 / 05 期小店，每日各一次
    birthday_gift_multiplier: 2,        // 11
  },
  /** 伙伴档起，隔几天可能送你东西；命中率随天数涨（照 storyPools 的保底做法） */
  presentPool: { everyDays: 3, base: 0.3, step: 0.2, max: 1 },
} as const;
```

- `ResidentSave.affection: number`（**新字段**，老档按当前 `affectionStage` 的下限补）。`affectionStage` 保留，由分数推导后写回（存两份是为了老代码与对话条件 `affection_at_least` 不改）。
- 加分入口**只有一个**：新剧情效果 `adjust_affection: { residentId, source }`——`source` 是 `gains` 表的键，效果执行时查表加分、按日节流、跨档发 `affection_reached` 信号。谁触发：`resident_greeted` / `dialogue_ended` / `gift_*` / `favor_completed` / `resident_visited` 这些**已有或本系列新增的信号** → storyRules 里五条规则各接一个 `adjust_affection`。好感变化因此也是数据，改"聊天给几分"不碰代码。

### 称呼（Core/src/Data/residents/address.ts）

```ts
export const addressDefinitions: Record<AffectionStage, AddressForm> = {
  stranger:          { kind: "generic" },          // "你"
  familiar_resident: { kind: "player_name" },      // 你的名字
  life_companion:    { kind: "nickname" },         // 他起的昵称
  family:            { kind: "nickname" },

```

- 每位居民的候选昵称列表在他的 talk 文件里：`nicknames: ["talk.slime.nick.1", "talk.slime.nick.2", …]`。到伙伴档那天确定性抽一个，存 `ResidentSave.playerNickname`。
- 文案模板 `{you}` 渲染时按档位替换。**所有 135 条台词里的第二人称都写 `{you}`**，不写死"你"。
- 玩家改昵称：对话选项 → `emitEventId: "ask_nickname"` → 打开一个单行输入（复用报纸取名那套输入框）→ 写 `playerNickname`。改口头禅同理写 `ResidentSave.catchphrase`。两个输入都过 `NET_LIMITS.maxNameLength` 那条长度闸。

### 专属家具与随机赠礼

- `ResidentDefinition.signatureItemId`（**新字段**）：到家人档那天经领取面板（`presentItems`）送出，一次性，`ResidentSave.memories` 记 `gave_signature`。三件家具要建模（**先问参考图**）。
- 随机赠礼：`ResidentDefinition.presents: ItemId[]`，伙伴档起每 `everyDays` 天抽一次保底池，命中 → 早上他主动走过来（`approach` 技能加一个"有东西要给"的高优先级分支）→ 一段对话 → 领取面板。**用现有 `storyPools` 那套保底抽签**，不另写。

### 心情（读入）

心情已经在存档里、已经在衰减（`driftMood`）。这期加读入，全部是数据：

| 读它的 | 怎么读 |
|---|---|
| 招呼池 | `mood_below` 条件（03 已加） |
| 走路速度 | `walk_to` 的 `speedScale` 乘 `moodSpeed(mood)`：`Core/logic/mood.ts` 纯函数，< 30 → 0.8，> 80 → 1.1 |

| 好感 | **不读**。心情低不扣好感 |

心情的涨跌来源补两条：连续 N 天没被打招呼 −，`sat_on_your_seat` / 天气合口味（性格表 `likesWeather: ["rain"]`）+。数字进 `moodTuning`。

## 联机

- 好感是**房主玩家**和居民的关系。房客和居民闲聊**不涨**任何人的好感（动森同样：客人和岛上村民不建立友好度）。`adjust_affection` 只在房主端执行——剧情效果本来就只在房主跑。
- 称呼：房客看到的台词里 `{you}` 渲染成**房客自己的名字**（generic 档），不显示房主的昵称。这是渲染时替换，不涉及同步。
- 随机赠礼、专属家具只发给房主。
- 联机验收：房客和史莱姆聊 5 次，房主 `/npc slime affection` 分数不变；房主到伙伴档后，房客那边史莱姆对房客仍叫名字不叫昵称。

## 存档

`ResidentSave` 加 `affection`、`playerNickname?`、`catchphrase?`；`ResidentDefinition` 加 `signatureItemId`、`presents`。老档 `affection` 按档位下限补。**版本号 +1，迁移只做这一处补值。**

## 刻意不做的

- 心形 / 数字 UI；减分；包装；照片道具；和房客的好感。
- 日记本"邻居页"：上一版方案里提过，这里**不做**——进度是物，翻日记看分数和"看面板"没区别。要看只有指令。

## 最容易写错的三处

1. 在 gifting.ts / dialogue.ts 里直接 `affection += n`。只有 `adjust_affection` 效果能加。
2. 昵称抽取用了 `Math.random`。确定性。
3. 台词里写死"你"。全部 `{you}`，i18n 测试用正则抓没写 `{you}` 却出现"你"的键（白名单里除外）。

## 验收

- Core `affection.test`：分数 → 档位；每日节流；跨档发信号；老档补值。
- Frontend：五条规则各 +1 一次；`{you}` 三档渲染；改昵称落存档；随机赠礼保底在第 N 天必中。

- 浏览器：`/npc slime affection =89` 聊一次 → 跨到伙伴档 → 次日早上他跑过来送东西（`/day` 推进）→ 领取面板；`=200` → 专属家具面板 + 门牌（07）。截图。
