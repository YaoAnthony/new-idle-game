# 07 · 来访与门口

> 状态：**文档，待执行** · 2026-09-05 · 前置：04 好感、05 委托、02 场所
>
> 一句话：他来你家敲门，进来坐你的椅子、评论你摆了什么、临走送你东西；
> 你送他的东西摆在他门口，家人档的门上挂着你的名字。这一期不建室内，全靠门口和你家。

## 玩家看到什么

- 下午你在屋里做东西，门外传来敲门声（音效）+ 门上冒一个"？"。走过去按 F 开门，阿茜站在门口："哟，我路过，进来坐坐？"选"进来吧" → 她走进屋，四处看看，坐到你做的椅子上，冒气泡："这把椅子是你做的？坐着比我家的软。"待几分钟，起身："我该回去了，这个给你。"领取面板一样小东西。她走出门回家。
- 你不在家（在院子里或小镇）她不来；你在屋里做专注行动（自动生活）她也不来，等你闲下来。
- 咕噜门口的地上摆着你送他的云朵灯，晚上和窗灯一起亮；阿茜门口是你送的小凳子。
- 薇尔到家人档那天，她门上多了一块小木牌，写着你的名字（存档里玩家名）。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 村民来你家敲门（NH：你在家时随机来） | 取：`visitPlayer` 技能，条件 + 保底抽签 |
| 进来后评论你的布置（按 HHA 那套：物品数量、主题、脏乱） | 取评论、**不取评分**：评论从你室内的家具能力和数量推 |
| 坐你的椅子、看你的电视、用你的东西 | 取：用 02 的场所解析，只是范围换成"你家室内" |
| 临走送东西 | 取 |
| 你去他家 → 他邀请 → 进屋 | 08（室内） |
| 送的家具摆进他家 | 这期摆**门口**，08 进室内 |
| 门上贴名字 | 取 |

## 数据

### 来访（Core/src/Data/residents/visits.ts）

```ts
export const visitTuning = {
  /** 伙伴档起可能来访；保底池 */
  pool: { everyDays: 2, base: 0.25, step: 0.2, max: 1 },
  requires: [{ kind: "affection_at_least", stage: "life_companion" }],
  /** 来访时段：从性格的作息表里挑一个 do !== hang_home 的段替换 */
  windows: ["11:00-13:00", "15:00-17:00"],
  /** 在你家待多久（秒，现实时间） */
  staySeconds: [120, 240],
  /** 敲门后等你多久，不开就走 */
  knockWaitSeconds: 45,
} as const;

/** 评论从室内推：每条 = 条件 + 文案池。条件读的是"你家室内"的快照 */
export const houseCommentDefinitions = [
  { id: "many_seats",   when: { capabilityCount: { capability: "sitting", atLeast: 4 } }, pool: "house_comment.many_seats" },
  { id: "has_gramophone", when: { furnitureId: "gramophone" }, pool: "house_comment.gramophone" },
  { id: "cluttered",    when: { floorFillRatio: { atLeast: 0.6 } }, pool: "house_comment.cluttered" },
  { id: "your_craft",   when: { anyFromAction: true }, pool: "house_comment.your_craft" },   // 家具来源是行动开箱
  { id: "empty",        when: { furnitureCount: { atMost: 3 } }, pool: "house_comment.empty" },
  { id: "fallback",     pool: "house_comment.fallback" },
] satisfies HouseCommentDefinition[];
```

- 评论条件是一小组**结构化查询**（能力计数、某件家具、地板占比、家具数量、来源），由 `Core/logic/houseComment.ts` 纯函数对一份 `HouseSnapshot`（家具列表 + 房间格数）求值。每位居民各自的评论**文案**不同（`pool` 键前加居民 id 找 `house_comment.<resident>.<id>`，找不到退回通用键），条件共用。
- 来访礼物：`ResidentDefinition.presents`（04 的随机赠礼池）复用。

### 门口展示位（建筑定义）

- `BuildingLevel.porchSlots: Array<{ x: number; z: number; facing: Facing }>`（本地坐标，2 个）。三栋居民房各填。
- `WorldSave.porch: Record<buildingInstanceId, Array<{ itemId } | null>>`（**新字段**）。写它的只有剧情效果 `porch_place: { residentId, itemId }`——送礼爱吃档 / 委托 `find` 完成的规则里接一条。
- 渲染：`BuildingsView` 读 `porch`，用现有 `FurnitureView` 的建模配方在展示位上摆一件**缩放 0.8** 的模型（复用店铺橱窗"大件缩成样品"的做法）。灯类家具夜里发光。
- 展示位满了新来的替换最早的（队列）。
- **不占格、不参与碰撞**（`userData.noCollide`），玩家能走过去。

### 门牌

- `BuildingLevel.namePlate?: { x, y, z, facing }`（本地坐标）。
- 到家人档（`affection_reached|<id>:family` 信号）→ 规则 `porch_nameplate: { residentId }` → `WorldSave.porch` 里那栋加 `namePlate: true`。渲染一块小木牌，文字是玩家名（`PlayerSave.profile.name`，**渲染时读，不存进世界**——联机时房客看到的是房主名，因为世界是房主的）。

## 技能与动词

### `visitPlayer` 技能（优先级 50，可打断）

`decide`（房主端）：

1. 今天不是来访日（保底抽签，`day_started` 时定好并存运行时）→ null。
2. 不在 `windows` 内 / 玩家不在自己主屋室内（`isIndoors(player)` 且 map 是 base）/ 玩家在专注行动（`getActiveAction()`）/ 主屋收起（`isHouseStowed`）→ null。
3. 否则 Intent：`[walk_to 主屋门外一步, knock]`。**`knock` 是新动词**：播敲门音效 + 门上冒"？"（`InteractBubble`），等 `knockWaitSeconds`；玩家在门内按 F（门的交互加一个分支：门外有访客 → 弹"进来吧 / 现在不方便"二选一）；不开 → Intent 结束，他回作息，今天不再来。
4. 开门 → 系统函数 `beginHouseVisit(residentId)`：门打开（走 `doorsRuntime`），下 Intent `[walk_to 室内随机可走点, stand(3s), walk_to 最近的空 seat（02 场所解析范围=室内）, sit, （staySeconds）, stand, walk_to 门外, （结束）]`。到达每个节点时 `speak` 一段评论（`houseComment` 求值一次，取前两条 + fallback，按顺序说）。
5. 结束前发 `resident_visited_player` 信号 → 规则接 `presentItems(present)` + `adjust_affection` + `add_memory("visited_you")`。
6. 期间玩家离开主屋 → 他说一句"我先回去了"提前结束（`onInterrupted`）。

### 门的改动

- `doorsRuntime` 门代理加 `visitorOutside?: residentId`（运行时）。按 F 的分支：有访客 → 选项面板；否则照旧开关门。
- 门只在玩家开门那一下自动开一次给他进，他出去时再开一次，之后按原状态。

## 联机

- 来访只对**房主**发生（`visitPlayer` 不在木偶跑；房客在做客也不会有房主的邻居来敲房主的门——条件里"玩家"是房主本人）。
- 房客看到的：史莱姆走到主屋门口、进屋、坐下（全是 Intent 复制）；门开关走已有的 `door_toggled` 同步；评论气泡**不同步**（对房主说的，03 的规矩）。
- 门口展示位和门牌走 `porch` 刷新切片（**`WORLD_REFRESH_KEYS` 加 `porch`**），房客看得见摆的东西和名字。
- 联机验收：房主 `/npc fox visit` → 房客看见阿茜敲门、进屋、坐同一把椅子；房主 `/npc slime porch cloud_lamp` → 房客那边咕噜门口出现灯；门牌上是房主的名字。

## 指令

| 指令 | 干什么 |
|---|---|
| `/npc <谁> visit` | 立即来访（无视时段与抽签，但仍要求你在屋里） |
| `/npc <谁> porch <itemId>` / `porch clear` | 摆 / 清门口 |
| `/npc <谁> nameplate on\|off` | 门牌 |
| `/npc housecomment` | 打印此刻室内快照求值出的评论 id 列表 |

## 存档

`WorldSave.porch`（新，含 `namePlate`）；`BuildingLevel.porchSlots / namePlate` 是内容。**版本号 +1、空迁移、`porch` 进切片与白名单、协议 +1。**

## 刻意不做的

- HHA 式评分与等级；他在你家过夜；多位同时来访（一天最多一位，`visitTuning` 里写）；他在你家用厨房 / 唱片机（等 12 的活动注册表把"用家具"做通用了，来访自动受益）；你不在家时"留言"（10 信箱做明信片）。

## 最容易写错的五处

1. **敲门时玩家在门外院子里**——条件是"在室内"，否则他敲的是你背后的门。
2. **门开了他进不去**：主屋门洞 2 m，居民半径 ≤ 0.35，没问题；但**舒舒**这类不是居民不该有这个技能——技能只挂在三个居民子类上。
3. **室内场所解析漏了"室内"限定**，他坐到院子里去了。02 的解析器加 `scope: "indoor" | "outdoor"`。
4. **展示位模型参与碰撞**，门口多了一个隐形障碍。`noCollide`。
5. **门牌名字存进世界**，房主改名字后牌子不变；联机时房客看到自己的名字。渲染时读。

## 验收

- Core `houseComment.test`：五条条件各一正一反；fallback 必有；文案键退回逻辑。
- Frontend `visitPlayer.test`：不在室内 / 专注中 / 房子收起 → 不来；来了不开门 45 秒走人且今天不再来；开门 → 完整链（进、坐、说、送、走、信号）；中途出屋 → 提前结束。
- `porch.test`：满了替换最早；`porch_place` 只由规则写；`noCollide`。
- 浏览器：在屋里 `/npc fox visit` 看敲门 → 开门 → 坐 → 评论 → 领取面板 → 走；`/npc slime porch cloud_lamp` + `/time night` 看门口灯亮；`/npc spirit affection =200` 看门牌。截图。
- 联机双端：见上。

## 自查（2026-09-05）

| 抓到的 | 改法 |
|---|---|
| 评论差点写成 if 链 | 结构化条件 + 纯函数求值，每位居民只换文案 |
| 门牌名字要不要存 | 不存，渲染时读玩家名 |
| 展示位差点复用 `placedFurniture`（会占格、能被玩家搬走） | 独立的 `porch` 表，只由规则写 |
| 来访礼物另做一张表 | 复用 04 的 `presents` |
| 敲门是不是动词 | 是：有等待、有音效、有中断，符合动词定义；也让 `/npc do knock` 能调 |
