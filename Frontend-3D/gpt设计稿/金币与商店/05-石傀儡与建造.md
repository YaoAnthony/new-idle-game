# 石傀儡与建造流程

> 状态：**期 A/B 已完成，C–E 待做** · 2026-08-22 · 前置：期 0–2 + 女巫小屋三轮全部完成
>
> 标准同前四份：任何人不看聊天记录也能照着做完并验收。

## 一句话

领地上坐着一尊无头石傀儡。玩家在院子另一头捡到他的头，走过去按 F 装上，他苏醒；
和他说话打开建造面板；面板里买一张图纸；拿着图纸选址落下蓝图；石傀儡走过去把它建起来。
建好之后对着建筑按 F 能迁移 / 拆除 / 升级 / 看详情。

### 空的 / 缺的

| 缺口 | 现状 |
|---|---|
| **建造代价** | **字段不存在**。`BuildingLevel` 只有 `upgradeCost`，新建一栋楼永远免费 |
| **扣材料** | `checkUpgrade` 的 `missing_materials` 校验写好了，但 `upgradeBuilding` 调它时**不传 `materials`**（`buildings.ts:266`），这道门物理上无法触发；**扣材料的代码根本不存在** |
| **施工时间** | `construction { targetLevelId, finishUtc, workerId? }` 和 `buildDuration` 都是预留字段，**全仓库零引用**。Core 里没有任何推进/结算施工的函数。而且只有 `finishUtc`，**算不出进度百分比** |
| **工人** | 只有 `workerId?: string` 一个字符串。没有工位、没有认领/释放、没有排队 |
| **围栏 / 半成品** | `BuildingsView.applyState` 只认 `fill`（液面）和 `stage`（农田），没有在建表现 |
| **图纸** | 零。能建什么是硬编码数组 `buildableIds()` |
| **建造 UI** | **唯一入口是控制台指令**。玩家点地上的罐子毫无反应——`refreshInteractTarget` 只遍历家具 + 门 + 宠物，**从不看 `listBuildings()`** |
| **NPC** | 不存在这个概念，只有宠物。`storyRules` 和 `dialogueDefinitions` **都是空数组** |
| **进度条** | 没有任何可复用组件，也没有世界空间进度条 |

**做的时候撞出来的三件事（都记在注释里）**

1. **模型第一版读成一根石柱**。三块 1.5 宽的石板越堆越窄、手臂缩在轮廓
   里面，站起来从远处只看得见一个长方体。人形的辨识度几乎全在剪影上：
   肩要比腰宽出去一截、头和肩之间要留出脖子、手臂要挂在轮廓**外面**。
   重排比例之后才读得出是个人形。坐姿同理——第一版沉 0.62、倾 0.3，
   读出来是一堆塌掉的石头；坐着的人形要保住竖直的躯干。
2. **`interactTarget` 两把尺子**（真 bug，顺手修了）。家具算的是到占地
   矩形最近边，生物算的是到中心。半径 1.1 的石傀儡贴着站中心距 1.3，
   旁边一米开外的纸箱按边算只有 1.2——按 F 打开的是纸箱，而玩家眼里
   那两样东西的远近正好是反的。生物那侧改成减掉体型。
3. **物品自检抓住一个空话字段**。头第一版写了 `surfaceHeight: 0.5` 却
   `blocksMovement: false`，`itemAudit` 当场报"有台面高度的必须挡路"——
   不挡路的家具上面放东西会直接落地，台面高度是句空话。

**金币怎么混进材料数组**（这一期唯一的设计难点）

钱不在背包里（它是金币罐实例的 `state.stored`，"罐就是钱包"），但用户要
材料是**一个数组**。与其给每个代价表配一个 `goldCost: number` 的旁路字段，
不如让金币占一个**保留 id** `"gold"`：面板只渲染一张表，扣费只走一条路，
以后加"圣水""声望"这类非背包资源也是照这里加一行。Core 那层因此完全不
需要知道钱存在罐子里这回事——它只收一张"你现在有多少"的清单。

代价是 `"gold"` 不能是真物品的 id。`auditMaterials()` 开机拦这个。

**上架清单 = 有没有图纸物品**

不另写一张"商店卖什么"的表：注册表里存在 `blueprint.buildingId` 指向它的
物品，它就上架。加一种可盖的建筑 = 加一件图纸物品，面板一行不用改；
反过来也不会出现"面板上有但买了没用"的条目。

### 期 B 附带：游荡 AI 和两个 bug

用户看着他站着不动、还浮在空中，补了一句"他有自己随便走来走去的简单 AI，
你可以先做一版……还有他浮在空中不知道为什么"。两件都是真 bug：

1. **浮空**：`golem.ts` 的 `animate` 里写了 `root.position.y = 0`，把
   `PetView` 每帧设的**地面高度**覆盖掉了。院子地面在 −0.45，所以他正好
   浮起 0.45。PetView 的约定写得很清楚："内部只动自己的子节点，root 的
   位置朝向仍归这里管"——加一个 `rig` 中间节点就守住了。
2. **不会走**：`PetAgent` 的寻路（`randomFreeCell` / `startPath` / 坐标换算）
   全都取 `getWorld().room`，也就是**主房间**。石傀儡站在院子里，格号换算
   直接算到房子的网格上去了，每次算路都失败。这是"一图一屋"公理在生物
   行为里最后一份拷贝，院子在期 1 变成真房间之后一直没人踩到——宠物从来
   只在屋里。改成按**脚下那个房间**算（`space()`）。

顺带两条：
- **驻地半径**（`PetBehavior.wanderRadius`，石傀儡 5 米）。院子是一整块
  60×45 的房间，不限半径他会一路溜达到据点另一头。驻地**进存档**，
  不能读档时拿当时站的位置顶上——那样每存读一次驻地就朝他溜达到的地方
  挪一次，挪几回就漂没了。
- **采样要先收到驻地附近**。60×45 = 2700 格里 5 米的圆只占 79 格，全房间
  均匀抽的命中率不到 3%，抽 24 次有一半机会一个都中不了——表现是他走一段
  就呆站十几秒。另外候选点要过 `isWalkable`（那条才认领地），不然他会
  径直走进没解锁的地里去。

### 期 D · 石傀儡施工（单工位排队）

**Frontend**
- `PetAgent` 加活动 `"work"` 和差事 `{ kind: "build", instanceId }`
- `trySeekConstructionSite()`：照 `trySeekWater()` 同构写。挑**最早下单**的、`workerId` 为空的工地，认领（写 `workerId`）
- 走到工地边 → `seekNear(工地中心, 占地半径 + 1)` → 到了切 `work` 状态 → `animate` 播砸击
- 完工：`construction` 清空、`levelId` 落到 `targetLevelId`、`emit("world_changed", { reason: "buildings" })`、傀儡释放工位
- **排队**：一次只认领一个。别的工地 `workerId` 为空、进度**不推进**（进度按"认领之后才开始走"算，不是墙钟——不然排队的工地会自己走完）

> ⚠️ 这条最容易写错：`finishUtc` 是绝对时间，排队的工地要是也按墙钟算，玩家去睡一觉回来全都建好了，工位就白设了。
> **改法**：`startUtc` 在**傀儡认领的那一刻**才写；没认领的工地 `startUtc` 为空 = 进度 0，"等着"。

**验收**
- 下单后傀儡自己走过去（能看见他走），到了开始砸，进度条涨
- 20 秒后围栏消失、半透明变实心、罐子建成
- 连下两单：第二个工地围栏立起但进度**恒 0**，傀儡建完第一个才走过去
- 建造中把傀儡引开（跟着玩家走）→ 进度停住，回来接着走
