# 附 · 薇尔的大树

> 用户 2026-09-05：小精灵应该住在树洞里，初期就搞一棵特别大的树。
> 这条改的是**薇尔的家是什么**，不改入住那条链。涉及 02 / 08 / 09，这里集中写，那三份只引用。

## 定下来的

- 院子里**开局就有一棵大树**，和井一样是开局布景（`seedInitialFurniture` / 建筑登记里的地标，不是玩家盖的）。位置在院子西北角靠林子那侧（薇尔"从林子里来"）。**先问参考图**再建模：这棵树是院子里最高的东西，剪影决定一切。
- 薇尔不住小屋。她的"房子"是**树洞**。`spirit_house` 这栋 3×3 小屋型号退役，换成大树的一个等级：`great_tree` l1 = 一棵树；l2 = 树洞开了门、挂了风铃（她住进来）。
- 图纸照旧：她给你的是"树洞门的图纸"（`blueprint_tree_hollow`），**选址是固定的**——图纸只能用在那棵树上（`BuildingLevel` 加 `upgradesOnly: "great_tree"`：这张图纸不落新工地，而是给现有建筑升级；石傀儡照旧走过去干活）。这比"再给她一块地"更像精灵。
- 室内（08）：树洞是三间室内里最小的一间（4×4），圆形地面靠方格近似，风铃是固定陈设，你送的东西挂在树壁的槽位上。
- 树本身还是**场所**（02）：`seat` 场所里加一种来源"树根"（`great_tree` 声明两个坐点），别的居民也会来树下坐；`shore` 之外再多一个天然场所。

## 顺手想到的、没定的

- 大树要不要有季节 / 天气表现（下雨树下不湿、夜里树洞透光）。夜里透光和窗灯是同一个机制（`isAtHome`），免费；其他等有季节再说。
- 大树是不是也算"能坐的场所"给玩家——玩家坐树根用现有的 `FurnitureAnchor` 那套，`BuildingLevel.seats` 复用同一个类型，不另做。

## 验收

- 新档院子里有树；老档迁移在同一位置补一棵（`seedInitialFurniture` 有"老档补东西"的先例：石傀儡的头）。
- 薇尔的图纸只能用在树上；选址面板对它只给一个候选。
- 石傀儡能走到树旁工地（树的碰撞从模型推导，02 那期定的"模型即碰撞"，树冠标 `noCollide`，树干挡人）。
- 08 之后树洞能进；窗灯换成树洞透光。
- 联机：树是建筑，走 `buildings` 切片，房客看得见等级变化。
