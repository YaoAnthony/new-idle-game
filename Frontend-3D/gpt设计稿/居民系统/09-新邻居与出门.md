# 09 · 新邻居与出门

> 状态：**文档，待执行** · 2026-09-05 · 前置：02 作息（去小镇）、03 对话
>
> 一句话：桥头偶尔站着一位陌生人，聊得来就请他住下——图纸、选址、石傀儡、到场，
> 走 `/npc join` 那条已经通了的链。没有搬走，只有"出门几天"，而且会提前告诉你。

## 玩家看到什么

- 某天早上报纸头版："桥头来了个陌生人。"走到东桥，一只没见过的小动物站在桥头看风景。按 F 聊天，三段对话后出现选项"要不要住在这儿？"。选"来吧" → 领取面板收到他的房屋图纸（现有链）；选"下次吧" → 他傍晚离开，几天后可能再来另一位。
- 房子建好那天他从桥头走进来住下（现有链）。
- 咕噜某天说："咕噜要回老家看看，三天后回来，别担心。"第二天他家门锁着、窗不亮，`/npc list` 显示"出门（回老家，还有 2 天）"；报纸登"咕噜回老家了"。第四天早上他从桥头走回来，见面第一句："咕噜回来啦，带了这个给你。"
- 领地满了（没有能放房子的地）访客不会来；开了新地块后又会来。

## 动森原型与取舍

| 动森 | 取法 |
|---|---|
| 露营地随机访客，聊天 + 小游戏后可邀请 | 桥头访客，聊天后邀请；**不做小游戏** |
| 岛上有空地块才会有人来 / 狸克卖地 | 访客只在"能放下一栋 3×3"时出现；地块由领地系统管 |
| 村民想搬走会冒泡问你，你能留 | **不做搬走**。做"出门几天"，一定回来，带礼物 |
| 搬走的村民寄告别信 | 出门的居民寄明信片（10） |
| amiibo 邀请 | 无 |
| 村民上限 10 | 上限 = 领地容量，不写数字 |

## 数据

### 访客池（Core/src/Data/residents/visitors.ts）

```ts
export const visitorPool = {
  /** 日抽签保底（照 storyPools）；同一天最多一位；有访客在桥头时不抽 */
  pool: { poolId: "visitor_arrival", base: 0.08, step: 0.06, max: 0.6 },
  /** 候选 = residentDefinitions 里 role=Resident 且还没住下、且 `visitorEligible !== false` 的 */
  stayHours: 10,                 // 早上来傍晚走
  requires: [{ kind: "territory_has_room_for", footprint: [3, 3] }],   // 新条件，读领地空位
} as const;
```

- 新居民 = `residentDefinitions` 加一条（带 `residence`、`personalityId`、talk 文件）+ 一栋房 + 图纸。访客池**自动**包含他，不用登记。
- 访客到场是剧情效果 `spawn_resident` 的一种用法：规则 `visitor_arrives` 触发 `day_started` + poolId，效果 `spawn_visitor: { at: "visitor_entry" }`——从候选里确定性抽一位、以 **`visiting` 状态**登场（`ResidentSave.visiting: { leaveAtLocalTime }`，**新字段**）。`visiting` 状态下：routine 不跑（他不是居民，没作息），只 `wander`（半径 2）+ `greet`。
- 邀请：访客的 `firstMeet` 对话末节点选项 `emitEventId: "invite_<residentId>"` → 规则接 `present_items(blueprint)`（03 的领取面板效果）+ 把 `visiting` 清掉、改为 `awaitingHouse`（他傍晚照样离开，房子建好那天走现有链从桥头到）。拒绝 → 傍晚离开，`visitor_arrival` 池 miss 归零重新累。
- 现在三位的"抽签池到来"规则（`resident_*_arrives`）**退役**，统一走访客路。`/npc join` 保留为调试口。

### 出门（Core/src/Data/residents/trips.ts）

02 的去小镇是"当天往返"；这里是**多天不在**，同一套 `residentTrips` 存档字段，加类型：

```ts
export const tripDefinitions = [
  { id: "hometown", days: [2, 3], announceDialogueId: "trip_hometown_announce", backDialogueId: "trip_hometown_back",
    pool: { everyDays: 12, base: 0.2, step: 0.1, max: 0.8 }, requires: [{ kind: "affection_at_least", stage: "familiar_resident" }],
    postcard: "postcard.hometown", giftPool: ["tomato", "cheese"] },
] satisfies TripDefinition[];
```

- 出发前一天**必须**当面说（`announceDialogueId` 走 `favor` 技能那套"主动走过来"）；没说到（你一天没上线）→ 推迟，不悄悄走。这是动森 NH 修过的那条教训。
- 出门期间：从运行时移除（同 02 的小镇），`residentTrips[id] = { kind: "hometown", backDayId }`，房门锁、窗灭、报纸登。10 的信箱在出门第二天收到明信片。
- 回来：`backDayId` 早上从桥头走回家，第一次见面播 `backDialogueId` + 领取面板一件 `giftPool` 里的东西。

## 技能与动词

- 无新技能。访客用 `wander` + `greet`；出门是系统层（02 的 `townTrips.ts` 扩成 `trips.ts`）。
- 新对话条件 `territory_has_room_for`：读领地系统"有没有一块 3×3 的可建空地"（`checkPlacement` 扫描），Core 纯函数。

## 联机

- 访客登场 / 离开、出门 / 回来全走 `pets` 切片对账（01）。房客看到桥头有陌生人，能按 F 闲聊（本地），**看不到邀请选项**（`invite_*` 事件在做客时不执行，选项条件加 `is_host`——新条件，读 `!isRemoteWorldActive()`）。
- 联机验收：房主 `/npc visitor spawn` → 房客桥头出现同一位；房主邀请 → 房客那边访客傍晚照样离开；房主 `/npc slime trip hometown` → 房客那边咕噜消失、门锁、`/npc list` 显示出门。

## 指令

| 指令 | 干什么 |
|---|---|
| `/npc visitor spawn [物种]` / `leave` | 立即来 / 走一位访客 |
| `/npc <谁> trip <tripId>` / `back` | 立即出门 / 立即回来 |
| `/npc join <物种>` | 保留（跳过访客直接给图纸） |

## 存档

`ResidentSave.visiting?`、`residentTrips` 扩形状（加 `kind`）。**版本号 +1；02 的 `residentTrips` 如果已经上线要迁一次形状**（两期合并实现就不用）。

## 刻意不做的

- 搬走、不告而别、赶走居民、访客小游戏、访客数量 > 1、访客在小镇地图出现、居民数量硬上限。

## 最容易写错的四处

1. **访客也跑 routine**（他没有 `personalityId`，02 已经返回 null，但 `visiting` 状态要再挡一道 `favor` / `social`）。
2. **邀请后房子没建他就永远等着**：`awaitingHouse` 没有过期，`/npc list` 显示"等你选址"。图纸弄丢了 `/npc join` 补。
3. **出门那天没当面说就走了。** 推迟规则要有用例。
4. **访客抽到已经住下的**——候选过滤读 `listResidents()` + `awaitingHouse`。

## 验收

- Core：候选过滤；保底抽签确定性；`territory_has_room_for`。
- Frontend `visitors.test`：早来晚走；邀请 → 图纸 + 建好 → 到场（复用 residentCommands.test 的链）；拒绝 → 池归零；满地不来。`trips.test`：宣布 → 次日走 → `backDayId` 回 → 礼物；没宣布不走。
- 浏览器：`/npc visitor spawn` 桥头截图、对话、邀请、领取面板；`/npc slime trip hometown` 门锁窗灭 + `/day` 三次回来送礼。
- 联机双端：见上。
