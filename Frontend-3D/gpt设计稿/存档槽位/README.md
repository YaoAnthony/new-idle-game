# 存档槽位（本地 A/B/C ＋ 云端 ×1）

2026-09-07 做完。用户当天拍的四条：云槽是**独立的第四个档**（不是某个本地槽的镜像）、
老档按登录态分去向、后端加真的 DELETE、云槽兼登录入口。

## 规格

四个槽地位相同：**都能进、都能下载成文件、都能删（二次确认）、空了都能新建或导入**。
唯一的区别是 `cloud` 跟账号绑定——只有玩云槽时才走云同步；A/B/C 永远纯本地，
不会哪天被自动推上去顶掉云端那份。

卡片上四项：`第 N 天 · 金币` / `上次保存` · `存档大小`。三个槽长一样等于没做多槽。

| 槽 | 键 |
|---|---|
| `a` / `b` / `c` | `world.a` / `world.a.backup` / `world.a.conflict`（b、c 同理） |
| `cloud` | `world` / `world.backup` / `world.conflict`（**沿用老键**） |

云槽不换名字的理由：云同步的三方基准（`lastSyncedRevision`、`pendingWriteId`）记的是
"本机这份主档和云端的关系"，键一改等于告诉引擎本地换了一份档，已登录玩家下次启动
当场吃一个假冲突框。代价是 `world` 这名字看不出它是云槽——用 `keysForSlot` 一个函数
换取，**别处不许再拼键**。

## 3D 舞台（2026-09-08 起的存档页）

「开始游戏」不再弹四张卡，而是铺满整屏的一块草地：你家小屋前，傍晚。四个站位一字排开
（屏幕左→右：云端 / C / B / A，世界 +x 在屏幕右）。**有档的位置站着那个档里捏出来的
角色本人**（`buildCharacter(summary.avatar)`，外观读不出来就用默认外观并在名牌上标
「外观待更新」）；空位是地上一圈虚线 + 「＋」；云槽空位飘一朵云，没登录就整套灰掉。
点站位（射线打不可见命中柱）或名牌 → **镜头推到那个人跟前**（人站画面左侧，名牌全收），
右边一张竖排信息卡：第几天 / 金币 / 上次保存 / 存档大小 + 动作，和原来的卡片一条不少。
「返回」和 ESC 先退特写再回标题。推轨按真实时间收敛（每秒吃掉 99% 剩余距离），掉帧不拖慢。

几条取舍：

- **独立场景，不借 RoomScene。** RoomScene 是整个世界的运行时，挂起来要先灌存档，而这
  一屏正是"还没选档"的时候。自己起一个 Scene 只要草地、房子、四个人。
- **房子用游戏里那一栋的同一份配方**（`buildHouse` + `generateCottageL1`，锚点朝北、
  elevation = FLOOR_LEVEL），灯光抄 Lighting.ts 黄昏那一档。玩家在这一屏看到的家就是
  进去之后的家。房子建不出来只 warn，舞台照样能选档。
- **名牌位置每帧由投影写 transform，不走 React 状态**——四块 DOM 每秒 60 次 setState
  没必要。
- 选中的站位抬 0.08、镜头横向轻推 0.35×站位 x，都用 lerp 收；生硬跳一下会像 bug。
- 667×375：信息卡缩窄；特写的横向偏移按画幅算，人不会被卡盖住；镜头视角按画幅比例分三档。

## 五个坑（改这块之前先读）

1. **抢跑读存档 = 读到空。** 搬家正把 `world` 挪去 `world.a` 的半路上，两个键都可能
   是空的。App 的启动检查、继续游戏、云对账全部先 `await whenSlotsReady()`。
2. **云对账必须锁死云槽**（`getSaveRepository("cloud")`）。多槽之后"全局仓库"就是
   "当前活动槽"：玩着 B 槽登录，对账会把云档写进 B，当场顶掉眼前的世界。
3. **存档页列卡之前先 `await whenCloudReady()`。** 换台设备登录时镜像还在下载路上，
   抢先列出来的云槽是"空档位"，玩家点一下新建就在云端那份还好好的情况下开了新档。
4. **删云槽先云后本地。** 云端失败就整件事不做——本地清了云端还在，玩家看到云槽空了、
   下次登录它又回来，比删不掉更难解释。删成功后同步基准必须归零，否则下一次节流推送
   把刚删掉的档原样推回去。
5. **导入云槽要补一次仓库写 + `pushCloudSoon()`。** `transfer` 直接写 IndexedDB，
   不认识仓库，不补这一下就是"导入成功但永远不上云"。

手动（浏览器，每次动这块都要重跑）：

1. 舞台四个站位：有档的站着那个档的角色（外观和捏脸时一致）、空位圆环 + 加号、
   未登录云槽灰圆环 + 灰云；名牌数字对得上。
2. 点站位本体和点名牌都能选中；镜头推近、人在左、右侧出信息卡；× / 返回 / ESC 退回全景。
3. 删除：点删除 → 卡翻成粉色问句带槽名 → 确定 → 只有那一个槽的键消失，站位当场变圆环。
4. 空位新建：「在这里开始新生活」→ 捏脸 → 进屋 → ESC 回标题 → 该位出现角色和「第 1 天」。
5. 下载：文件名形如 `异世界小家-A-第12天-20260907.json`。
6. 上传：空位点「上传存档」→ 选一份导出的文件 → 站位当场立起那个档的角色。
7. 云槽未登录：点它 → 「登录账户」→ 登录面板盖在舞台上；登录完云槽刷新。
8. 「返回」回标题页；再进舞台场景重建（不残留上一次的选中）。
9. 667×375 横屏：四个站位都在画面里、详情卡在右下不盖人、按钮点得到。

## 已知的取舍与待办

- **游客登录不再自动上传本地档。** 以前登录那一刻本地那份会被当成"本地有档、云端没有"
  推上去；现在它在 A 槽而云槽是空的，不会自动上云——这是"四个槽互相独立"换来的代价。
  手动通道是下载 A → 传进云槽。要不要做一个"复制到云槽"的按钮，等你说。
- **登录态下的云槽卡片没在浏览器里真跑过**（需要在本机后端注册账号）。那一排按钮和
  本地槽是同一段代码，云端那半边由用例覆盖。
- 舞台上的角色是按摘要里的 `avatar` 现建的模型（不是存图），所以捏脸改了外观舞台立刻跟着变；
  代价是四个模型同时在场——低模，实测无压力。
- 舞台没有环境音和进入转场：选档后直接切加载页。要做的话是加载页那边的事。
- 摘要里的"第几天"用 `createdAtUtc` 的日期和世界日相减，跨时区玩家在日界线附近可能
  差一天。补一个"建档那天的 worldDayId"要 bump 存档版本 + 写迁移，为卡片上一个数字不值得。
