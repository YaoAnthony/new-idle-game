## item架构

所有的掉落物都能被捡起，所有的item应该拥有注册表：

```ts

    enum ItemCategory {
        material = "material",
        PlaceFurniture = "place_furniture",
        Tool = "Tool",
        food = "Food"
    }

    type ItemDefinition = {
        id: string;
        localizationKey: string; // 名字，localizationKey主要用于翻译

        
        category: ItemCategory;
        stackLimit: number;

        // 下面根据 category 会有以下的属性：
        placeableFurnitureId?: FurnitureId;

        food?: {
            hungerRestore: number;
            canExpire: boolean;
            expiredDate?: Date;
        };

        tool?: {
            toolType: "camera";
            durability?: number; // 耐久度
        };

        // 物品稀有度
        rarity: Rarity;

    };

```

每个背包or储存箱里的item应该信息如下：

```ts
    type InventoryStack = {
        stackId: string;
        itemId: ItemId;
        quantity: number;

        state?: ItemStackState;
    };

    type ItemStackState = {

        // 食物过期时间，建议用游戏时间，不要直接混真实时间
        expiresAtGameTime?: number;

        // 工具耐久。一般有耐久的工具 stackLimit 应该是 1
        durability?: number;

        // 比如家具物品换皮肤、照片、信件等特殊内容
        customDataId?: string;
    };
```

## 声效系统

分成音乐，声效，Player 是 listener，即听觉位置，下面是具体规则

### 规则
音效应当遵循以下规则
- 距离衰减
- 最大听距
- 墙体遮挡检测
- 被遮挡时降低音量或加 low-pass
- 某些墙/门/窗可通过定义改变遮挡强度

音乐则不受上述规则影响


### 音乐

我们会储存一系列无版权音乐，后期可以像动森一样分早中晚的时间播放不同时间段的音乐，现在共享一个大音乐库

可以随机播放，顺序播放，单曲循环，可以选择音乐播放（为未来音乐播放器做准备）

特殊剧情会柔性中断当前播放音乐，插播符合剧情的音乐


### 声效

Player 是 listener，即听觉位置，以下所有的音效都会根据距离调整，声音应该受障碍物影响，如墙的另一头应该听不到，家具，小动物声音 等
下面是三种类型：
- 环境音： 环境音应当检查存档的天气和房子的type播放，并且会找寻窗户和门的位置，越靠近这两个地方，玩家应该能听到更清晰的环境音，如雨声等
- 家具音：家具有不同的音效
- 小动物声音： 小动物做的事情发出不同的声音




## 用户操作

映射键位，用户可以调整键位

目前设计应该有以下键位：

- 移动： wasd
- 交互：F/鼠标左键

当用户手持家具类item时，鼠标会出现家具的虚影，如果可放置则为蓝色，如果不能，则为红色，再次鼠标左键，可以放置

用户操控角色走到家具旁边，可以按F进行交互

我们有两套系统，一个是用于和内部的dialogue系统

正下方应该出现对话框，对话框内可以互相对话，和选择，以及提交物品

第二套是未来的联机用的对话系统，我们暂且留空



## 网格装饰

装饰是本作品一大核心，我们会有分为墙饰（wall_grid）和地面装饰（floor_grid）

墙饰只能放在墙上的网格，地面装饰（家具）只能放在地面，

每个可放置物都有自己的 footprint，例如 1x1、1x2、2x2，以适应不同的尺寸的图片

目前墙饰有：
- 画、挂钟、窗帘、壁灯、风铃

目前地饰有：
- 桌子、床、工作台、地毯、椅子

墙饰要特别小心：top-down 2D 里“墙”不是普通地板格。最好把墙面放置点做成独立的 wall placement layer，不要让它混进地面家具系统，否则以后会很难处理遮挡、深度排序和点击选择。

## 家具注册

家具应该是随时添加注册的
下面是对应的数据机构

```ts

type VisualId = string;
type AudioProfileId = string; // 未来再进行复杂变化，或者不改

// 用于告诉商店分类等
enum FurnitureCategory {
    Station = "station",
    Storage = "storage",
    Bed = "bed",
    Seating = "seating",
    Table = "table",
    Lighting = "lighting",
    Decoration = "decoration",
}

// 墙壁装饰物还是地面装饰物
enum PlacementSurface {
    Floor = "floor",
    Wall = "wall",
}

// 对应功能，将抽象给不同的家具
enum FurnitureCapability {
    Crafting = "crafting",
    Cooking = "cooking",
    Storage = "storage",
    Sleep = "sleep",
    Sitting = "sitting",
    Ambience = "ambience",
}

type FurnitureDefinition = {
    id: string, // 用于确定家具的注册id
    visualId: VisualId; // 视觉资源 ID，例如 "ordinary_workbench_default"，方便出皮肤
    footprint: GridFootprint // 网格占地，保证不同图片都按规则限制长宽

    placementSurface: PlacementSurface; // floor or wall

    localizationKey: string, // 其实就是名字，只是方便未来翻译


    category: FurnitureCategory; // 哪类家具
    capabilities: FurnitureCapability[]; //能够使用的功能
    audioProfileId: AudioProfileId | null;
    
}
```

理论上当一个家具被造出来，他的type应该如下所示：

```ts

    
    type PlacedFurniture = {
        instanceId: PlacedFurnitureInstanceId; // 世界中这个具体家具的唯一 ID

        furnitureId: FurnitureId; // 指向 FurnitureDefinition.id，例如 "ordinary_workbench"

        //储存放置信息
        type FurniturePlacement =
            | 
                {
                    kind: PlacementSurface.Floor;
                    roomId: RoomId;
                    gridPosition: GridPosition;
                }
            | 
                {
                    kind: PlacementSurface.Wall;
                    roomId: RoomId;
                    gridPosition: GridPosition;


                    wallId: WallId; // 墙有好几面
                };

        state: PlacedFurnitureState; // 针对不同的家具的不同变化，应该有更细微的思考
    };

    type PlacedFurnitureState = {
        durability?: number;

        // 如果这个家具有 Storage capability，可以指向它拥有的库存
        storageInventoryId?: string;

        // 如果这个家具有 Cooking/Crafting 等过程，可以记录正在进行的流程
        activeProcessId?: string;

        // 如果单个实例换了皮肤，比如同一张床被玩家换成春季外观
        customVisualId?: VisualId;
    };
```

## 存档系统

存档应该包含以下data

数据:
```ts

GameSave = {
    meta : {
        version: number; // 游戏版本，用于检测两者版本联机时是否相同
        createdAt: string;
        updatedAt: string;
    }

    player: PlayerSave; // 玩家数据
    ownWorld: WorldSave; // 地图数据
};

PlayerSave = {
    name: string; 
    avatar: string;
    missions: {
        daily: MissionInstance[];
        primary: MissionInstance[];
    };
    character: {
        inventory: InventoryStack[];
        needs: {
            hunger: number;
            fatigue: number;
        };
    };


    // 表示玩家已经学会的菜谱或制作配方
    discoveredRecipeIds: string[];

};

type WorldSave = {
    worldId: string;

    // 随机分配后必须固定下来
    seed: number;
    house: HouseSave;

    // 世界时间与环境
    clock: WorldClockSave;
    weather: WeatherSave;

    maps: Record<string, MapSave>;
    pets: Record<string, PetSave>;
    placedFurniture: Array<PlacedFurniture>
    inventories: Record<string, InventorySave>; // 储存箱应该有单独的空间储存内容

    progression: {
        // 解锁的功能
        unlockedFeatureIds: string[];

        // 事件推进
        events: EventProgressSave; 
    };
};
```

当游戏运行的时候，我们需要有一个 RuntimeGameState，表示application正在运行的存档，具体应该如下

```ts
type RuntimeGameState = {

    activeWorld:
        | {
            kind: "own";
            world: WorldSave;
        }
        | {
            kind: "remote";
            world: WorldSnapshot;
            hostPlayerId: string;
            revision: number;
        };

    // 如果只有玩家自己，那这里只有自己
    participants: Record<string, ParticipantState>;
};

type ParticipantState = {
    playerId: string;

    position: Position;

    activity?: {
        actionId: string;
        startedAt: number;
        furnitureInstanceId?: string;
    };
};


```
